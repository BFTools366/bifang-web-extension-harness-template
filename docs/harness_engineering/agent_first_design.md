# 以智能体为首要使用者的设计

## 智能体是首要使用者

Harness 的首要产物不是文件数量，而是一组能被 Agent、用户和工具共同解析的稳定事实。每项约束应具备唯一来源、明确触发器、可执行入口和可确定验证；文档只做路由，不复制容易漂移的实现细节。

人类决定产品方向、权衡、凭据、外部副作用和最终发布。Agent 可以自主完成范围内的只读检查、可逆实现和必要验证，但不能从“任务重要”推导出提交、推送、发布或不可逆权限。

## 事件驱动执行

- 范围清楚的工作直接实现并验证。
- 持久工作计划 只解决用户明确要求、跨会话交接或确有必要的发布/高风险协调。
- 并行写入同时要求本次用户明确提出、策略启用、至少两个不重叠单元和 helper 机械门禁。
- 构建、E2E、完整候选验收、安全/权限复核和发布各自由自身事件触发，互不暗含。
- 只有被独立事件触发的 产品规格、产品状态、工作计划、架构决策、变更记录或验收记录 才更新；未触发时不写占位。

这种模型避免用固定任务等级捆绑无关成本，也避免普通多步骤工作自动制造计划、浏览器和发布流程。

## 会话、Task 与 Subagent

用户可见左侧 Task 使用三字段标题：

```text
Task {序号} | {当前进度} | {单一结果}
```

进度只取 `已分配`、`运行中`、`检查中`、`已完成`；同一结果中序号和单一结果稳定。内部 plan、Subagent 与单元 Worktree 不使用该标题合同，也不占用项目序号。每次真实阶段转换至多尝试一次更新并有界复读。标题 API 失败不覆盖工程结果，但未完成、未发布或被阻断的工作不得虚写完成。

`user_owned_tasks: disabled` 时只在用户明确要求时创建左侧 Task；`enabled` 时结果边界变化前自动创建。左侧 Task 的创建、绑定与状态由 `$web-manage-user-tasks` 执行；环境按用户已有选择与当前项目策略冻结。Git Worktree 使用独立登记目录与 `codex/task-*`，Git Local 绑定保存项目并串行，不擅自切换分支。内部 Subagent 属于当前 Task，不调用创建左侧 Task 的入口；内部单元使用 `codex/unit-*` 和 Git common-dir 中的所有权登记。显示标题、技术 `task_name`、Git ref、Worktree 路径和项目身份相互独立。

## 失败关闭

输入不完整、事实来源冲突、路径/符号链接不安全、所有权不确定、测试批次为空或授权不足时停止当前副作用并报告精确阻断。失败后继续安全只读分析，不通过猜值、扩大范围、静默安装、自动 stash/commit 或把 Mock 改判为真实可用来绕过。
