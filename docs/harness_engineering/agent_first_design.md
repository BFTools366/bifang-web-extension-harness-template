# Agent-first 设计

## Agent 是第一消费者

Harness 的首要产物不是文件数量，而是一组能被 Agent、用户和工具共同解析的稳定事实。每项约束应具备唯一来源、明确触发器、可执行入口和可确定验证；文档只做路由，不复制容易漂移的实现细节。

人类决定产品方向、权衡、凭据、外部副作用和最终发布。Agent 可以自主完成范围内的只读检查、可逆实现和必要验证，但不能从“任务重要”推导出提交、推送、发布或不可逆权限。

## 事件驱动执行

- 范围清楚的工作直接实现并验证。
- 持久 Work Plan 只解决用户明确要求、跨会话交接或确有必要的发布/高风险协调。
- 并行写入同时要求本次用户明确提出、策略启用、至少两个不重叠单元和 helper 机械门禁。
- 构建、E2E、完整候选验收、安全/权限复核和发布各自由自身事件触发，互不暗含。
- 只有被独立事件触发的 Product Spec、Product Status、Work Plan、ADR、Changelog 或 Verification 才更新；未触发时不写占位。

这种模型避免用固定任务等级捆绑无关成本，也避免普通多步骤工作自动制造计划、浏览器和发布流程。

## 会话、Task 与 Subagent

普通当前 Session、用户可见 Worktree/Local 左侧 Task 与内部 Subagent/agent thread 使用同一逻辑标题：

```text
{序号}|{Task简述}|{当前进度} |{功能摘要}
```

进度只取 `已分配`、`运行中`、`检查中`、`已完成`；同一结果中序号、简述和摘要稳定。每次真实阶段转换至多尝试一次更新并有界复读。标题 API 失败不覆盖工程结果，但未完成、未发布或被阻断的工作不得虚写完成。

左侧 Task 只在用户明确要求时创建，并精确绑定已保存项目；Git Task 使用独立登记 Worktree 和 `codex/task-*`。内部 Subagent 属于当前 Task，不调用创建左侧 Task 的入口；内部单元使用 `codex/unit-*` 和 Git common-dir 中的所有权登记。显示标题、技术 `task_name`、Git ref、Worktree 路径和项目身份相互独立。

## 失败关闭

输入不完整、事实来源冲突、路径/符号链接不安全、所有权不确定、测试批次为空或授权不足时停止当前副作用并报告精确阻断。失败后继续安全只读分析，不通过猜值、扩大范围、静默安装、自动 stash/commit 或把 Mock 改判为真实可用来绕过。
