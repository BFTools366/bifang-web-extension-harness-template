# Mantine UI 设计规范

本文档是 Bifang Web Harness Template 及其下游 Mantine 界面的唯一详细设计规范。它约束视觉令牌、布局、组件语义、交互状态、响应式、无障碍与国际化；具体项目身份与品牌色仍以 `.harness/project.json` 为事实源，工程和测试通则仍以 [`ENGINEERING_RULES.md`](ENGINEERING_RULES.md) 为准。

当前模板声明 Mantine `9.6.3`，并以根级 `MantineProvider`、`createTheme` 和 Mantine CSS variables 为实现基线。升级 Mantine 时必须先核对本文引用的主题、Styles API 和响应式机制；未安装的 `@mantine/form`、`@mantine/notifications`、图标或 DnD 包不是现有能力。

## 1. 规范等级与使用方式

- **硬规则**保护一致性、可访问性、品牌事实源和宿主边界。实现不得静默偏离；确需例外时按工程规则记录原因、范围、风险、验证与恢复条件。
- **默认规则**给出大多数产品界面的首选方案。有真实用户任务或宿主限制时可以偏离，但要在实现说明中写清原因，不能为个人偏好另建一套局部视觉语言。
- 新增或修改当前宿主的页面、界面入口、布局、组件、交互状态、主题或 CSS 前，读取本文和 `.harness/project.json`；只读取当前 `projectType` 对应的宿主章节。
- 初始化生成的宿主页面与界面入口只是最小工程示例，不代表业务界面自动满足全部产品级检查。第一个真实页面出现时应按本文收敛主题和状态模式。
- 优先使用 Mantine 原生组件和语义化 HTML。只有同一项目内出现至少两处真实复用，或某项产品语义需要集中保证时，才建立本地组合组件；不得建立第二套基础组件库或跨宿主共享包。

### 1.1 设计风格支持

下游项目在 `.agents/skills/design-taste-frontend/SKILL.md` 提供来自 [Taste Skill](https://github.com/leonxlnx/taste-skill) 的设计参考。真实落地页、作品集或视觉改版任务可调用 `$design-taste-frontend`，只采用符合用户目标的排版、构图、留白与层级建议；其字体、阴影、圆角、近黑与单一强调色倾向已内化到 §3 theme 令牌，下游以 theme 为准，不逐页覆盖；数据表、后台工作流、多步表单及受限宿主界面不自动套用营销页规则。

本规范、项目身份与工程规则优先。上游的 Next/RSC、Tailwind、Motion/GSAP、替代组件库和状态库偏好不能替换 Mantine、纯 TypeScript、既有路由、Query/Jotai 或 i18n；字体禁用、固定断点、按钮不换行和英文词数限制不能覆盖项目 theme、语义状态色、中文布局、文本缩放与无障碍要求。安装 Skill 只安装设计文档，不授权依赖安装、远程字体/图片/脚本、图像生成、额外 Lighthouse/浏览器检查或构建；这些动作仍按实际任务和当前宿主门禁触发。

## 2. 设计原则

1. **任务优先**：每个视图先突出用户当前要完成的任务，再展示辅助信息和装饰。
2. **克制一致**：同一语义使用同一组件、颜色、密度和反馈方式；不以更多颜色、阴影或动画制造层级。
3. **渐进披露**：首屏只显示完成当前任务所需的信息，低频设置与技术细节进入展开区、帮助或专用设置界面。
4. **可恢复**：加载、空态、错误、禁用和破坏性操作都说明当前状态以及可执行的下一步。
5. **内容驱动布局**：适配中英文、文本缩放和窄视口，不以固定文案长度或开发机字体作为布局前提。
6. **无障碍默认开启**：键盘、可见焦点、语义标签、对比度和减少动态效果是默认能力，不是交付前补丁。

## 3. 主题与设计令牌

### 3.1 单一主题入口

**硬规则：**

- 全局 theme 保存在当前包内唯一稳定模块，并由根 Provider 消费。`MantineProvider` 只在每个 React 根挂载一次。
- 品牌主色来自 `.harness/project.json.brand.primaryColor` 派生的 `BRAND.primaryColor`；页面、组件和 CSS 不复制品牌十六进制值。
- 全局颜色、字体、字号、行高、间距、圆角、阴影、断点与组件默认值优先进入 `createTheme`。跨组件语义变量无法由内置 theme key 表达时，才通过 `theme.other` 与 `cssVariablesResolver` 暴露命名清楚的 CSS variables。
- 主题对象定义在组件外，不能随渲染重建。每个下游独立维护本文约定的令牌名称和语义，不得跨仓库导入同一源码。

样式选择顺序：

1. theme token 与组件 `defaultProps`；
2. Mantine 组件 props 和非响应式 style props；
3. 稳定、复杂或可复用样式使用 CSS Modules 与 Mantine CSS variables；
4. 需要修改组件内部 slot 时使用 Styles API；
5. 只由运行时测量或计算得到的一次性值才使用内联 `style`。

不得用高优先级全局 CSS、`!important` 或 DOM 结构选择器批量覆盖 Mantine 内部实现。响应式 style props 适合少量布局，不在大列表中逐项生成重复样式。

### 3.2 令牌语义

| 领域   | 统一语义                                                             | 默认用法                                                                                                                                         |
| ------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 字体   | `fontFamily`、`headings.fontFamily`、`fontSizes`、`lineHeights`      | 全局采用 theme 集中声明的系统无衬线栈，不为字体引入未声明的外链；标题与正文共享字体族，以字号、字重和间距建立层级。品牌指定字体时只改 theme 一处 |
| 间距   | `xs`、`sm`、`md`、`lg`、`xl`                                         | `xs` 同组细节，`sm` 控件内部，`md` 常规组件，`lg` 区块，`xl` 页面级留白                                                                          |
| 圆角   | `sm`、`md`、`lg`、`xl`                                               | `defaultRadius: "md"` 管控件，面板与图片容器统一 `lg`；同一视图不混用其他档位，`xl` 仅在整个视图统一采用时使用                                   |
| 阴影   | 无阴影、`xs/sm`、`md`                                                | 常规内容优先边框；悬浮层和临时叠层使用轻阴影；`theme.shadows` 取与 `black` 同色相的低透明度色而非纯黑，不得以多档重阴影表达普通信息层级          |
| 断点   | `xs`、`sm`、`md`、`lg`、`xl`                                         | 默认沿用 Mantine 断点；需要修改时只在 theme 集中修改并使用 `em`，CSS 配置同步同一静态值                                                          |
| 品牌   | `brand`                                                              | 主动作、选中、焦点和少量强调，每个视图只有这一个强调色，其余用中性灰；不是正文色、状态色或大面积装饰背景，不用紫蓝渐变或霓虹发光装饰             |
| 中性色 | `gray`/`dark` 与 Mantine 语义 CSS variables                          | 页面、surface、边框、主文本和次文本；不要为每页创建略有差异的灰色                                                                                |
| 状态   | `green`、`yellow`、`red`、`blue` 分别表达成功、警告、危险/错误、信息 | 状态必须同时有文字或图标等非颜色线索；品牌色不能替代全部状态色                                                                                   |

**硬规则：**

- Mantine 自定义颜色必须满足当前版本要求的至少 10 个条目。初始化从品牌主色派生十阶 `brand` 色阶，避免重复同一色值；真实产品使用 hover/active 和文本对比时，仍须针对实际品牌色逐项验证。中性状态 Badge 使用 Mantine `default` 变体。
- 文字与背景、交互边界、状态和焦点指示满足 WCAG 2.2 AA；普通文字至少 `4.5:1`，大号文字和必要非文字界面信息至少 `3:1`。品牌 Logo 的豁免不能扩展到按钮文字或正文。
- 色彩方案默认跟随系统 `auto`，并提供显式亮色/暗色切换。偏好使用项目命名空间的 `localStorage` 键；页面背景与文字使用 Mantine 语义变量。真实产品增加新 surface、状态色或 Logo 时，逐项验证两种方案和最终产物。
- theme 的 `black` 设为带轻微色倾向的近黑，不以纯 `#000` 作正文色；自定义 surface 不硬编码 `#000`/`#fff`，使用 Mantine 语义 CSS variables。
- 可点击控件须有可见的 hover、active 与 focus 状态；优先沿用 Mantine 默认状态，自定义组件补齐，位移类反馈在 `prefers-reduced-motion` 下关闭。
- focus ring 不得设为 `never`。主题与自定义组件必须保留键盘可见焦点，并避免被 sticky header、overlay 或滚动容器遮挡。
- 动画和过渡必须尊重 `prefers-reduced-motion`；不得用动画作为唯一状态提示。

### 3.3 排版层级

每个视图最多使用下列稳定层级：

| 层级          | Mantine 表达                | 用途                                         |
| ------------- | --------------------------- | -------------------------------------------- |
| 页面标题      | `Title order={1}`           | 当前页面或主任务，每个页面一个               |
| 区块标题      | `Title order={2}`           | 页面内主要分区                               |
| 子区块标题    | `Title order={3}`           | 复杂区块内分组；不要为了视觉大小跳过标题层级 |
| 正文          | `Text size="md"`            | 默认说明、结果和表单上下文                   |
| 辅助文字      | `Text size="sm" c="dimmed"` | 帮助文案、元数据、时间和次要说明             |
| 极短标签/眉题 | `Text size="xs"` 或 `Badge` | 分类或状态，不承载长句                       |

长说明左对齐并控制行宽；营销页可以居中短标题，但表单、错误、帮助与多行正文不使用大段居中排版。只用字重和字号建立主次，不同时叠加大字号、全大写、品牌色与重阴影。

## 4. 布局、密度与层级

### 4.1 通用布局

- 页面由页面、内容面板、区块、字段、操作五级关系组织。页面容器控制宽度和外边距，内容面板承载一组相关内容，区块用标题与间距分组，字段保持标签/输入/帮助/错误相邻，操作与其影响对象就近出现。
- 默认密度为 `comfortable`：常规控件使用 Mantine `md` size，区块 gap 使用 `md/lg`。受限空间可以采用 `compact`，但最小点击目标仍不小于 `24 × 24 CSS px`；主要触控动作默认接近 `40 × 40 CSS px`。
- 同一操作组只保留一个视觉主动作。主动作使用品牌 filled，次要动作使用 default/outline，低优先级动作使用 subtle/链接；危险动作使用 red 且不得与主动作同色。
- 内容面板默认使用 `Paper/Card` 的边框和统一圆角；只有浮层、拖拽对象或需要明显脱离页面的临时区域使用 shadow。避免卡片套卡片和每个区块一张卡。
- 主要内容按 DOM 顺序排列。视觉重排不得造成键盘焦点顺序与阅读顺序不一致。

### 4.2 响应式策略

- 采用移动端优先策略。先保证等价于 `320 CSS px` 的窄容器、200% 文本缩放和用户覆盖文本间距后仍可用，再从 Mantine `sm/md/lg` 断点扩展列数或留白。
- 断点只解决真实结构变化：单列/多列、导航显隐、操作组换行、次要信息折叠和容器宽度。不要为每个组件发明局部断点。
- 小范围响应变化可用 Mantine 响应式 props；复杂或重复布局使用 CSS Modules。大列表避免在每一项上使用响应式 style props；需要时先用容器/网格 CSS，存在证据再考虑 `deduplicateInlineStyles`。
- 文案、按钮、表单和状态区域允许自然换行；不以固定高度裁切中英文。数据表在窄屏优先保留关键列、卡片化或允许局部横向滚动，不让整个页面横向滚动。

## 5. 组件语义

### 5.1 Button、ActionIcon 与链接

- Button 文案使用“动词 + 对象”，避免“确定”“点击这里”等脱离上下文的词。仅图标动作使用 `ActionIcon`，必须提供可访问名称；Tooltip 只能补充说明，不能成为唯一名称。
- 提交期间使用组件的 loading 状态并阻止重复提交；禁用态仍应通过附近说明解释原因。完成后提供可感知的成功或失败反馈。
- 页面跳转使用链接语义，触发操作使用 button 语义。不能以 `onClick` div 模拟按钮，也不能只为视觉效果把导航做成按钮。
- Mantine 与 Router Link 组合优先使用 `renderRoot` 或保留具体 Router 泛型的类型化组合；确保 `to`、params、search 仍被检查，并透传真实 anchor 的 props、事件与 ref。不能仅用 `component={Link}` 丢失参数推断后再靠 `any`、`as never` 或双重断言消除错误，也不嵌套两个链接。
- 破坏性操作说明对象和影响范围；不可轻易恢复时使用二次确认，并在确认界面保持取消为安全默认。

### 5.2 表单

- 每个输入都有可见 label；placeholder 只展示示例，不替代 label。必填、格式、长度和单位在提交前可理解。
- helper 描述输入要求，error 描述发生的问题和修复方式；两者不得混成同一句常驻红色文字。
- 表单默认单列，相关短字段才并列。主要提交动作位于表单末尾且位置稳定；服务器错误在表单或相关字段附近显示，不只发瞬时通知。
- 原生 Mantine 输入足够时不自建底层控件。只有出现真实复杂表单需求时才评估并安装 `@mantine/form`；未安装前不在文档或代码中假定其存在。
- 使用原生 `form` 和单一 `onSubmit` 入口，提交按钮明确 `type="submit"`，其他按钮明确 `type="button"`；单行输入的 Enter 提交与点击执行同一校验和动作，多行输入保留换行语义。按字段语义声明 `name`、`autoComplete`、`inputMode`，允许粘贴与浏览器自动填写。
- 客户端校验只改善交互，服务端校验仍是权威。首次提交失败时聚焦首个无效字段或有名称的错误摘要；输入过程不反复抢焦点。错误与字段通过可访问描述关联，只把已校验的服务端错误码映射为本地化文案。
- 提交期间防止重复动作；失败保留输入、草稿和可恢复错误，成功后才按明确交互更新表单基准或清空。后台 Query 刷新不能覆盖用户正在编辑的值，取消请求不能被宣称为撤销服务端写入。
- 只有存在真实未保存修改和丢失风险时才接入 Router 导航阻断，并明确站内导航、刷新/关闭的覆盖边界；不能用一个自定义弹窗声称覆盖全部浏览器离开路径。拒绝离开保留草稿，保存成功后解除阻断。
- mutation 的重试、缓存失效和乐观回滚遵循 [`DATA_ACCESS.md`](DATA_ACCESS.md) §2.6；真实表单测试覆盖 Enter、校验失败焦点、提交防重、服务端失败保留输入和成功反馈。

### 5.3 内容、导航与数据

- `Paper/Card` 承载一个明确主题；Badge 只表示短状态或分类，不作为标题上方的装饰性眉题或普通正文装饰。导航的当前项同时通过语义状态和视觉样式表示。
- 列表/表格首次加载、刷新、空数据与失败分别处理。刷新保留可用旧内容并显示局部进度，不用整页闪烁替换。
- 分页继续复用 `src/pagination/` 的受控 page/pageSize 基础。页码、上一页/下一页和每页条数保留本地化名称；窄容器允许操作组换行，不复制另一套分页状态。
- Tooltip、Popover、Menu、Modal 和 Drawer 必须可由键盘打开/关闭，关闭后焦点回到触发器。弹层内容超过当前宿主空间时改用更宽或更持久的宿主界面，而不是无限嵌套或缩小文字。

### 5.4 React Web 重复记录视图

- `projectType=web` 的列表页、数据表格、后台列表或搜索结果页同时调用 `$web-implement-list-view`；该 Skill 只编排本文和 [`DATA_ACCESS.md`](DATA_ACCESS.md) 的当前事实，不建立第二套 UI 或分页规范。
- 先根据真实信息结构选择 Table、卡片列表或搜索结果；只有二维关系确实需要行列语义时才使用 Mantine Table，不为命中 Skill 强制改为表格。
- 首次 loading、后台刷新、筛选无结果、全局无数据、可重试错误与终态错误分别表达；纯翻页 placeholder 只读，选择、分页、批量和行内副作用在旧内容上禁用。
- 可见结果范围、总数、刷新、错误和选择反馈使用稳定的 live region，不因同一状态的组件重渲染重复播报。分页 landmark、页码、上/下页和每页数量具有本地化可访问名称。
- 表格仅在局部、有名称、可聚焦且焦点可见的滚动区内双向滚动，sticky offset 来自共享布局事实。`Table.Thead` 使用稳定 CSS Module 类，其 `th` 以 `background-color: var(--mantine-color-body)` 提供随主题变化的不透明背景，避免滚动数据透出；不让页面根水平滚动。卡片/行的子控件自己拥有动作，hover 高亮不得暗示父容器是按钮。
- Table 的唯一主业务单元格使用 `th scope="row"` 给行提供可理解名称；可排序列同时提供与当前方向一致的 `aria-sort` 和可见图标，不只用颜色或隐藏文本表示状态。
- 选择、列显隐与列顺序只在真实产品需求出现时启用。拖拽列重排才需按授权流程在当前 Web 项目本地安装 DnD 依赖，并同时提供键盘 sensor、命名手柄、移动按钮和位置播报；不因列表能力存在而预装依赖或生成空 UI。

## 6. 状态与反馈

| 状态       | 必需信息                           | 默认呈现                                                        |
| ---------- | ---------------------------------- | --------------------------------------------------------------- |
| 首次加载   | 正在加载什么                       | 与最终结构接近的 Skeleton 或有名称的进度；避免短请求闪烁        |
| 后台刷新   | 旧内容仍可用、正在更新             | 保留内容，标题或局部区域显示轻量进度                            |
| 提交中     | 哪个动作正在执行、不能重复提交     | 触发 Button loading/disabled，相关字段按风险决定是否锁定        |
| 成功       | 已完成什么、必要时下一步           | 就近状态或短时提示；关键结果不只依赖会消失的通知                |
| 空态       | 为什么为空、用户接下来能做什么     | 内容容器内的标题、简短说明与至多一个主动作                      |
| 可重试错误 | 哪项失败、是否保留数据、如何重试   | 就近 Alert/错误面板与明确重试入口                               |
| 权限/认证  | 缺少什么条件、如何恢复             | 专用说明与安全入口；不把权限问题伪装成普通网络错误              |
| 系统错误   | 当前操作无法继续、用户数据是否安全 | Error boundary/fallback；技术细节进入脱敏日志，不直接暴露 stack |

HTTP 基础已生成 `HttpErrorView` 和每个 React 根唯一的 `HttpFeedback`，使用既有 Mantine Alert 与 i18next。全局提示持续保留原内容，关闭只清提示；局部/路由接管同一错误后精确清理全局反馈，同语义重复只播报一次，最新失败拥有清理权。401/403 使用专用本地化状态，只有真实入口存在时才提供认证或权限申请动作；写入失败不能提供未经业务确认的重放按钮。

如果另外引入全局通知，必须先安装并验证 `@mantine/notifications`，在每个 React 根只挂载一个 Notifications 容器，并保留关键反馈的持久、就近表达。Toast 不能承载字段错误、长说明或唯一的完成证据。

## 7. 无障碍、国际化与内容

**硬规则：**

- 目标达到 WCAG 2.2 AA；以下项目是当前工程的最低检查，不替代对适用成功准则的完整一致性评估：语义化 landmarks、连续标题层级、键盘全流程、可见且不被遮挡的焦点、可访问名称、状态消息和正确的 name/role/value。
- 图像有信息时提供有意义的替代文本；纯装饰图使用空替代或从辅助技术隐藏。颜色不是错误、选中、趋势或必填的唯一线索。
- 文字可放大到 200% 而不丢失内容或功能。对纵向滚动内容，还要在等价于 `320 CSS px` 宽度（例如 `1280 CSS px` 视口下 400% 缩放）时保持单向回流；只有数据表、地图等确实依赖二维布局的内容可以局部双向滚动。
- 用户覆盖正文行高为 `1.5` 倍字号、段落间距为 `2` 倍字号、字间距为 `0.12` 倍字号、词间距为 `0.16` 倍字号时，不得丢失内容或功能。
- 交互目标至少满足 `24 × 24 CSS px`，或具备 WCAG 2.2 允许的间距或其他例外；高频与主要操作优先使用更大目标。
- 当前界面 locale 必须同步到文档根元素的 `lang`；单独出现的其他语言片段使用局部 `lang`。项目名称、描述和品牌值属于事实源身份文案，默认按原值展示；若产品需要本地化身份，先扩展事实源契约，不得在翻译资源中维护互相冲突的副本。
- 用户可见文案全部进入 i18next。禁止用字符串拼接组成句子；变量、复数、日期、时间、数字和单位通过完整翻译模板与明确 locale 格式化。产品明确只服务单一 locale 的内部工具是标准豁免场景，不需要逐次论证业务理由；仍要按 [`ENGINEERING_RULES.md`](ENGINEERING_RULES.md) §9 记录范围（哪些页面/组件不接入 i18next）、验证（改用受控本地化文案而非拼接字符串）与恢复条件（产品需要新增 locale 时的接入路径），只是可以省略"为什么单语言合理"的业务论证部分。
- 布局同时验证英文和中文。按钮与标签不写死宽度；受限宽度的界面使用短文案，详细解释进入 helper、帮助或专用设置界面。项目名称、描述和品牌值继续从事实源派生，不复制为翻译常量。
- 不假定 Mantine 组件或语义元素会自动播报异步变化。未移动焦点的加载结果、提交结果和错误等动态状态必须显式使用 `role="status"`、`role="alert"`、`aria-live` 或等价机制，并验证只播报一次且不会重复。
- `Button`、`Anchor`、`Switch`、`Checkbox`、菜单项等语义控件必须自己拥有动作；包含这些控件的 Card、Paper、Table 行/单元格或其他父容器不得代理子控件动作，也不得依赖 `stopPropagation` 才维持正确语义。父容器确有独立主动作时为该动作提供单独的可聚焦语义所有者，并分别测试子控件与周围容器区域。
- 错误文案说明影响和恢复动作，不向用户展示原始异常、服务端内部消息、Token、路径或堆栈。

**默认规则：**

- 主按钮使用 2–8 个汉字或 1–3 个英文词；无法做到时优先调整布局，而不是截断动作含义。
- 日期、时间和相对时间在同一视图使用一致精度；没有产品时区规则时明确采用用户 locale，不把开发机时区写成事实。
- 已移动焦点到新上下文时，不再额外制造重复 live region；保留在原位置的动态结果则按硬规则提供显式播报语义。

## 8. Web 宿主规范

Web 页面采用以下三类布局，不把初始化的居中 Hero 复制到所有业务页：

| 页面类型  | 默认结构                           | 容器与密度                                                   |
| --------- | ---------------------------------- | ------------------------------------------------------------ |
| 欢迎/营销 | 品牌区 → 价值说明 → 单一主动作     | `Container size="sm/md"`，允许短内容居中和克制装饰           |
| 工具/列表 | 页面标题/操作 → 筛选 → 内容 → 分页 | `Container size="lg/xl"`，内容左对齐；操作组在窄屏换行       |
| 表单/设置 | 页面标题 → 分组表单 → 提交/危险区  | `Container size="sm/md"`，默认单列；危险区与普通设置明显分隔 |

- 只有存在持续导航、header/aside 或真实 shell 需求时才使用 `AppShell`；单页工具不为视觉完整感制造空导航。
- 全局 theme 固定由 `src/app/theme.ts` 导出，并由 `src/app/AppProviders.tsx` 的根 `MantineProvider` 消费；不要在 route 或 feature 内重建 Provider。
- 页面主体下限为 `320px`，不依赖固定高度垂直居中。sticky 区域不得遮挡焦点或错误；路由切换后标题与焦点策略可理解。
- route 文件只声明路由契约，页面布局和状态组件留在 feature。跨页面重复的 PageShell、状态面板或 SectionHeader 出现真实复用后再提取。
- 浏览或管理重复记录的页面按 §5.4 调用 `$web-implement-list-view`，路由状态、Query 数据与分页的详细所有权以 [`DATA_ACCESS.md`](DATA_ACCESS.md) 为准。
- CSS Modules 和 Mantine CSS variables 承担复杂布局；不要在全局 `styles.css` 为业务页面不断追加类名和品牌常量。
- 当前单包只保留站点入口、路由与资源，不增加第二宿主。

### 8.1 功能组合的页面与布局

按已选择的认证、组织、权限及业务操作采用本节布局；创建不注入页面。原型只做一个桌面设计，实施按实际设备范围适配。需要工作区时提供完整应用布局，不添加虚构业务。

| 区域     | 可复用布局                                                                                   | 按操作选择                                                                          |
| -------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 入口     | 未登录默认进入登录页；已有凭据先恢复会话，用户与权限就绪后才进主 UI；保留安全的原目标        | 公开营销首页单独确认，不能默认充当客户端或后台入口                                  |
| 认证页   | 完整页面；桌面品牌/说明与表单分区，表单宽度可读，窄屏收为品牌与单列表单，内容自然滚动        | 只有明确选择注册且服务支持时才提供注册入口、路由与请求                              |
| 表单辅助 | 语言和外观用紧凑控件收在表单内，立即生效并保留输入与返回目标；找回密码、注册等次动作层级清楚 | Mock 边界用可展开的“演示账号模式”说明与必要凭据；不默认增加跳过登录的演示工作区按钮 |
| 工作区   | 完整高度的侧栏、顶部工具区、右侧账号菜单与宽幅主内容；每页有标题、主动作、状态和内容层级     | 只显示已采用且有权限的功能；不照搬参考图品牌、工具业务、费用或配额                  |
| 侧栏底部 | 稳定显示当前身份、作用域及真实可用的状态信息，收起后仍可访问                                 | 按实际作用域显示当前组织和操作者身份，管理目标组织在业务页内明确标注                |
| 窄屏     | 侧栏转为等价抽屉/紧凑导航，账号菜单仍可达，筛选与动作换行，长表格局部滚动                    | 导航收起不丢失当前页与选中态；偏好、退出、条件性组织切换不能仅桌面可用              |

基础元素按真实职责组织：认证布局与表单辅助、应用 shell、导航项与分组、侧栏上下文、账号菜单、页面标题/操作、加载/空态/错误/恢复面板。使用现有 Mantine 与项目令牌；出现真实复用后提取本地组合，不预建第二套组件库或业务模块。

账号菜单的固定主线是当前账号与退出；仅明确采用切换且服务确认多个可用组织时增加组织切换；管理目标不改变操作者身份。弹窗关闭、取消或异步恢复后把焦点交还稳定触发器；会话恢复或退出使旧弹窗失效时关闭它，异步回调不得重开旧组织视图。加载、网络待恢复、无权限和空业务均在完整布局中有可执行下一步，不用假统计、假订单或占位工具填满页面。

原型自查与开发回归按已采用范围及各自设备边界覆盖：匿名直达与返回目标、会话冷恢复、登录/退出、已选注册、组织切换与找回、表单内偏好切换及输入保留、账号菜单/弹窗键盘与焦点、桌面侧栏收起、空态/错误恢复；窄屏导航仅由产品实现及对应回归覆盖。已选购买时另覆盖商品选择、订单管理、钱包管理；未选时三项入口和请求不存在。局部检查不等于最终浏览器验收。

### 8.2 路由加载、错误与恢复

- 持续导航的布局保持挂载；子路由的 pending/error 放在正文插槽，普通菜单切换不重建侧栏、账号菜单、底部身份区或全局 Provider。同一会话导航凭据校验仍须先完成再放行目标 loader/页面，异步守卫放在叶路由或具有等价隔离效果的边界，不能为保留外壳提前加载未授权正文。会话失效或作用域变化可立即隐藏私有区域，详见认证会话合同。
- 初始化在 `src/features/route-state/RouteState.tsx` 生成统一路由状态，并由 `src/app/router.tsx` 消费 `routeStateDefaults`。慢路由使用本地化 `role="status"`；沿用 Router 的加载阈值和最短展示时间，真实 feature 可以按实际结构覆盖，不为静态页面制造假请求。
- 默认 `RoutePendingPage` / `RouteErrorPage` 为独立页面提供 `main`；已有 `AppShell.Main` 或 `main` 的布局，其子路由显式装配 `RoutePendingContent` / `RouteErrorContent`，在正文插槽内复用相同状态与恢复行为，不嵌套主内容 landmark。
- loader、路由组件渲染和路由加载失败进入安全错误界面；原始异常只交给统一 logger。未知路径仍走独立 404；已有 `HttpErrorView` 区分认证、权限、网络、超时、频率与服务错误，真实 feature 复用分类，不能把所有失败都显示成 404。
- 只有允许恢复的读取显示普通重试，401/403 无普通重试或虚构登录按钮，回首页使用 Link；用户显式重试调用并等待 `router.invalidate({ sync: true })`，每次配合 Query error boundary reset 恢复读取；只重置 React boundary 不能替代重新执行 loader。按钮防止重复点击，持续失败仍保留恢复入口，不自动重放 mutation 或额外清空产品草稿。路由错误可能卸载子树，组件本地状态不保证保留；真实表单按 §5.2 定义草稿保存边界。
- route 状态与外层 `AppErrorBoundary` 分工：前者覆盖路由内的加载与渲染，后者保留为 Provider/根渲染失败的最后防线。致命启动失败不能承诺原地恢复；需要重新打开页面时，文案明确这一操作。
- 生成测试使用真实 Router 覆盖慢 loader、首次失败后重试、持续失败、渲染异常和 404 返回首页；这些单元证据不替代真实浏览器布局或网络验收。

### 8.3 页面标题、焦点与滚动

- 中性单页只提供事实源派生的站点 title。首次出现真实多页面时，声明每页本地化标题与唯一的文档 title 所有者，采用“页面标题 + 项目名称”；语言变化同步更新，404 和错误状态也有可识别标题，不把敏感查询或实体数据拼进 title。
- 不同 pathname 的导航完成后，将焦点交给新页面标题或主内容入口（可使用 `tabIndex={-1}`）；组件负责在内容可用后聚焦。相同页面的搜索、分页、刷新与 Query 完成不抢焦点，由局部状态播报结果。
- 多页面时在当前 Router 配置中启用并验证 `scrollRestoration`，明确窗口或 AppShell 滚动容器。前进/后退恢复历史位置，普通新页面与 hash 锚点各自遵守导航语义；聚焦使用 `preventScroll` 时不得破坏历史滚动恢复。
- 有持续导航时提供跳到主内容的键盘入口，当前项使用语义状态。异步导航、菜单关闭与弹层焦点返回不能争抢同一个目标；测试以真实导航、历史返回和键盘路径证明行为。

### 8.4 导航路由与当前项

- 每个表示独立页面的叶子菜单项拥有独立的规范 URL，点击、刷新与直接访问落在同一页面；不能让多个页面菜单复用同一目标再靠局部状态切换。纯分组开合使用 button，不伪装成页面链接。
- 页面路径、标题、菜单可见性与路由权限消费同一份真实页面声明和权限判断。路径身份不能按字符串前缀猜测；权限码不要求逐页唯一，同一权限可以按服务契约覆盖多个页面。
- 每个可见导航区域最多一个 `aria-current="page"`，视觉高亮与它一致。叶子菜单使用 Router 的精确匹配；TanStack Router Link 显式设置 `activeOptions.exact: true`，不要同时用手写 `aria-current` 与默认前缀激活竞争当前态。父分组的展开/祖先状态与当前页分开表达。
- 尾斜线按当前 Router 约定规范化，search/hash 只有确实区分页面身份时才参与激活；详情页归属哪个菜单由页面声明明确指定。未知路径不能因共享前缀继承某个页面的身份或权限。
- 导航变化的相关测试通过真实 Router 点击与直达，覆盖父路径、同级页面、尾斜线、search 和历史返回；分别核对桌面、收起与窄屏的可见导航区域，断言 URL、页面标题、唯一当前项与视觉状态一致。是否运行浏览器仍按当前任务事件决定。

### 8.5 路由布局与插槽

- 采用工作区布局时，根负责全局布局/入口分流，应用父路由负责持久 shell 与一个正文 `Outlet`，工作台及其他页面各为独立叶路由；父布局路径不兼作另一个菜单页面。工作区的参考路径为 `/app/dashboard`，已明确采用的其他路径沿用其合同；普通欢迎页或单页工具仍可把 `/` 作为真实首页，Extension 不采用本节文件路由。
- 已采用的认证页复用认证父布局：登录、找回与注册各自按明确选择呈现；需要共享布局而不增加 URL 段时使用 pathless 路由。认证模式与表单状态归叶页面，语言/外观偏好归既有拥有者；页间切换保留经校验的安全返回目标，成功或离开后按流程清理密码与验证码。
- 一个当前页面只有一个主内容 landmark。shell 使用 `AppShell.Main` 时叶页面提供 section/标题，不再嵌套 main；认证布局也遵循相同语义。固定或 sticky header 的实际高度与 AppShell offset 一致，换行、窄屏与文本缩放不得遮挡正文或焦点。
- 布局入口仅做精确、可解释的重定向；未知路径保留 404，不以共享前缀推断页面。URL 段、文件层次、路由 ID、菜单名称与插槽归属在当前页面声明中可追踪，`_auth` 等 pathless 文件名不泄漏进公开 URL；生成 route tree 由工具维护。
- 回归使用真实 Router 覆盖同级叶页面、慢校验、加载失败、直达与历史返回；以语义查询找到 shell 节点，再核对节点身份和局部交互状态持续保留，同时证明目标正文不会在授权前挂载。冷恢复、失效退出和换 scope 另测其应发生的隐藏与重建。

## 9. Extension 宿主规范

Popup 与 Options 使用同一主题语义，但服务不同任务：

| Surface | 目标                           | 默认布局                                                                                |
| ------- | ------------------------------ | --------------------------------------------------------------------------------------- |
| Popup   | 在一次短会话中完成一个主要任务 | 基线最小宽 `320px`，内容可在 `320–400px` 内调整；身份区 → 主任务 → 状态/帮助 → 次要操作 |
| Options | 完成长表单、详细配置和帮助     | 默认最大宽 `760px`、居中单列；设置按 section 分组，必要时再引入两列                     |

- Popup 首屏应看到当前状态和主动作；不放多层导航、复杂表格、长帮助、无限滚动列表或需要长期阅读的内容。超出范围的任务明确跳转 Options。
- Extension Popup/Options 各自使用 TanStack Router 代码路由，不调用 `$web-implement-list-view` 或复用 Web 列表恢复逻辑；扩展的重复项界面仍按当前 surface、消息与 Storage 契约单独设计。
- Popup 使用 compact but operable 密度：可以采用 `sm` gap/控件，但可点击目标、可见焦点、错误和文本缩放不得牺牲。核心 CTA 不应依赖滚动才能发现。
- Options 不复用 Popup 的固定宽度和紧凑密度，也不引入与设置任务无关的站点式导航。只有设置量真实增长后才增加目录/侧栏。
- theme 与根 `MantineProvider` 保持在 `src/providers.tsx`；只有出现真实跨入口复用需求时才提取单独 theme 模块。
- Popup/Options 的实际 Router 各自装配 `ExtensionRouteErrorPage`，复用 HTTP 分类、Query reset 和读取恢复；两入口各挂载一个 `HttpFeedback`，不跨上下文共享反馈或认证 latch。
- Popup/Options 各自挂载 Provider 时使用同一包内 theme 定义；外观偏好通过项目命名空间的 `localStorage` 保存，不跨执行上下文假定弹层、通知或焦点状态自动共享。
- 避免远程字体与远程样式依赖，保持 Chrome MV3 / Firefox MV2 的 CSP 与资源自包含。Overlay、Select、Menu 和 Tooltip 必须在扩展 surface 的实际视口内验证位置、裁切和关闭行为。
- 当前单包只保留扩展入口、资源和已批准的最小权限，不增加第二宿主或站点路由。

## 10. 交付检查

### 10.1 实现自检

- [ ] 主题、品牌值和语义 token 只有一个来源；没有新增散落的品牌 hex、字体栈、圆角、阴影或任意间距常量。
- [ ] 页面符合当前宿主的一种明确布局；主动作唯一，危险、次要与导航动作语义正确。
- [ ] 首次加载、刷新、提交、空态、成功与错误按真实异步路径覆盖适用状态；错误有恢复动作。
- [ ] 表单有 label、helper/error 和提交反馈；仅图标控件有可访问名称。
- [ ] 键盘可以完成核心任务，focus ring 可见且不被遮挡，弹层关闭后焦点恢复。
- [ ] 中文、英文、`lang` 同步、200% 文本缩放、等价 `320 CSS px` 回流和用户覆盖文本间距下无裁切、重叠或不可达操作。
- [ ] 未移动焦点的动态加载、提交和错误状态具有明确 live region 语义，且不会漏报或重复播报。
- [ ] 颜色与非颜色线索共同表达状态，对比度达到目标；减少动态效果设置得到尊重。
- [ ] 当前单包只保留 `.harness/project.json.projectType` 对应的宿主入口、资源与已批准权限。
- [ ] Web 重复记录视图选择了有信息结构理由的 Table/卡片/搜索形态，并按 `$web-implement-list-view` 清单记录适用项；Extension 该项为 N/A。

### 10.2 测试与验收

- UI 行为变化使用 Testing Library 从角色、名称和用户操作验证，不以 class、内部 DOM 或大快照代替语义断言。
- 验证布局连续性时，可以在语义查询的基础上断言节点身份与局部状态保留；它补充用户行为断言，不能只凭渲染次数或节点引用声称导航、权限与恢复正确。
- 至少覆盖核心成功路径和最高风险失败路径；按变更实际涉及补 loading/empty/error、live region、键盘、焦点恢复、禁用防重、文档语言、i18n 标签和响应式结构断言。
- 含子控件的可操作容器分别点击 Button/Link/Switch/Checkbox 与周围非控件区域，证明各动作只有一个所有者且不会互相代理。
- theme 或共享状态组件变化要验证 Provider 下的真实消费方；测试中的 `MantineProvider env="test"` 只稳定 transition/portal，不等于浏览器视觉验收。
- 普通变更运行受影响的最小充分检查；显式 Release 候选或完整验收按工程规则构建精确产物。用户、产品、安全或渠道硬要求真实浏览器时，检查目标宿主、中文/英文、窄宽度、键盘焦点和关键状态，并记录未验证平台。

## 11. 反模式

- 在页面或 JSX 散落 `#hex`、独立字体、`7px/13px` 等无令牌值，或用 `!important` 压过 Mantine。
- 每个页面各自定义 hero/card/shell、状态色、按钮层级和 loading/empty/error 组件。
- 把 10 个相同品牌色值当成已完成的色阶，并直接依赖 shade index 表达浅深层级。
- 同一操作组出现多个 filled 主按钮，或让危险操作沿用品牌主色。
- 用 placeholder 代替 label、用 Tooltip 代替可访问名称、用颜色或 Toast 作为唯一反馈。
- 用 Jotai 镜像 Query 数据只为改变样式，或为局部 hover/open 状态创建全局 atom。
- 在大列表逐项生成响应式 style props，或以 JS 宽度判断替代可由 CSS 完成的布局。
- 只因页面包含重复记录就强制 Table、选择、列偏好或拖拽，或在中性初始化中生成假列表来展示能力。
- 为未来可能使用的 form、notifications、dates、charts 或图标库预装依赖和空组件。
