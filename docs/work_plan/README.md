# 工作计划索引

本目录只在用户明确要求持久计划、任务需要跨会话交接，或发布/高风险工作确需协调时保存当前 Todo。日常开发不自动创建 Work Plan；多步骤、多模块、中等风险或可并行本身不构成准入。

## 写入规则

- 文件名固定为 `YYYYMMDD_work_plan.md`，日期使用计划更新所在时区的自然日；同一天只维护一份。
- 新自然日首次写入时读取前一份活动计划，把仍有效步骤、未完成事项和新增范围整理为完整当前快照。
- 持久计划至少包含稳定 Todo ID、状态、可观察结果、依赖与必要验证；状态只使用 `pending`、`in_progress`、`blocked`、`done`。
- 计划存在和 Todo 完成都不自动触发 Product Spec、Product Status、ADR、Changelog、Verification、构建、E2E、并行或发布。
- 只保留当前活动计划；被完整取代或已结束的旧文件删除，历史由 Git 保存。
