## 里程碑：统一分页状态与 HTTP 请求上下文

### 目标与路径

- 路径：里程碑。
- 目标：让新生成的 Web 与 Extension 单包都具备同一套分页状态、语言偏好和 HTTP 请求边界；真实集合页只需绑定业务 Query 与登录入口，不再各自发明 Storage、header、Token 或 401 处理规则。
- 当前事实：这是未初始化的 Harness 源，没有 `.harness/project.json`；两种互斥模板分别生成相同工程契约，不产生同仓多宿主，也不虚构真实 endpoint、登录页或 Extension 网络权限。
- 演进说明：本里程碑取代前述 WFR 里程碑中“只生成 `src/api/README.md`、不生成 client”的当时范围；旧段落保留为历史执行证据，不再代表当前初始化契约。

### 范围与协议决定

- 分页内部标准使用从 1 开始的 `page`、受控 `pageSize`、`items` 与非负安全整数 `total`；服务按实际接口文档把外部字段映射到该规范化结构。`pageSize` 是用户所说的“数据量”，sessionStorage 只保存 `{ version: 1, page, pageSize }`，不保存列表、`total`、错误或用户数据。
- 每个集合使用项目 ID、Schema 版本和稳定 `scope` 隔离 Storage key。同页多个列表必须使用不同 scope；pageSize 变化时回第一页。
- 只有当前 `page/pageSize` 对应的请求已成功、非 fetching、非 placeholder 且 `items` 为空时，`page > 1` 才回退第一页；loading、error、旧响应、第一页空态和成功非空均保持当前位置。
- `X-Http-Request` 定义为服务端批准传播的 opaque continuation/correlation header：只从同一受控 API 边界的成功响应提取并供后续请求携带，不生成或复用每请求唯一 request-id，也不把其值默认写入日志。
- `X-Lang` 每次 dispatch 动态读取规范化语言；语言偏好按 `<project-id>:language:v1` 写入 localStorage，非法值或 Storage 失败回退浏览器语言与英文且不阻断应用。若响应随语言变化，业务 Query key 必须包含语言。
- `X-AUTH-TOKEN` 默认从同名响应 header 提取，同时提供按真实接口文档替换的异步 extractor；Token 只保存在当前运行上下文内，不写 localStorage/sessionStorage。乱序响应不得覆盖较新的 continuation/Token，迟到旧 401 不得清掉新 Token。
- 401 清理当前请求实际使用且仍为当前 revision 的 Token 及同会话 continuation，记录不含 header/body/Token 的稳定日志，并通过 single-flight 的 `UnauthorizedHandler` 调用真实登录导航；模板提供需要显式真实登录地址/导航函数的适配器，不硬编码不存在的 `/login`。Extension 不新增 background、`storage` 或 `host_permissions`，所以跨 Popup/Options 上下文会话和真实远端请求仍需产品里程碑另行设计与授权。
- 基础传输使用浏览器原生 Fetch 的类型化 client factory，不新增 Ky/Axios 依赖、不生成业务请求。真实 Ky/openapi-fetch 接入也必须复用同一 header、并发、错误和安全语义。
- 范围外：真实 API schema/endpoint、refresh endpoint、自动重放、登录 UI、Cookie 策略、跨 Extension execution context 的认证所有者、新增 manifest 权限、生产调用、部署或发布。
- 并行判断：工作区从任务开始即包含大量未提交用户内容，没有可安全建立 Worktree 的干净提交基线；可并行只读审计，最终写入由主 Agent 顺序整合并保护已有修改。
