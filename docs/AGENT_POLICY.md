# Agent 运行策略

本文件是任务路径、持久计划、并行协作与真实浏览器验收偏好的唯一持久事实来源。可选流程用于提高特定任务的可信度或可恢复性，不替代安全规则、用户授权、产品要求或发布渠道硬门禁。

## 字段语义

- `decision_mode: reuse_then_infer_then_ask`：先复用本文件，再根据任务风险和真实产物判断；只有字段非法、规则冲突、无法建立可运行性或需要新增外部授权时才询问。
- `standard_work_plan: optional`：标准任务只有在跨会话、需要交接或失败恢复、步骤依赖明显，或用户明确要求时才创建持久 Work Plan；否则可直接实施，并在当前任务内维护必要的轻量进度。
- `parallel_worktree_subagents: enabled`：任务能拆成至少两个写入边界清晰、互不重叠的单元时，允许并行 Agent/Worktree。它不要求为不可拆任务强行并行。
- `milestone_smoke: optional`：里程碑的静态、测试与 Release 证据完成后，仅在浏览器运行时仍是主要风险、产物价值足以覆盖执行成本，或用户/产品/渠道要求时运行真实候选冒烟；跳过时记录 `Not run` 与未验证风险。
- `milestone_e2e: disabled`：默认不自动执行可选 E2E；用户、产品、安全或渠道明确要求时仍必须执行。关闭 E2E 不允许把 Mock 或源码检查冒充真实产物验收，也不跳过三环境校验、Release 构建、自动 `pnpm release:inspect` 或其他固定门禁。

对 `milestone_smoke`/`milestone_e2e`，`enabled` 表示满足适用条件时默认执行，`optional` 表示按增量风险与证据价值选择，`disabled` 表示默认跳过；并行字段的 `enabled` 只表示允许创建，不表示必须并行。用户更严格要求或产品、安全、渠道硬门禁可以覆盖浏览器默认值。一旦某项被选为当前候选的必需检查，失败、超时、取消或未执行都不能再按“可选”忽略。

## 任务路径

快速、标准和里程碑是逐任务选择，不是新的持久字段：

- 快速：局部、可逆、低风险；直接实施并运行受影响检查。
- 标准：可逆的多步骤或跨职责工作；根据 `standard_work_plan` 决定是否持久化 Todo，完成后运行受影响的最小充分检查。普通页面、路由或交互变化不因“用户可见”自动升级。
- 里程碑：初始化器/项目创建契约、项目类型能力、品牌或身份派生、安全/权限、已承诺的兼容性或对外契约、不可逆数据、生产副作用、最终候选或发布；必须维护 Todo，全部完成后再验收精确 Release 产物。使用 `$instantiate-project` 创建一个新下游时遵循该 Skill 自带的完整创建门禁，不为相同事务另造通用 Work Plan。

用户可以要求更严格路径。安全、扩展权限、身份迁移、外部上传、商店发布、不可逆操作或已承诺的兼容性/对外契约变化不得为了缩短流程而降级。

日常开发按变更风险选择检查：先运行受影响的格式、lint、类型与非空测试；配置、项目结构、跨切面、构建链或 Release 行为变化再增加对应环境、Harness 与构建检查。里程碑、发布候选、用户明确要求，或窄检查不足以建立可信度时运行完整 package 门禁。纯文档/元数据任务使用相称的格式、链接、解析或静态差异检查。

## 并行协作边界

- 创建并行写入单元前明确每个 Agent 的文件所有权和责任，不允许两个写入者同时修改同一文件。只读审计不要求为了使用多个 Agent 创建 Worktree。
- 所有写入者共享工作区事实时，不得撤销其他 Agent 或用户的修改；遇到重叠先协调。
- 并行只优化独立工作，不改变一个下游只能有单一 `projectType` 的产品边界。
- 主 Agent 在交付前必须等待必需结果、整合冲突并执行相称的整体检查；子任务局部通过不等于候选通过。

## 冒烟与 E2E

- 只有策略判断或硬要求选中浏览器步骤时才探测 Chrome；未选中时记录 `not-required/not-probed`，不把 Chrome 缺失当作静态、单测或构建任务的阻断项。
- 选中 Web 冒烟时，只验证 `pnpm build` 的最终输出，不用 Vite 开发页代替；选中 Extension 冒烟时，从精确 Chrome MV3 候选加载，只覆盖项目真实需要的入口。
- 冒烟/E2E 只接受通过 `pnpm env:validate` 并由逻辑 Release（`.env.production`）生成的精确候选；捕获的 console 必须符合 [`LOGGING.md`](LOGGING.md)，不能带入开发/测试 BaseURL 或敏感数据。
- E2E 需要登录、真实账号、生产数据、付费、商店上传、凭据或不可逆副作用时，必须获得该操作的独立明确授权。
- 任一必需检查失败、超时、取消或未执行时，不得宣布里程碑或发布就绪；应修复后重跑受影响的完整闭环。

## 执行优先级

1. 系统安全规则、批准的产品范围与渠道硬要求。
2. 当前任务中用户明确给出的更严格约束。
3. 本文件持久策略。
4. Agent 根据风险、存在时的当前唯一 `projectType` 和真实候选作出的适用性判断。
5. 仍无法可靠判断时请求用户决定。

本文件不授权发布、push、商店提交、凭据操作、生产访问或数据删除；这些行为始终需要其自身的任务授权。
