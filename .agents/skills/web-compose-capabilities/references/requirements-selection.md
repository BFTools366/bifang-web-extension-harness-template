# 从需求流程选择独立能力

本合同归 `$web-compose-capabilities`；调用方传入已分析的流程、原文依据、唯一宿主、阶段、角色与数据范围。本 Skill 选择领域能力及适用资源，不负责完整文档语义分析、PRD 确认、实际 UI 设计或代码装配。

## 按操作判断

| 能力                | 采用依据与边界                                                                                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 身份认证 `identity` | 明确需要登录、登出、会话恢复或受保护用户数据时选择所需操作；注册、找回与第三方登录分别判定。已有可信身份直接复用，不强制生成登录页。                                         |
| 权限 `permissions`  | 明确存在不同角色、动作限制、资源作用域或撤权时选择；管理员名称不能推导权限码、角色写入或服务端授权方案。身份来源和权限获取按真实契约明确归属，访问控制叶子只消费既有上下文。 |
| 组织 `organization` | 明确存在组织/团队隔离、成员管理或组织切换时选择对应操作；组织创建、邀请、成员写入与切换独立判定。只需要登录不自动启用组织与权限。                                            |
| 其他能力            | 商品 `catalog`、订单 `orders`、钱包支付 `wallet-payments`、审计 `audit` 按具体读取、写入或恢复操作独立选择；未被模板覆盖的需求返回调用方，不为匹配模板新增模块。             |

不按“账户”“团队”“后台”或“SaaS”等关键词打包选取功能。组织与权限可复用已有身份，查看订单不默认带商品、钱包或支付。模块无全局强制依赖，显式组合只有所需操作全部命中时才参考。

## 阶段与输出

- 创建前 `creation-analysis`：只读返回模块、操作、原文依据、状态、角色/数据范围、宿主、可用资源与契约缺口；不取代码模板、不调用组装器、不写入工程、不授予权限，完成后返回需求分析调用方。阶段是调用上下文，不是新增配置。
- 下游需求/设计：复用唯一 PRD 和已确认范围，只读所选知识；设计确需参考时读取相应设计资源。不重新收齐文档或改变已选范围。
- 下游实施：返回当前操作适用的 code/design/demo 模板与适配约束，由 `$web-implement-change` 负责装配、真实代码和验证；本 Skill 不独立启动开发、HTTP 接入或发布。

每项结果给出明确要求 / 建议 / 待确认 / 不需要状态。没有需求依据的能力保持未选；原文没有说明但会扩大范围的选项标待确认，不静默启用。可信身份、权限获取、管理目标、组织作用域与缓存所有者分别记录，不能相互代替。

真实 API、GraphQL 列表 Schema、凭据保存、并发和写入恢复缺口照实保留。浏览器权限与业务权限分开，未知结果先查询而不重放订单/支付；能力建议和模板不授权真实资金、生产访问或权限扩张。详细不变量读取所选模块知识，不在本表重新定义。
