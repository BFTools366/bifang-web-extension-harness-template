## 组织用户与细权限管理

先确认 Account、Organization、OrganizationUser 的独立标识；组织 ID 负责租户数据边界，成员 ID 负责成员授权、私有范围和审计。完整用户方案保留一个自有组织，任何已选注册成功都须原子创建账号、自有组织和 owner 成员；接受邀请只增加目标成员，不替代自有组织，查询和切换本身不创建组织。当前代码资源与完整目标的差异见接线合同，不能以缺少自动生成缩减已确认需求。

显式选择 organization.manage，复用当前可信成员和权限，对菜单、直达、页面、提交和 API 同时核对对应读取与动作权限 code，不按 owner/member 名称授权；系统角色与拥有者的保护由服务对象规则执行。表单改名只刷新同 scope 的共享组织 Query，失败留草稿，迟到结果失去界面权利。organization.switch 独立提供多组织弹窗、同目标 no-op 与账号级恢复页，管理页没有恢复豁免。最小实现与回归见[固定设计](design.md)。
