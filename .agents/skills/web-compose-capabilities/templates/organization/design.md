# 组织切换与权限管理固定设计

组织导航子项只随已选操作存在：完整协作预设提供组织设置、成员管理和角色管理，本人邀请在切换组织弹窗处理；明确收敛为账号核心且未选管理或协作时，不显示整个组织管理分组，不补回已取消的入口。账号、自有组织、有效成员及个人设置仍保留。

完整用户方案包括 Account、一个自有 Organization 与各组织的 OrganizationUser。当前组织来自可信成员上下文；organizationId 是租户数据边界，组织用户 ID 是授权主体、成员私有资源归属与审计操作者。注册原子创建自有组织与 owner 成员，接受邀请只增加目标组织成员，生命周期见[组织知识库](../../knowledge/organization.md)。查询和切换不创建组织。

## 已确认目标

- Web 侧栏组织管理下设组织设置、成员管理、角色管理，分别按 settings.read、members.read、roles.read 显示；无可见子项时隐藏父分组。Extension 使用自己的紧凑导航。
- 切换弹窗使用同一组织列表并标记当前项，当前项禁用；未接受或失效邀请不可切换。只有一个成员组织时保留切换入口及禁用的当前候选，本人邀请在弹窗内，账号级恢复 URL 保留。
- 账号菜单“切换组织”弹窗承载全部已加入组织及本人收到的邀请；当前项禁用，接受邀请保留自有组织和当前选择，随后显式切换。
- 注册以同一流程建立账号、自有组织和 owner 成员；组织名可使用基于显示名称的可编辑默认值，不能把只建账号当作成功。

## 当前模板资产

- organization.switch：账号菜单直接以“切换组织”动作作为入口，打开 Modal；当前项禁用，相同目标服务层 no-op。/organization 保留为账号级恢复页，即使业务权限已撤销也能返回有效组织。
- organization.manage：独立选择才有侧栏子菜单和 /organization/settings 页面，只检查管理页面/动作权限 code 与非阻断状态；无权限时菜单隐藏，直达与 API 均拒绝，不按 owner/member 名称授权。独立操作不附带邀请、角色、转移或删除；完整 identity.workspace 另接邀请和角色。
- 名称编辑：trim 后 1–60 字、防重复提交、失败保留草稿、成功精确刷新共享上下文；账号或 revision 变化后迟到结果不提示、不导航、不刷新新 scope。

OrganizationContext 为顶部、菜单、弹窗、恢复和管理页提供同一 Query，侧栏只保留导航。scope 与语言进入 key，名称不进入另一份存储。切换期间保留外壳和账号触发器，撤下私有正文与旧弹窗；服务端写入无论成功或响应未知都权威重读并刷新目标权限，无法确认时失败关闭。只读本地资源选择的回滚不能套到服务端转换。

Web 管理页采用 organization_.settings.tsx，独立于没有 Outlet 的 /organization 叶页；Extension 在应用父路由下直接接线。设置从侧栏底部或宿主独立入口进入可返回的全屏页，语言/主题不进入账号菜单。

代码由[应用装配器](../application/files.ts)按已选操作返回，输入、现状及已有服务适配要求见[接线合同](../application/wiring.md)。验证多组织/单组织、邀请接受前后、自有组织保留、同组织授权共享与跨组织拒绝、同目标零副作用、同权限不同角色可访问、无权限直达与 API 拒绝、撤权恢复、未知结果及迟到隔离；现有按成员分区的 Mock 不证明组织共享数据隔离或真实服务授权。

三页及动作的 11 码、读取依赖、角色对象保护和恢复合同见 [Auth 标准](../../../../../docs/ACCOUNT_OWNERSHIP.md#前后端标准交互与权限表)。

账号菜单、弹窗和列表的固定外观以 [Mantine UI 标准](../../../../../docs/MANTINE_UI_GUIDELINES.md) 为准：Header 不放组织卡片，单一显示名称，菜单统一无图标；切换组织、个人设置、修改密码使用弹窗，列表复用 ListSurface/ListTable/ListFooter。详细状态归属仍遵循数据规范。
