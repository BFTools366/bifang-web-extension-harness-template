# 应用主界面固定设计

主界面复用品牌、持续导航、顶部账号区、路由正文和构建版本。采用账号与组织的 Web 工作区默认保留可收起侧栏，只有工作台一个页面时也保留；侧栏仅工作台与最下方设置，不放账号资料、组织卡片、组织管理或成员入口。额外产品导航须有单独确认的需求。独立落地页不制造工作区；Extension 使用所在 Popup/Options 的紧凑导航，不照搬 Web 侧栏。Web 使用既有文件路由，Extension 使用 Popup memory / Options hash 代码路由。

本设计记录已确认的账号与组织基线。当前代码资产尚未覆盖全部目标，差异以[接线合同](wiring.md#当前装配器与目标规范的差异)为准，不因设计确认声明生成器已实现。

首页正文由已确认需求实现并以 HomePage 提供；装配器拒绝缺失正文，不生成欢迎页、计数器或默认占位功能。每个页面拥有实际 URL 和本地化标题，语言/主题沿用当前工程。

完整用户方案的右上账号触发器固定为头像、昵称和展开指示；头像缺失用姓名首字，长姓名保留可访问全名。展开顺序固定为：

1. 账号摘要与“账号信息”：打开全局个人资料页面；切换组织不改变账号资料，不在左侧重复入口。
2. 当前组织名称与当前成员角色，作为只读上下文；顶部可同步显示组织与当前页。
3. “切换组织”：有效且已加入的组织数大于 1 时打开选择弹窗；自有与加入组织分组或以文字区分，当前项禁用，同目标 no-op。
4. “组织管理”：当前有效成员具备服务要求的管理权限 code 时显示，不依据角色名称或 ownerAccountId；直达、页面、提交及 API 同样校验。组织资料、成员/邀请和角色权限在该页面内组织，受保护目标由服务给出对象状态。
5. “加入组织”：展示发给当前账号的有效邀请，可标注待接受数量；接受后保留原组织，显式切换进入新组织。单组织时仍可加入其他组织。
6. 分隔线及危险色“退出登录”。

语言和主题只在可返回的全屏公开设置页，Web 入口位于侧栏最下方；Extension 使用独立设置导航。缺少资料或邀请的实际页面/API 时，实施入口报告未完成项，不能用空菜单或当前注入槽宣称完整用户系统已交付；也不能从示意文案生成服务契约。

组织名称、成员角色、切换弹窗和组织管理共用唯一可信 Query，不能在组件或 Storage 复制档案；组织上下文不注入侧栏。布局保留唯一 `content` 正文与右上账号触发器，现有 `context(compact)` 兼容槽位只挂在顶部，侧栏不展示组织卡片。切换期间保留外壳，撤下旧组织正文、草稿、菜单和业务弹层；账号入口仍可用于退出或必要恢复。只有新组织、成员和权限全部确认后才放行业务；超时或结果未知显示组织待确认，禁止混用旧数据/权限。迟到回调不能干扰新上下文。

语言与外观统一进入脱离私有外壳的全屏公开 `/settings`，不触发身份恢复、组织读取或权限门禁；提供返回入口；设置导航与账号菜单分开。认证页底部只保留一个低强调文字设置链接，不使用齿轮按钮，字段保留可见标签并提供本地化 placeholder。更改即时生效；返回只接受已声明页面及安全业务目标，并按 Router 的 pathname、defaultParseSearch(search)、hash 分别导航；不得将完整 URL 放进 to 或用 Object.fromEntries(searchParams) 改写数值/JSON 形态字符串，来源随历史项传递，表单凭据不进入 URL 或存储，离开表单后清空。直接设置页按已选身份能力返回登录或首页。Web 文件路由与 Extension Popup memory / Options hash 各自拥有公开设置路由，不增加跨入口状态或权限。

登录页位于公开路由，完整用户方案在私有正文读取前完成账号、组织、成员与实际权限校验。采用注册时，默认只要求邮箱和密码；验证码按已选验证流程呈现，用户名和组织默认名由服务生成。服务原子创建账号、自有组织和 owner 成员；注册后自动登录与否按真实服务合同处理，不由原型直接进入演示决定。采用权限后，导航、路由、元素和动作消费统一权限要求。采用购买后，各能力页入口按已确认导航需求组合，不自动占据默认侧栏。

已选能力保持各自固定设计；原型将这些组件和真实首页内容组合成一个桌面交互流程，自查登记后实施，不重新发明登录、账号区或购买布局。

来源层级、可替换文案/页面和 Mock 数据边界见 [提取与定制](extraction.md)。品牌只消费当前项目身份，结构复用不固化来源业务正文。
