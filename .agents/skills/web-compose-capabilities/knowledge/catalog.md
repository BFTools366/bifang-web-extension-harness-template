# 商品与分类知识库

聚合分类树、商品浏览/维护、规格与权威报价。按实际操作选择只读目录或管理写入；不自动生成购买、订单、钱包、组织或权限页面。

本库复用已有分类/商品 SOP 与中性信息架构，不固定 endpoint、字段拼写、商品类型、币种、状态值或真实服务能力。

## 对象与不变量

| 对象       | 核对事实                                              | 不变量                                          |
| ---------- | ----------------------------------------------------- | ----------------------------------------------- |
| 分类       | 稳定 ID、父级、名称、顺序、状态、版本、引用、可见范围 | 无环、无重复 ID、无悬空父级；父级直属商品不丢失 |
| 商品       | 有效分类归属、规格、可售/发布状态、版本               | 分类与可售性由服务校验，不从 UI 推断            |
| 金额与报价 | 最小单位或精确十进制、币种/精度、报价 ID/版本/期限    | 不用浮点展示计算定价；报价由服务权威确认        |
| 历史关联   | 已采用订单时的商品/规格/金额快照                      | 当前改价/下架不覆盖历史订单或擅自撤销权益       |

多分类、最大深度、分页/懒加载、报价有效期、折扣/汇率和零金额处理均由服务确认。没有订单能力时历史关联标为不适用，不为其增加订单模块。

## 浏览与报价 SOP

1. 读取有效分类与服务端可见商品，给出加载、空、错误、无权限和恢复反馈。分类展开与选择分开，保留祖先路径和选中态。
2. 选择分类时明确查询直属还是含后代；已有中性建议为“所选分类及后代”，必须由真实合同确认。不能拼接不完整分页后声称全量，父分类有直属商品时不能丢失。
3. 商品选择显示真实名称、说明、可售状态及服务支持的规格/数量。若本次只做目录浏览，不默认增加数量、购物车或结算按钮。
4. 需要报价时冻结商品/规格/数量及作用域，读取权威金额/币种和期限。切分类/商品使无效选择与旧报价失效；迟到响应不能恢复旧选择。
5. 下架、分类删除、空分类、报价过期和服务拒绝分别反馈。只有组合支付流程时才读取实际服务提供的支付方式，不因目录模块存在而查询钱包。
6. 已提交订单属于订单生命周期，不能经目录搜索/筛选把它改回可编辑购买草稿。

## 分类维护 SOP（可选）

读取分类树/版本与引用 → 填写服务必需资料 → 移动时排除自身和全部后代、展示子树及商品影响 → 服务原子校验 → 成功后精确重取树与受影响归属/列表。

停用、归档、删除按真实允许动作分别呈现。引用未处理时按合同阻止或迁移，不默认级联删除、重挂后代、批量改商品分类；分类隐藏不等于取消订单。冲突保留输入并读取新版本，禁止转无条件覆盖。

## 商品维护 SOP（可选）

1. 新建/编辑核对稳定标识、有效分类、规格、准确金额/币种与可售规则，使用真实版本。
2. 有草稿状态时先保存草稿；没有时说明真实生命周期与保存后可见影响，不伪造未发布。
3. 发布前核对分类、规格、计价和服务校验。已组合钱包方式时才校验兼容币种；不存在该能力时不强绑钱包。
4. 改价/规格/分类影响后续报价，已有报价保留或失效由服务决定；已有订单快照不可覆盖。
5. 下架/停用只改变可售性。已有待支付单资格与既有权益由对应服务决定，不自行撤销、退款或强制重建。
6. 归档/删除核对引用和保留策略。未知创建/更新先按原关联恢复，不重复新建商品；成功但刷新失败保留保存结果，仅重试读取。

## 访问、状态与组合

公共目录是否匿名可读依服务；受限管理动作消费已有可信身份/权限，不要求另建认证或角色模块。Query key 含真实 target、身份/组织等实际 scope、语言与查询，不含 Token；目标/权限变化失效旧草稿与响应。

商品目录与订单通过不可变选择/报价及服务快照合同关联，不直接读写对方私有状态。管理操作所需服务审计独立于是否选择审计展示页面。

## 宿主与设计

Web 按真实信息结构采用分类折叠导航、卡片或列表，复用列表、Router/Query、Mantine 和 i18n。树样式不等于 ARIA tree，未实现其完整键盘模型时使用语义折叠导航。价格带币种，发布/下架/归档动作明确，错误关联字段，弹窗有焦点返回。

Extension 只在已选 Popup/Options 等 surface 实施适合的目录交互，不调用 Web 专属列表 Skill或文件路由，不复制完整 Web shell。Chrome MV3/Firefox MV2 的实际读取、消息与权限边界分别验证；不因目录增加 host permissions、后台入口或凭据持久化。

## GraphQL 列表强约定

分类树、商品、规格及候选集合按 [列表查询协议强约定](../../../../docs/DATA_ACCESS.md#列表查询协议强约定) 判断协议与契约缺口；本领域知识只补充对象语义，纯本地计算不构造远端服务。

## 验证

按本次操作覆盖：两层以上树的展开与选择、父级直属商品、非法树拒绝；分类/商品切换后迟到报价隔离；空态和不支持规格；精确金额/币种；分类移动环/引用；并发改价；历史快照不变；下架后待支付资格重新读取；未知提交与刷新失败恢复。

没有订单、支付、组织、权限或真实服务时对应部分明确不适用或未验证，不借中性演示宣称业务上线。

基础接线以 [固定设计](../templates/catalog/design.md) 和 [应用装配](../templates/application/wiring.md) 为准。catalog 只描述当前可执行资源的最小前置，不随模块名启用全部操作；完整用户信息遵循[账号与组织基线](identity.md#完整用户信息)，购买必须含基础身份。旧专项操作建议不覆盖该基础接线合同。
