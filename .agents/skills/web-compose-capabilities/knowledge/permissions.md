# 权限与角色知识库

按真实服务合同选择权限上下文消费、菜单/路由/动作访问控制、组织成员角色或平台角色管理。不因角色名、前端开关、模块选择或网络失败获得授权。

入口实施继续复用既有访问控制能力；本库补充权限来源、角色管理、作用域与撤权合同，不建立第二套会话或竞争判断框架。

## 能力与事实

| 操作               | 真实输入                                                | 行为                                   |
| ------------------ | ------------------------------------------------------- | -------------------------------------- |
| 当前权限消费       | 已确认身份、服务权限码、适用组织/对象、版本或有效上下文 | 未知/缺失/空权限默认无授权             |
| 入口与动作判断     | 每个菜单、路由、按钮和请求的 all/any 要求               | 同一判断覆盖可见性、直达和执行         |
| 角色查询/分配/撤销 | 目标主体、角色范围、可授予集合、版本与服务允许动作      | 平台角色与客户组织成员角色分离         |
| 撤权恢复           | 权限变化的可信结果、当前页面/动作/缓存                  | 立即阻断受限内容与新操作，再清理并恢复 |

通配符、超级管理员与 all/any 语义必须显式来自服务，不定义公共权限码。服务可提供已有身份和 scope，不要求为权限另建登录/组织模块。

## 访问控制 SOP

1. 列出实际受影响入口、操作、对象/组织范围及权限要求；显式区分公开入口。菜单与守卫消费一致的页面声明。
2. 未加载或不可解析时显示可理解的加载/恢复状态，不短暂放行。不要把持久化权限快照当成刷新后的授权依据。
3. 目标导航先满足真实凭据/上下文流程，再判断该目标权限，之后才运行受限 loader、API 或呈现正文。预取、隐藏按钮和 effect 后检查不能替代守卫。
4. 已识别但无权限的目标进入独立拒绝恢复状态，不伪装未知路径或静默回首页。恢复入口不依赖被拒绝的权限，保留退出及真实可访问目标，完全无权限时不循环跳转。
5. 动作执行前再次核对当前身份、scope、对象和权限；服务端逐请求继续鉴权。禁止通过浏览器直接调用绕过本地动作边界。
6. 当前页撤权、目标/身份/组织变化时先隐藏受限正文并阻止新操作，再停止读取/订阅，隔离缓存与回调，进入适当恢复。迟到成功和 401 不能覆盖新上下文。
7. 普通业务 403 保留会话，按真实合同有界重取权限；会话失效只交给唯一认证所有者处理。拒绝结果不能被网络容错转成新授权。

## 角色管理 SOP（可选）

读取操作者权限与可授予角色 → 明确目标是平台操作员还是某组织成员 → 展示当前/目标角色及影响 → 按允许范围提交真实版本/幂等关联 → 重读目标权限和角色 → 若本次影响自己，立即重判当前入口。

不得超出可授予范围、用成员移除代替全局账户禁用、靠前端保留最后有效管理员。最后管理员/唯一负责人和自我降权的保护由服务原子校验；前端只提前反馈。服务不支持角色写入时仅提供真实只读范围，不留下假成功表单。

未知提交保留原关联并先查询，不自动重放；冲突保留草稿并核对新版本。成功但刷新失败保留写入事实并仅恢复读取，不继续沿用已确认撤销的旧授权。

## 组织、审计与模块组合

组织角色管理只在真实成员/组织对象存在时消费其公共身份，不自动生成组织管理 UI。平台角色管理不启用客户组织切换或代登录。

管理写入要求服务端所需审计，不由前端随后补写一条日志冒充一致性。是否展示审计页面独立选择；业务写入的审计职责不能因未选审计 UI 消失。

## Web 与 Extension

Web 菜单、文件路由和动作复用现有 Router/Query；拒绝恢复 URL 与页面一致。Extension 仅在真实 surface 的路由中提供等价拒绝，不继承 Web 文件路由或自动新增入口。浏览器 permissions/host permissions 与服务端业务权限严格分开；服务端允许不证明浏览器 API 可用，浏览器允许也不授予业务权限。

跨 Popup/Options/background 的权限上下文只按已确认消息/会话架构分发，分别验证 Chrome MV3 与 Firefox MV2；不得把 Web 的 LocalStorage 例外用于 Extension 或持久保存权限副本。

## GraphQL 列表与契约

角色、操作员、成员权限候选等远端集合查询统一使用 GraphQL，覆盖无条件首载、筛选、搜索、排序、分页。权限详情或当前上下文的单对象读取与写入按其真实语义；不能换名字把列表伪装成详情。可信 Schema 缺失是契约缺口，已有 REST 列表如实标记不符合；本地权限集合判定无需构造远端查询。

## 验证矩阵

按实际操作建立最小差异矩阵：允许身份成功；拒绝身份菜单隐藏且直达/动作拒绝；加载失败无授权；登录返回不能绕过；拒绝恢复无循环；已挂载撤权正文消失；切 scope/迟到结果不恢复旧权限。角色写入时追加越权授予拒绝、最后管理员保护、自我降权和未知提交恢复。

分别断言入口隐藏与受限正文未挂载。Mock fixture 在真实域边界定义权限来源和生命周期，不按账号名字推导，不让所有演示身份全权限。规范或 Mock 通过不能证明服务端授权。
