# 钱包与支付知识库

按需选择钱包/流水只读、支付记录核查或对已有原单的钱包支付。仅选钱包查询不需要商品与订单 UI；仅选支付需有服务可恢复的原单身份，不要求使用本 Harness 的建单模板。

现有通用支付能力只适配服务端返回的钱包方式。充值、提现、转账、退款、调账、外部渠道、自动续费与手工余额修改均不因采用本库启用。

## 服务事实与边界

| 对象       | 必需事实                                            | 不变量                             |
| ---------- | --------------------------------------------------- | ---------------------------------- |
| 钱包       | 真实归属、资产/币种/精度、状态、可用/冻结余额语义   | 归属不能从当前 UI组织推断          |
| 流水       | 独立标识、时间、类型、准确金额、订单/尝试关联、分页 | 服务记录是权威，不由余额差额拼账本 |
| 支付方式   | 服务方式 ID、类型、钱包 ID、可用性及原因            | 空列表/不支持类型不能伪造可支付    |
| 原单与尝试 | 原订单、剩余应付、允许状态、尝试 ID、幂等与结果查询 | 服务扣款；客户端不直接减余额       |
| 一致性     | 状态/流水可见期限、失败与终止证明、刷新边界         | 一次未查到不证明未扣款             |

金额采用服务最小单位整数或精确十进制字符串，带币种/精度；不假设两位小数、不使用浮点求和定价。同币种/资产才按合同比较，汇率/费率由服务提供，零金额订单流程需服务确认。

## 钱包与记录只读 SOP

确认查询身份/管理目标和钱包归属 → 读取余额/状态 → 按服务支持的时间/收支类型等查询分页流水 → 查看真实关联订单/尝试 → 刷新与显示更新时间。

旧余额标记待更新，不作为扣款成功证据。流水索引延迟按服务一致性显示同步中，不补造记录。管理目标不改操作者身份；默认无余额编辑、充值、提现、强制支付成功、流水删除或代付。

## 原单钱包支付 SOP（可选）

1. 取得已存在的原单 ID并读取权威状态、归属、有效期、应付与允许动作；尚无订单时交给实际建单边界，不在支付页重复建单。
2. 读取服务当前可用方式，仅呈现已识别钱包；展示归属、币种、余额与冻结/不足等不可用原因。服务无钱包或无兼容方式时阻断支付，不自行补默认选项。
3. 用户确认原单、应付、钱包和作用域。冻结身份/scope revision、原单、方式及本次支付意图，再按真实幂等合同提交。
4. 处理中保持原订单可识别，禁重复提交但允许安全离开等待。关闭 UI、取消本地 Fetch 不表示服务已取消扣款。
5. 确认成功后显示已支付，禁止再次付款。失败是否可发起新尝试必须由服务证明原尝试终止、原单仍可付；不能只按客户端超时或错误提示判断。
6. 超时/丢响应进入结果未知，按原单/原尝试查询，不生成新 key、不自动 replay。轮询有界、可取消和退避；离页停止，之后从原单恢复。
7. 只有服务确认可付的未完成原单才可继续支付，复用原单历史快照并重读当前方式；不拿当前商品价格覆盖历史订单。

## 幂等与失败恢复

支付与建单各有独立幂等语义，明确作用域、保留期、同键不同输入与并发原子性。请求追踪、会话 revision和业务 key不是同一个概念。

未知查询仍未确认时保留原意图阻断重付；查询未找到、key过期或副本延迟不能证明未扣款。钱包不足/冻结、币种不符、报价失效、原单不可付、权限拒绝与无响应网络错误分别反馈。普通业务 403保留会话，认证失效交唯一 owner；网络容错不能授权离线支付。

保存成功但读取刷新失败与实际扣款失败分别表达，不能因刷新错误重新付款。

## 成功后的精确刷新

服务确认支付成功后刷新原订单及其列表、实际钱包/流水和已选的当前账号数据；仅商品确实影响权益/额度/权限且有服务合同才追加对应读取，不强制安装其他模块。

收集原 scope 内各读取结果：部分失败显示“已支付，相关数据待更新”，只重试读取，保留成功事实。当前身份/组织/目标已变化时不能把旧账户结果写入新 scope；保留原单的可恢复查询。不得清空整个 QueryClient、乐观扣余额或凭空加权益。

## 宿主、权限与组合

消费已有可信身份/scope及真实服务授权，不从功能选择或角色名推导资金权限。只读管理查询与付费动作分别选择；服务管理写入的审计要求独立于审计 UI。

Web复用 Router/Query、数据层和 i18n，金额带币种、状态播报与弹窗焦点恢复符合项目 UI。Extension按真实 surface 与消息所有者实施；Popup关闭不代表服务终止，Chrome MV3/Firefox MV2的背景生命周期、权限拒绝分别验证。不得因支付默认新增后台入口、宽泛 host permissions、凭据持久化或把 Web LocalStorage例外移植过来。

## GraphQL 列表强约定

钱包、支付方式、流水及支付记录集合按 [列表查询协议强约定](../../../../docs/DATA_ACCESS.md#列表查询协议强约定) 判断协议与契约缺口；本领域知识只补充对象语义，纯本地计算不构造远端服务。

## 验证与资金授权

覆盖本次已选的只读归属/币种/流水；付费时覆盖无支持方式、余额不足/冻结/币种不符、双击/跨页并发、未知后实际成功、原尝试未终止阻断重付、原单恢复、切scope/退出迟到、成功但账号/流水刷新失败。

离线演示可使用明确示例单位，不能证明真实金额、服务账本或扣款。真实资金/生产操作必须有当次明确环境和授权；知识分发、模板填写、Mock或普通测试不自动授予。

基础接线以 [固定设计](../templates/wallet-payments/design.md) 和 [应用装配](../templates/application/wiring.md) 为准。catalog 只描述当前可执行资源的最小前置，不随模块名启用全部操作；完整用户信息遵循[账号与组织基线](identity.md#完整用户信息)，购买必须含基础身份。旧专项操作建议不覆盖该基础接线合同。
