# 组织与成员知识库

按实际需要选择组织查询/维护、账户成员关系、邀请、负责人交接或当前组织切换。组织管理与会话组织切换是不同操作；选择组织不自动生成身份认证页面、平台角色、订单或钱包。

本库描述已有通用 SOP 与不变量，不声明真实 endpoint、权限码、状态值或完整服务能力。

## 账号、组织与组织用户

- Account 是全局登录账号；Organization 是独立租户；OrganizationUser 是有独立 ID 的成员身份，关联 accountId 与 organizationId。同一账号在不同组织有不同组织用户，同一账号和组织的有效关系唯一。
- 已选“注册 + 组织生命周期”时，服务原子创建 Account、个人 Organization 和 owner OrganizationUser。每个账号保留自己的个人组织，即使没有业务数据、没有邀请过人或加入了别人组织。身份独立能力不凭空增加组织注册接口。
- 接受邀请只增加目标组织的成员身份，不迁移账号、不覆盖个人组织，也不复制业务资源或权限。邀请、成员维护、角色分配和负责人交接仍是独立操作；没有可信合同不生成 endpoint。
- 权限、业务数据归属、排行统计和审计操作者使用当前 OrganizationUser.id。组织与排行榜等业务资源分别建模，不能以资源 ID 冒充组织 ID；切组织后只读取目标组织范围的数据。
- scope 只保存必要标识和代次；名称、成员角色及可信权限由各自 API/共享 Query 提供，不能在侧栏、菜单或 Storage 镜像档案。角色用于运行时校验时必须来自已确认成员关系。

## 对象与操作

| 对象/操作    | 必需事实                                              | 边界                                   |
| ------------ | ----------------------------------------------------- | -------------------------------------- |
| 组织         | 稳定标识、名称、状态、负责人、版本、服务允许动作      | 停用不隐含删除数据、退款或冻结钱包     |
| 账户         | 全局账号状态与可查询字段                              | 与组织成员关系分开                     |
| 成员/邀请    | 目标组织、账户、角色、成员状态、邀请状态、可授予范围  | 邀请不是已加入；移除成员不全局禁用账号 |
| 负责人交接   | 新负责人资格、原子交接及唯一负责人保护                | 不能先移除唯一负责人再补建             |
| 当前组织切换 | 当前身份的可用成员组织、服务端 scope 转换、上下文恢复 | 不把组织 ID 本地赋值当成切换成功       |

组织详情的订单、钱包或审计标签仅在已选能力且服务/权限支持时关联，可独立省略。平台跨组织管理的目标与操作者 scope 分开，不调用切组织接口或写入客户凭据冒充目标。当前组织拥有者管理则明确限定当前组织，不混用这两种授权。

## 查询与维护 SOP

1. 用服务支持的名称、标识、状态筛选组织，进入详情始终标明目标组织。不同目标的草稿、缓存和迟到响应隔离。
2. 新建/编辑只提交确认的必需资料、允许状态与实体版本；服务没有版本/并发合同则明确缺口，不用更新时间或 JWT 版本代替实体版本。
3. 添加已有用户、发送邀请、修改角色、移除成员分别表达，核对组织、账户、成员状态和可授予范围。
4. 交接负责人由服务原子检查新负责人有效、操作者有权、交接完成后仍有负责人；并发冲突保留输入、重读并由用户核对。
5. 停用组织、账户或成员前展示真实影响和必要原因。明确登录、订单、钱包、成员访问分别受到什么影响；没有合同就不臆断级联状态。
6. 成功精确刷新目标详情、受影响成员/组织列表与实际关联上下文；刷新失败保留已确认写入结果，只重试读取。未知提交先查询原请求，不自动重放或改成无条件覆盖。

账户独立管理确有需求时再形成其完整范围，不为存在“用户与成员”页面默认增加全局账户管理。

## 当前组织切换 SOP（可选）

当前组织的名称与状态同时用于账号菜单和侧栏上下文，选择页消费同一 Query 缓存；不在菜单、组件局部状态或持久存储各保存一份组织档案。未选择、加载、切换、失败与已接受明确区分，不能在新语言或新 scope 的详情待加载时误报“未选择”。侧栏收起后保留带可访问名称的入口，组织选择恢复入口依赖有效账号与成员关系，不依赖被撤销的组织业务权限；管理入口没有这一豁免。固定壳、菜单与偏好结构见 [主界面设计](../templates/application/design.md)。

服务端会话切换与只读验证后的客户端资源选择具有不同失败语义。前者沿下述权威恢复流程处理未知结果；后者只有在证据确认没有服务写入时才可保留之前选择。组织与排行榜等领域对象分别建模；只有客户端本地选择时，失败回到最后完整接受的上下文，不能回到正在校验的中间值。并发 A→B 未完成、C 失败时仍以 A 为恢复点，迟到 B 无权覆盖后续选择。

1. 由现有可信身份上下文读取可用成员组织；去重后可用数大于 1 才提供切换入口。查询与切换不创建组织；注册默认组织由上文的已选生命周期负责。只剩一个组织时下拉入口隐藏，但保留账号级恢复路由，使撤权用户仍能返回有效组织。
2. 弹窗保留当前项并禁用，或明确排除当前；服务收到相同目标立即 no-op，不请求、不重读权限、不清缓存、不增加 revision。无效或失去成员资格的项不可选。组织读取有加载、错误、空结果反馈；未提交时关闭保留当前 scope。
3. 提交前冻结当前身份/revision 和目标，阻止旧组织的新业务操作。服务重新验证成员资格并返回新的组织上下文及适用凭据。
4. 唯一会话所有者接收已确认转换，失效旧请求/订阅/私有缓存和组织草稿；按实际依赖重取用户、组织及已选权限。未就绪前不能组合“新组织 + 旧权限”。
5. 重新判定当前页面访问资格；可访问则恢复，不可访问则先撤下受限正文/阻断动作，进入真实拒绝恢复入口。旧响应不能写入新 scope。
6. 明确拒绝且服务确认原会话未变时保留原 scope。超时/响应丢失或新上下文读取失败时先恢复权威上下文，不直接回滚旧组织继续请求。
7. 切换为会话变化时同 key 多标签页/上下文按既有协调者收敛。取消本地等待不代表服务取消转换；原导航取消不得遗留无人完成的已接受 scope 恢复。

管理组织对象不需要这套切换 UI。组织功能可以消费外部已存在的身份/作用域，不要求安装第二个认证协调者。

## 当前组织拥有者管理（独立可选）

显式选择 organization.manage 才生成账号菜单与管理页；organization.switch 不自动启用管理。当前组织用户为 owner，组织 ownerAccountId 与登录账号一致，同时满足可信管理权限且 scope 未阻断时才显示入口。菜单可见性、直达路由、已挂载页面、提交前与 API 边界统一复核，member 即使持有普通页面权限也不能改名。

改名只提交当前组织和经过 trim 的 1–60 字名称；防重复提交，失败保留草稿。成功刷新同 scope 的共享组织上下文，侧栏、切换弹窗和管理页同步名称；不要为改名重建登录或切换组织。写入已成功而刷新失败时保留成功事实并恢复读取；超时未知按真实版本/幂等合同查询，不自动覆盖他人的新名称。账号、组织或 revision 变化后，迟到提示、导航和刷新不能影响新 scope。

Web 的 /organization 与 /organization/manage 是独立叶页；父页没有 Outlet 时，管理页文件采用 organization_.manage.tsx，不能错误嵌套导致只有父页渲染。Extension 直接在应用父路由下接线同级页面。拥有者改名不附带删除、转移或角色管理。

## 权限、宿主与状态

组织列表、详情、成员和写动作分别服从真实对象/范围授权。平台角色、组织成员角色与操作者身份不同，不从“管理员”名称推导全部权限。已选择权限能力时复用其判断与撤权，业务 403 不作为统一注销。

Web 按实际 Router/Query、列表与 i18n 合同工作。Extension 使用所在 Popup/Options 的导航与消息边界，不调用 Web 文件路由或列表 Skill；真实需要跨上下文协调时确认唯一 owner、Chrome MV3/Firefox MV2 生命周期与权限拒绝，不默认加入 background 或扩大权限。组织模块本身不授权凭据持久化。

Query key 含实际影响结果的目标、身份/scope、语言和查询参数，不含 Token。退出、目标或权限变化使旧响应、回调和草稿失效；后端始终校验对象级范围。

## GraphQL 列表与服务合同

组织、账户、成员、邀请及角色候选等远端集合统一走 GraphQL，包含无条件首载、筛选、搜索、排序和分页。没有可信列表 Schema 是缺口，不能因已有 REST 合同绕过；纯本地候选过滤不假造远端接口。详情与写操作依据真实契约，不从 BaseURL、页面名或参考字段猜 endpoint。

## 验证与交付

本次已选操作覆盖：管理目标不改变登录身份；跨组织对象拒绝；成员移除不影响其他组织；账户/成员状态分离；唯一负责人保护；版本冲突、超时实际成功、刷新失败保留结果；退出/切目标后迟到结果隔离。

采用切换时追加多组织弹窗、单组织隐藏、相同目标 no-op、撤权恢复与管理无豁免、拒绝/未知恢复、新组织上下文就绪前阻断、旧权限隔离、原导航取消与多上下文竞争。组织无订单/钱包依赖时明确不适用，不为补齐矩阵启用功能。区分通用规范、Mock、真实服务和最终候选证据。
