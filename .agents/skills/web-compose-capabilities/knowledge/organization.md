# 组织与成员知识库

组织导航子项只随已选操作存在：完整协作预设提供组织设置、成员管理和角色管理，本人邀请在切换组织弹窗处理；明确收敛为账号核心且未选管理或协作时，不显示整个组织管理分组，不补回已取消的入口。账号、自有组织、有效成员及个人设置仍保留。

按实际需要选择组织查询/维护、账户成员关系、邀请、负责人交接或当前组织切换。组织管理与会话组织切换是不同操作；选择组织不自动生成身份认证页面、平台角色、订单或钱包。

本库描述已有通用 SOP 与不变量，不声明真实 endpoint、权限码、状态值或完整服务能力。

## Go 服务基准

[固定 Go 上游](../../../../docs/GO_CLIENT_CONTRACT.md) 仅提供默认 Org；本地 install-users 的组织 overlay 提供八表 RBAC、成员、邀请、角色权限、切换和改名。完整协作使用 identity.workspace 与 Go 账号装配入口，数据归属以 [ACCOUNT_OWNERSHIP.md](../../../../docs/ACCOUNT_OWNERSHIP.md) 为唯一来源；profile 的自有组织仍不能替代当前 teamContext。已有外部服务不自动具备本地扩展。

## 账号、组织与组织用户

- Account 是全局登录账号；Organization 是独立租户；OrganizationUser 是有独立 ID 的成员身份，关联 accountId 与 organizationId。同一账号在不同组织有不同组织用户，同一账号和组织的有效关系唯一。
- 注册成功必须由服务原子创建 Account、一个自有 Organization 和 owner OrganizationUser；三者全部成功才可报告账号开通，失败不能留下只建账号或只建组织的半成品。每个账号保留这一个自有组织，即使没有业务数据、没有邀请过人或加入了别人组织；不因邀请、切换或退出其他组织而丢失。完整用户方案不提供“只有账号、没有组织”的成功分支，缺失事实进入服务恢复，前端不补造组织。额外创建组织、删除或负责人转移不属于本次基线。
- 接受邀请只增加目标组织的成员身份，不迁移账号、不覆盖个人组织，也不复制业务资源或权限。邀请、成员维护、角色分配和负责人交接仍是独立操作；没有可信合同不生成 endpoint。
- `organizationId` 是组织数据的租户边界，同组织共享内容归属该组织；`OrganizationUser.id` 是成员授权主体、成员私有内容归属及审计操作者，不可作为全部组织共享数据的分区键。需要成员统计时同时保留组织与成员标识，不能将组织、排行等业务资源或全局账号 ID 相互替代。钱包、订单等资源的组织共享/成员私有范围按真实领域合同判定，不因改知识库自动迁移现有数据。
- scope 保留 `accountId`、`organizationId`、`organizationUserId` 及代次等必要标识；名称、成员角色及可信权限由各自 API/共享 Query 提供，不在顶部、菜单或 Storage 镜像档案。服务端逐次校验账号、有效成员与对象的组织归属，前端隐藏、缓存键或本地赋值不能证明隔离。切组织后只读取目标组织范围的数据，旧请求、草稿和迟到回调失去新 scope 写入权。

完整用户信息是账号与当前组织、当前组织成员的组合；当前组织可以是自有组织，也可以是已经接受邀请且成员资格有效的他人组织。完整用户方案必须保留返回自有组织及已选协作范围内的加入其他组织入口；待接受邀请不是可访问成员资格。

## 邀请与加入组织

1. 有当前组织管理权限 code 的有效成员通过组织管理的成员管理页进入成员列表；发送邀请前复核有效成员、所需动作权限及 scope，不按角色名或 ownerAccountId 授权。只为当前组织创建面向指定账号的邀请，不授予全局账号管理能力。
2. 邀请展示目标组织、邀请者、受邀账号和加入后的角色，分别表达待接受、已接受、失效或被拒绝等真实服务状态。邀请码、有效期、角色和错误恢复必须来自可信合同，不从原型编造 endpoint。
3. 受邀者在左侧组织管理分组的切换组织弹窗查看并确认发给自己的有效邀请；服务绑定账号和目标组织，接受成功才原子新增唯一成员关系，不继承拥有者身份或复制旧组织的权限、资源。
4. 接受后精确刷新成员组织与邀请列表，保留自有组织和当前工作组织，再由用户显式切换进入新组织。只有一个成员组织时仍保留加入入口；邀请未接受时不能直接切换。
5. 重复邀请、重复接受、邀请失效、成员撤销及未知写结果按服务合同处理；未知结果先查询，不自动重发或把待接受显示为已加入。被移出一个组织不注销全局账号，也不影响其自有组织及其他有效成员关系。

## 对象与操作

| 对象/操作    | 必需事实                                              | 边界                                   |
| ------------ | ----------------------------------------------------- | -------------------------------------- |
| 组织         | 稳定标识、名称、状态、负责人、版本、服务允许动作      | 停用不隐含删除数据、退款或冻结钱包     |
| 账户         | 全局账号状态与可查询字段                              | 与组织成员关系分开                     |
| 成员/邀请    | 目标组织、账户、角色、成员状态、邀请状态、可授予范围  | 邀请不是已加入；移除成员不全局禁用账号 |
| 负责人交接   | 新负责人资格、原子交接及唯一负责人保护                | 不能先移除唯一负责人再补建             |
| 当前组织切换 | 当前身份的可用成员组织、服务端 scope 转换、上下文恢复 | 不把组织 ID 本地赋值当成切换成功       |

组织详情的订单、钱包或审计标签仅在已选能力且服务/权限支持时关联，可独立省略。平台跨组织管理的目标与操作者 scope 分开，不调用切组织接口或写入客户凭据冒充目标。当前组织管理明确限定当前组织，不混用这两种授权。

## 查询与维护 SOP

1. 用服务支持的名称、标识、状态筛选组织，进入详情始终标明目标组织。不同目标的草稿、缓存和迟到响应隔离。
2. 新建/编辑只提交确认的必需资料、允许状态与实体版本；服务没有版本/并发合同则明确缺口，不用更新时间或 JWT 版本代替实体版本。
3. 添加已有用户、发送邀请、修改角色、移除成员分别表达，核对组织、账户、成员状态和可授予范围。
4. 交接负责人由服务原子检查新负责人有效、操作者有权、交接完成后仍有负责人；并发冲突保留输入、重读并由用户核对。
5. 停用组织、账户或成员前展示真实影响和必要原因。明确登录、订单、钱包、成员访问分别受到什么影响；没有合同就不臆断级联状态。
6. 成功精确刷新目标详情、受影响成员/组织列表与实际关联上下文；刷新失败保留已确认写入结果，只重试读取。未知提交先查询原请求，不自动重放或改成无条件覆盖。

账户独立管理确有需求时再形成其完整范围，不为存在“用户与成员”页面默认增加全局账户管理。

## 当前组织切换 SOP（可选）

当前组织的名称与状态用于顶部上下文、切换组织弹窗，消费同一 Query 缓存；Web 侧栏不放组织卡片，组织设置、成员管理和角色管理在组织管理分组。不在菜单、组件局部状态或持久存储各保存一份组织档案。未选择、加载、切换、失败与已接受明确区分，不能在新语言或新 scope 的详情待加载时误报“未选择”；切换结果未知时显示组织待确认并阻断业务，不沿用旧组织角色或管理菜单。侧栏收起后右上账号入口仍有可访问名称；组织选择恢复入口依赖有效账号与成员关系，不依赖被撤销的组织业务权限，管理入口没有这一豁免。固定壳、菜单与偏好结构见[主界面设计](../templates/application/design.md)。

服务端会话切换与只读验证后的客户端资源选择具有不同失败语义。前者沿下述权威恢复流程处理未知结果；后者只有在证据确认没有服务写入时才可保留之前选择。组织与排行榜等领域对象分别建模；只有客户端本地选择时，失败回到最后完整接受的上下文，不能回到正在校验的中间值。并发 A→B 未完成、C 失败时仍以 A 为恢复点，迟到 B 无权覆盖后续选择。

1. 由现有可信身份上下文读取已加入且有效的成员组织；账号菜单的“切换组织”动作作为入口，待接受或失效邀请不计入。查询与切换不创建组织；注册自有组织由上文的原子注册合同负责。只有一个组织时仍保留切换组织入口及禁用的当前候选，本人邀请在切换弹窗内，账号级恢复路由保留，使撤权用户仍能返回有效组织。
2. 弹窗展示全部已加入且有效的组织，保留当前项并禁用；服务收到相同目标立即 no-op，不请求、不重读权限、不清缓存、不增加 revision。无效或失去成员资格的项不可选。组织读取有加载、错误、空结果反馈；未提交时关闭保留当前 scope。
3. 提交前冻结当前身份/revision 和目标，阻止旧组织的新业务操作。服务重新验证成员资格并返回新的组织上下文及适用凭据。
4. 唯一会话所有者接收已确认转换，失效旧请求/订阅/私有缓存和组织草稿；按实际依赖重取用户、组织及已选权限。未就绪前不能组合“新组织 + 旧权限”。
5. 重新判定当前页面访问资格；可访问则恢复，不可访问则先撤下受限正文/阻断动作，进入真实拒绝恢复入口。旧响应不能写入新 scope。
6. 明确拒绝且服务确认原会话未变时保留原 scope。超时/响应丢失或新上下文读取失败时先恢复权威上下文，不直接回滚旧组织继续请求。
7. 切换为会话变化时同 key 多标签页/上下文按既有协调者收敛。取消本地等待不代表服务取消转换；原导航取消不得遗留无人完成的已接受 scope 恢复。

管理组织对象不需要这套切换 UI。组织功能可以消费外部已存在的身份/作用域，不要求安装第二个认证协调者。

## 当前组织管理（独立可选）

organization.manage 生成侧栏组织管理分组下的组织设置子菜单与管理页，完整 identity.workspace 将其纳入基线。前端入口、直达、已挂载页面和提交前只复核可信页面/动作权限 code 与 scope，不依据 owner 角色名或 ownerAccountId 放行。后端另校验 RBAC 及真实组织/对象归属；拥有者保护属于目标对象规则，不是管理授权特例，普通页面权限不授予改名权。

改名只提交当前组织和经过 trim 的 1–60 字名称；防重复提交，失败保留草稿。成功刷新同 scope 的共享组织上下文，顶部、账号菜单、切换弹窗和管理页同步名称；不要为改名重建登录或切换组织。写入已成功而刷新失败时保留成功事实并恢复读取；超时未知按真实版本/幂等合同查询，不自动覆盖他人的新名称。账号、组织或 revision 变化后，迟到提示、导航和刷新不能影响新 scope。完整用户方案中的成员列表与邀请按上文独立合同接线，当前 rename 模板本身不提供邀请实现。

Web 的 /organization 与 /organization/settings 是独立叶页；父页没有 Outlet 时，管理页文件采用 organization_.settings.tsx，不能错误嵌套导致只有父页渲染。Extension 直接在应用父路由下接线同级页面。独立改名操作不附带删除、转移或角色管理；完整 identity.workspace 另接角色和成员管理。

## 权限、宿主与状态

组织列表、详情、成员和写动作分别服从真实对象/范围授权。平台角色、组织成员角色与操作者身份不同，不从“管理员”名称推导全部权限。已选择权限能力时复用其判断与撤权，业务 403 不作为统一注销。

Web 按实际 Router/Query、列表与 i18n 合同工作。Extension 使用所在 Popup/Options 的导航与消息边界，不调用 Web 文件路由或列表 Skill；真实需要跨上下文协调时确认唯一 owner、Chrome MV3/Firefox MV2 生命周期与权限拒绝，不默认加入 background 或扩大权限。组织模块本身不授权凭据持久化。

Query key 含实际影响结果的账号、组织、成员/权限 scope、代次、目标、语言和查询参数，不含 Token。组织共享资源按组织归属，成员私有资源在组织边界内再按成员限制；不得靠仅使用全局 accountId 或仅使用成员 actor 模拟完整租户隔离。退出、目标或权限变化使旧响应、回调和草稿失效；后端始终校验对象级范围。

## GraphQL 列表与服务合同

组织、账户、成员、邀请及角色候选集合按 [列表查询协议强约定](../../../../docs/DATA_ACCESS.md#列表查询协议强约定) 判断协议与契约缺口；本领域知识只补充对象语义，纯本地计算不构造远端服务。

## 验证与交付

完整用户方案验证账号与自有组织/owner 成员原子创建及失败无半成品；接受邀请后保留自有组织；未接受邀请不可访问；同组织授权成员共享组织内容、不同组织隔离、成员私有数据仍受限；管理目标不改变登录身份；成员移除不影响其他组织；账户/成员状态分离；唯一负责人保护；版本冲突、超时实际成功、刷新失败保留结果；退出/切目标后迟到结果隔离。

采用切换时追加组织名称点击、多组织弹窗、单组织保留名称且禁用当前选项、相同目标 no-op、撤权恢复与管理无豁免、拒绝/未知恢复、新组织上下文就绪前阻断、旧权限隔离、原导航取消与多上下文竞争。组织无订单/钱包依赖时明确不适用，不为补齐矩阵启用功能。区分通用规范、Mock、真实服务和最终候选证据。
