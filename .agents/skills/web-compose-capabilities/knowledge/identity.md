# 身份认证知识库

完整账号不等于启用全部协作界面。明确只用自有组织时保留可信组织/成员恢复、profile 和 password.change；按需注册及默认验证。只有采用完整协作时选择 identity.workspace；现有产品收敛范围须增量移除入口/调用并保留数据，不能重装或删除组织。

按已选操作复用登录、退出、可选注册与密码找回、会话恢复和凭据生命周期。完整用户信息以账号与组织为基线；低层认证组件可独立复用，不代表完整用户系统已经交付。

本库是可复用设计知识，不是已经接入的服务、可直接运行的代码或产品规格。真实需求进入下游唯一 Product Spec；缺少的 endpoint、密码规则、验证码期限和账号开通流程保留待确认。

## Go 服务基准

当前 Go Harness 的账号自服务、原始 DTO、Token 生命周期及客户端接线边界见 [Go 客户端合同](../../../../docs/GO_CLIENT_CONTRACT.md)。上游 profile 仅有 account 与可空 org；本地 install-users 自动增加完整组织 overlay，完整协作前端使用 identity.workspace；明确收敛时使用完整账号核心操作。归属规则统一见 [ACCOUNT_OWNERSHIP.md](../../../../docs/ACCOUNT_OWNERSHIP.md)。昵称可为空，显示层回落用户名；phone/last_login_at 可 null，时间为 Unix 秒。注册不自动登录，refresh 不撤销旧 refresh，logout/改密/找回撤销全账号令牌。基础会话仅采用 access；显式刷新结果须由唯一 owner 接受，不能自动重放写入。

## 完整用户信息

完整用户信息由 Account、当前 Organization 与该账号在当前组织中的 OrganizationUser 组成。每个注册账号必须同时拥有一个自有组织及对应 owner 成员；加入他人组织只增加新的成员关系。模型、注册原子性和组织数据隔离以[组织知识](organization.md#账号组织与组织用户)为准。

采用完整用户方案时，登录与恢复必须取得可信账号、当前组织和有效成员关系，再开放组织私有内容；缺少自有组织或成员关系是服务/数据缺口，进入阻断恢复，不能在浏览器中补造组织或当作完整用户就绪。注册入口仍只在需求明确且服务支持时出现，但任何注册成功结果都必须满足账号与自有组织同时成立的不变量。

`identity.session` 和独立会话 helper 是当前可执行的认证底层资源，不会自动生成全部组织、资料或注册操作。能力选择必须把完整用户方案需要的组织上下文及缺失接线交还实施入口，不能用当前 catalog 的最小依赖缩减已确认范围；当前实现差异见[接线合同](../templates/application/wiring.md#当前装配器与目标规范的差异)。

## 操作与组合边界

| 可选操作       | 本模块负责                                               | 按实际需要关联                                           |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 登录与会话恢复 | 校验凭据、取得当前账号、确认凭据保存及公开登录状态       | 完整用户方案同时恢复当前组织及成员；受限功能消费可信权限 |
| 退出           | 阻止新私有操作，清理本应用会话与私有状态，同步相关上下文 | 服务端吊销按真实范围执行                                 |
| 注册           | 服务支持的账号字段、验证码及账号与自有组织的原子创建     | 同时建立 owner 成员；邀请接受是另一操作，不替代自有组织  |
| 密码找回       | 用途绑定验证、新密码提交、目标账号的会话收敛             | 不默认启用自动登录或全设备退出                           |
| 导航校验       | 当前导航先校验，再交给实际授权规则，最后运行私有读取     | 不要求没有业务权限模型的产品制造权限码                   |

基础 identity.session 默认接入完整登录页面与路由；已有可信身份实现时复用其唯一 owner 和等效认证流程，不另建 Token。orders.purchase 明确依赖此基础身份；其他读取按 catalog 的具体依赖选择。匿名页面、公开商品等是否允许由真实服务决定。

## 主界面用户信息与账号菜单

主界面结构遵循 [Mantine UI 规范](../../../../docs/MANTINE_UI_GUIDELINES.md) 的“功能组合的页面与布局”。固定触发器为头像、昵称和下拉指示；缺少头像时显示姓名首字，长值保留可访问全名。身份仍由唯一会话拥有，头像按真实需求从可信身份或资料查询传入，不复制用户档案或扩大持久化。

完整用户方案账号菜单固定显示可信邮箱／昵称摘要、切换组织、个人设置、修改密码和退出。个人设置仅改全局昵称，改密使用独立账号页；侧栏组织管理只放组织设置、成员管理、角色管理，各按有效读取码显示。

Web 工作区左侧保留工作台、组织管理分组与底部公开 /settings；账号资料和组织卡片不进侧栏。/account/settings 与 /account/password 独立，不要求组织业务权限；本人邀请在切换弹窗处理，切组织不改变全局资料。Extension 保留紧凑宿主导航。

完整 identity.workspace 包含本人资料编辑与改密，生成真实个人设置页面；低层 identity.session 不默认增加这些操作。已有服务按可信合同提供适配，不能以空槽位或持久档案冒充完成。注册、找回、计费和充值仍由各自需求触发。

## 宿主与持久化

Web 使用现有 Router、Query、HTTP client、i18n 与数据层，唯一会话协调者负责恢复、轮换、退出和异步所有权。Web 认证若采用已确认的 LocalStorage 凭据方案，沿用该限定例外：精确命名并隔离项目、服务环境和 schema；只保存必要凭据，不保存密码、验证码、用户档案、权限快照或 continuation。读入按未知数据校验；写入/删除后核实结果，失败时阻断“已持久登录”或恢复声明。不能由“存在身份认证模块”扩张全部 Web 的持久化授权。

Extension 不继承 Web LocalStorage 例外或文件路由。Popup、Options、background 各上下文不会自动共享会话；凭据默认保持当前受管内存边界，确需跨上下文/持久化时先确定真实所有者、消息、宿主存储及权限合同。Chrome MV3 与 Firefox MV2 按实际生命周期和 API 分别验证，不为认证默认新增 background、content script 或浏览器权限。

## 登录与恢复 SOP

1. 打开实际入口或受保护深链接，校验应用内安全返回目标。无凭据显示表单；有凭据先恢复，身份尚未确认时不闪现私有正文。
2. 使用可见标签、服务确认的账号格式、current-password、防重复提交和可访问反馈。允许密码管理器与粘贴，不裁剪密码，不把新密码强度规则套给旧账号。
3. 通过隔离的公开请求边界提交；公开登录、注册、验证码和找回不携带残留 Token，也不借其错误清理其他当前会话。
4. 校验成功响应与 header 编码；按已确认方案保存并装配当前凭据。完整用户方案的账号、组织、成员及本次必需权限全部就绪后才公布可操作状态。
5. 返回安全且实际可访问的原目标；未知路径、匿名、权限拒绝分别处理。没有可访问页时提供真实恢复或退出，不制造跳转循环。
6. 冷启动或新 scope 的读取网络失败只保留凭据并提供重试，不能拼造账号或权限；同一 scope 已加载上下文的容错不扩大其原有授权。

## 退出 SOP

阻止新私有操作 → 使旧异步结果失效并停止请求/订阅 → 清理精确持久项、内存凭据/continuation、私有 Query 和实际附属上下文并阻止旧记录恢复 → 使用捕获的旧凭据按合同尝试一次有界吊销 → 复核归属后返回公开恢复入口。本地失效不等待远端。

保留语言/主题，不清空整个 Storage。远端失败不阻止本地退出，也不宣称全部设备已退出；删除失败必须阻止本页重新恢复旧记录并提供清理重试。退出接口自身的 401 不递归退出。临时签发因保存失败或迟到被丢弃时，只能处置本次签发，不能借全账号 logout 误伤后来登录。

## 可选注册与找回 SOP

- 注册仅在明确选择且服务支持时出现入口、路由和请求。邮箱验证码按目标与注册用途绑定，期限/限流来自服务；更换邮箱废弃旧状态。服务原子建立账号、自有组织与 owner 组织用户，三者全部成立才报成功，首次登录使用该成员关系；组织名称可由显示名称提供可修改的默认建议，服务负责最终校验。成功清除秘密输入；是否签发凭据和自动登录服从可信服务合同，原型的直接进入演示不授予自动登录或持久化。当前 Go 注册不返回令牌；页面成功后使用唯一 session 显式登录，安全返回原目标。注册已成功但登录失败时冻结邮箱，只重试登录；注册结果未知时阻断再次创建，提供登录核对入口。具体不变量见[组织知识](organization.md#账号组织与组织用户)。
- 找回使用服务真实的验证码或重置链接流程，不编造另一协议。验证码一次性与用途隔离，new-password 按服务规则，确认密码一致。反馈避免无依据暴露账号是否存在；已有来源差异必须明确映射。
- 写入超时不自动重放或假报成功。找回成功只清理仍属于本次提交代次及可核实目标账号的上下文；后续登录使旧回调失去本地清理、提示和跳转权。服务已吊销时不再额外扩大 logout；吊销范围由服务证明。

## 会话、导航与错误

会话 generation/revision 与导航 ID 分离。同 scope 普通导航保留外壳、Query 与局部交互，不因 checking 重建会话；实际导航仍先校验再放行业务 loader。取消旧导航不应中断已确认失效清理或已接受新 scope 的恢复；新登录可以替代旧工作，await 后复核所有权。

凭据校验操作的 HTTP/业务错误或协议错误按已确认“返回错误即退出”策略统一清理；普通业务 403 保留会话并交权限反馈。无响应 network/timeout 与本地配置/编码/程序错误分别处理；取消或被替代的请求不注销新身份。不得从健康检查、任意 2xx、JWT 解码、过期时间或网络失败推导授权；不默认自动 refresh 或重放写操作。

跨标签页变化重新读取并校验当前记录；不得信任事件载荷。LocalStorage 没有 CAS，跨页协调须按真实原生能力确定，无法可靠协调时阻断冲突，不用时间戳假装原子性。

## 接口与列表强约定

远端账号、会话等集合与单对象身份操作按 [列表查询协议强约定](../../../../docs/DATA_ACCESS.md#列表查询协议强约定) 判断协议与契约缺口；本领域知识只补充对象语义，纯本地计算不构造远端服务。

不从 BaseURL 猜 endpoint。Header 采用真实服务适配，公开请求隔离，受控 target 才接收凭据；日志、URL、Query key 不含秘密。

## 本次操作的验证

覆盖成功与最高风险失败：响应校验、公开请求隔离、存储损坏/拒绝、未公布签发清理范围、冷恢复网络失败、导航取消/迟到 401、新 scope 恢复、退出失败及多上下文竞争。完整用户方案追加自有组织缺失阻断、账号资料跨组织一致、干净侧栏和账号菜单入口；采用注册时覆盖账号/组织/owner 原子成功及失败无半成品，找回只测试本次已选分支。

开发投递 Mock 在自建邮箱注册尚无邮件服务时默认启用，仅限 dev 注册；发送成功在当前表单显示实际验证码及简短未接邮件提示，验证码校验、持久化、配额和单次消费仍由真实服务完成。接通真实 SMTP 同时关闭 mock，真实回执不带 code，页面移除回显。找回及非开发环境拒绝 Mock。测试 Mock 明确账号、签发、验证码与时间所有者；不能据此声称真实投递、授权或最终候选通过。

独立会话代码不依赖组织或权限；会话状态机实施由 `web-implement-auth-session` 负责。[账户协议参考](../templates/compositions/account-workspace/README.md) 仅提供API、Mock与存储边界，当前应用使用唯一 application 装配。

基础接线以[固定设计](../templates/identity/design.md)和[应用装配](../templates/application/wiring.md)为准。catalog 只描述当前可执行资源的最小前置，不替代完整用户信息要求或启用全部操作；购买必须含基础身份。旧专项操作建议不覆盖该基础接线合同。

## 邮箱注册与验证码的生成合同

已选注册采用邮箱和密码，不要求用户名、昵称或组织名称；兼容旧客户端的可选名称字段由 API 保留。服务生成唯一内部用户名与不含邮箱的公开显示名，组织默认名也不能泄露邮箱。登录继续允许旧用户名或邮箱，不把注册的新密码规则强加给旧账号。既有服务若有不同必填字段，先明确契约差异再适配。

自建邮箱注册默认组合 identity.register 与 identity.verification，前后端装配自动补齐；无邮件服务时默认采用上述 dev 模拟投递，不再补问。基础登录不自动增加注册，已有外部服务遵循其可信验证合同。发码经匿名请求，邮箱 trim/lowercase、register/email 场景、数字前导零、绝对期限、码长和重发秒数均按可信回执处理；真实回执禁止 code 字段。验证码、密码及邮箱草稿只留当前表单内存，不进入 URL、Query 缓存、日志或 Storage。

更换规范化邮箱立即取消旧请求并递增代次，A→B→A 也不能接纳迟到的 A 或其 finally；取消和卸载后无权提示或解锁新请求。同邮箱重发 deadline 按实际时钟恢复，切回已冷却邮箱不能冻结倒计时。发送和注册都同步防双击；验证码错误定位字段，未知投递不自动重发。注册采用 new/registered/unknown 分支，注册成功后的登录重试不能再次消费验证码或创建账号。

组织内业务页面保持一个入口，以当前组织作用域读取；自有/加入关系只可在组织选择器中解释，不把同一业务拆成“我的”和“我加入的”导航。切换放在用户下拉菜单，顶部只展示当前组织，菜单与正文共用可信作用域。具体业务标题由下游需求提供。

账号菜单、页面、服务端 11 码及迁移统一遵循 [Auth 标准](../../../../docs/ACCOUNT_OWNERSHIP.md#前后端标准交互与权限表)。

账号触发器仅显示单一昵称或用户名；Header 不放组织卡片，账号菜单统一无图标，切换组织、个人设置、修改密码用弹窗。列表复用统一 ListSurface/ListTable/ListFooter，状态仍由原账号、组织与列表归属持有。详见 [UI 规范](../../../../docs/MANTINE_UI_GUIDELINES.md#标准账号与列表组件)。
