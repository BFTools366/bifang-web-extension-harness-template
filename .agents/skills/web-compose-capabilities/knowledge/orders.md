# 订单知识库

按真实需要选择建单、订单列表/详情、原单恢复、允许状态查询或取消。只读 orders.read 可消费已有外部订单而不引入其他页面；orders.purchase 必须接入基础身份、商品、订单创建及钱包付款，不能交付匿名购买。

商品目录、支付、钱包与权益只通过本次服务真实提供的稳定关联协作；选择订单不会自动产生资金写操作。

## 必需合同与不变量

| 对象/操作 | 必需事实                                                            | 边界                             |
| --------- | ------------------------------------------------------------------- | -------------------------------- |
| 建单      | 原业务意图、商品/报价等真实输入、服务订单 ID、作用域、幂等/恢复查询 | 服务定价；未知建单不得重复创建   |
| 订单      | 购买者/组织归属、历史业务/金额快照、状态、允许动作、版本            | 当前商品资料不能覆盖历史         |
| 支付关联  | 原订单 ID、独立支付尝试、服务可支付能力                             | 订单、支付尝试、权益状态分别表达 |
| 取消      | 仅服务当前允许的状态、必要原因、版本/幂等、竞争结果                 | 取消未支付单不等于退款           |
| 查询恢复  | 原意图/订单标识、一致性期限、已终止的证明                           | 一次未找到不能证明未创建/未扣款  |

状态名称仅作领域映射，不强改服务。“待支付”是否可继续以服务允许动作、归属和有效期共同决定，未知状态默认不可付。

## 建单 SOP（可选）

1. 冻结当前身份/业务 scope、选择/报价、输入与原意图关联。来自已选目录时消费其权威报价，不从展示价自行定价。
2. 确认商品/规格/数量、金额/币种和业务作用域。价格或条件变化必须展示并重新确认，不悄悄接受更高扣款。
3. 用真实幂等契约提交，同一意图保持原 key；前端禁用双击不能替代跨页/跨设备服务幂等。
4. 校验返回的原订单身份、历史快照和允许动作。成功后由服务决定进入待支付、已完成或其他真实流程，不默认存在钱包。
5. 超时或响应丢失时查询原意图并恢复原单；查询仍未知时阻断重新建单。服务证明原意图终止且后续不会提交后才可按确认流程重新发起。
6. 关闭表单/弹窗只停止本地等待，不表示订单或服务请求取消。刷新、返回后以原关联恢复。

key 的作用域、有效期、同键不同输入拒绝及并发原子性来自服务，不用请求追踪 ID 冒充幂等。必要的最小非凭据恢复标识仅按已确认数据层/用户 scope 保存，不放 URL或日志，不持久化余额/权限/订单权威状态。

## 列表、详情与续付 SOP

用实际订单号、状态、时间和归属筛选 → 服务分页列表 → 原单详情 → 分开读取订单、支付尝试和实际权益状态 → 提供服务允许动作。

- 默认只读范围可以单独成立，不能因为存在订单页增加继续支付或取消。
- 采用续付时重查原单状态/归属/有效期/应付与当前方式。仅服务确认可支付原单显示继续；处理中或未知只查询；已支付、关闭、过期或无权不给再次扣款入口。
- 复用原订单 ID与历史商品/金额快照；新报价/新订单仅在服务明确要求并经用户确认时执行。原单付款委托已选支付边界，不读取其私有 UI/atom。
- 支付成功与权益生效分开；权益同步失败保留已支付。未选择权益或服务没有权益合同则不添加伪状态。
- 列表计数不推导全量统计；全量指标只有明确聚合合同才展示。

## 取消与管理核查 SOP（可选）

1. 展示原订单、目标购买者/组织、当前允许动作及真实影响，按服务要求收集原因。
2. 提交版本/幂等关联，由服务处理取消与支付竞争，前端不能“抢先本地取消”。
3. 超时未知只查询原请求/订单，不能假报取消或重复写入。
4. 已支付、关闭、过期订单不手改历史金额/支付结果，不强制标记成功、删除交易或代付。
5. 管理核查可关联服务支付尝试、钱包流水与审计，但未选相关模块时保留本服务提供的必要信息，不生成多余页面。退款、调账、补发权益与强制干预均不在通用默认范围。

## 会话、作用域与恢复

消费现有可信身份/作用域，实际匿名订单是否允许由服务决定。操作者和管理目标分开；平台查看某组织订单不改变登录组织。Query key含影响结果的 target、作用域、目标、语言与查询，不含秘密。

提交冻结会话/目标 revision，响应提交前重核所有权。退出、切组织或撤权隔离旧 UI/缓存/回调；取消 Fetch 不表示服务已取消订单或扣款。成功保存但列表/详情刷新失败只恢复读取；未知结果不自动重放写入。

Web 采用现有列表、Router/Query/i18n 合同；Extension 采用本 surface 的导航/消息/数据 owner，分别验证 Chrome MV3/Firefox MV2，不继承 Web文件路由、专属列表 Skill或 Web凭据持久化例外。

## GraphQL 列表强约定

订单、支付尝试候选/记录等远端集合查询统一使用 GraphQL，含无条件首载、条件筛选、搜索、排序与分页。原订单详情、原意图恢复查询和写操作按真实语义判断；不能给列表换名规避。可信 Schema 缺失是缺口，REST 列表如实标记不符合；纯本地集合不构造服务。

## 验证

按已选操作覆盖建单成功、双击/并发幂等、超时后实际成功与副本未找到、刷新恢复原单；列表筛选与详情归属；历史快照保持；订单/支付/权益状态分离；续付资格；取消与支付竞争；成功刷新失败；退出/目标切换后迟到结果隔离。

真实付费、生产订单写入不因知识或模板使用得到授权；Mock/规范检查、真实服务及最终候选分别报告。

基础接线以 [固定设计](../templates/orders/design.md) 和 [应用装配](../templates/application/wiring.md) 为准。catalog 的操作依赖是最小前置，不随模块名启用全部功能；身份不隐含组织/权限，购买必须含基础身份。旧专项操作建议不覆盖该基础接线合同。
