# 下游 PRD 记录约定

此约定只在下游实际需求工作中使用；初始化不实例化此模板，也不创建业务 PRD。沿用 `docs/product_spec/README.md` 的日期、完整快照和唯一当前正文规则。首次需求工作若目录不存在，由 `$web-define-product` 创建索引和当天正文，不能假定初始化已有业务记忆。

PRD 保持与需求规模相称。推荐结构如下，已有项目结构可保留，只补缺少的实质信息：

```markdown
# YYYY-MM-DD 产品规格（PRD）

状态：Draft

## 用户、问题与目标

目标用户、场景、痛点、预期结果与可衡量成功标准。

## 本轮范围

稳定 scope ID、包含/不包含、页面或 Extension surface、优先级。

## 需求与验收

稳定需求 ID；每项写触发、输入、行为、输出及可观察的成功/失败标准。

## 数据与交互

实体/字段、来源与存储、主要状态/转换、异常与恢复；简单需求不强制画图。

## 约束与未决项

宿主、权限、隐私、无障碍、语言、依赖和外部服务边界；待定项的影响与解决条件。

## 确认依据

真实用户确认的日期与原话/会话依据；明确哪些仍是建议或假设。
```

确认只覆盖实际讨论过的范围。没有用户确认时保持 `Draft`；确认需求后改为 `Approved`。单一原型应实现当前已确认需求；业务规则、权限或范围变化必须先回写并确认 PRD。

原型登记是独立事实：每次仅生成一个桌面端可交互 HTML，不做 A/B 比较或 Mobile 设计。`docs/prototypes/<scope>/review.json` 绑定项目、PRD 哈希、版本及唯一原型哈希，不记录用户选择。开发时读取 PRD 和该登记记录，按已有实施授权继续；新增需求改变 PRD 后修订、自查、展示并重新登记，不能复用旧摘要。

列表接口设计先按 `docs/DATA_ACCESS.md` 的“列表查询协议强约定”确定 GraphQL Query 及筛选、排序、分页和 Schema 依据；无契约时只给待确认设计，不把 REST 列表写成建议，不因原型使用本地数组而虚构服务已支持。

## 功能模块组合

宿主只分 Web 与 Extension；功能按具体需求组合，不按产品类别决定。创建只生成中性工程；成功下游在唯一 PRD 记录已选模块、具体操作、角色/数据范围、采用依据及日期。已有 PRD 直接复用，局部修复不重启需求确认；旧分类记录只作为历史，不推导当前能力。

命中身份认证、组织、权限、商品目录、订单、钱包支付或审计时，读取 [$web-compose-capabilities](../../web-compose-capabilities/SKILL.md) 和所选模块知识；实施需要时再取模板。模块可单独采用，组合示例须显式选择，未选操作不进入菜单、路由、请求或原型。注册、组织切换、管理写入、购买和扣款分别按实际需求与服务确认，不因安装技能而启用。

| 当前范围               | 具体操作           | 角色与目标/作用域    | 可信契约与缺口       | 所选模板及类型   | 验收             |
| ---------------------- | ------------------ | -------------------- | -------------------- | ---------------- | ---------------- |
| 按当前需求填写所选模块 | 列明读取/写入/恢复 | 区分操作者与管理目标 | 不猜 endpoint/Schema | code/design/demo | 可观察成功与失败 |

远端列表查询必须使用 GraphQL，包括无条件首载。服务不支持时明确缺口；不把参考文档或 Mock 当服务事实。模块选择不授予权限或生产/资金操作授权。

## 创建与开发 SOP

1. **源创建工程**：确认唯一宿主、身份、源外绝对空目标、品牌与策略；复用既有 staging/安装/独立 Git 事务，不收集功能范围、不自动注入业务、PRD 或原型。
2. **下游确认需求**：定义可观察流程并按需组合模块，在唯一 PRD 保存当前选择和操作边界。已有可信身份或权限源直接复用，不强制生成额外模块页面。
3. **原型**：只读取已选模块知识与设计参考，生成一个桌面端交互原型并自查登记；按真实流程选择认证页、工作区或公开页面。
4. **实施**：按实际操作适配独立模板或显式组合模板，状态归属唯一，复用现有 API、Query、Router、i18n 和存储边界。
5. **真实服务**：按 [模块 API 关联与缺口](../../../../docs/API.md#功能模块与-api-关联) 核对可信契约，保留未确认项；不从 BaseURL 猜接口。
6. **文档**：使用 API 导出技能同步按业务聚合的接口与已实现流程，核对已有文档与当前代码差异；模板划分不要求导出逐模块碎片文档。
