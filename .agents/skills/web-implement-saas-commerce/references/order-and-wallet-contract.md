# 订单、支付与钱包实施合同

以下为能力与不变量，不规定服务路径、HTTP 方法、字段拼写或状态码。真实接入先映射服务契约；缺少关键防重复与对账能力时不执行真实扣款。

与已收录契约的关联统一见 [客户端 API 缺口](../../../../docs/API.md#客户端契约缺口) 与 [协议适配](../../../../docs/API.md#协议与会话适配)。profile 只负责账号档案/默认组织读取；购买所需目录、报价、支付方式、建单、原单续付、钱包和权益读取均待真实服务补齐。请求追踪 ID 不承担建单/支付幂等，通用分页形状不证明已有订单或流水列表。

## 必须核对的服务能力

| 边界       | 必需事实                                                                               |
| ---------- | -------------------------------------------------------------------------------------- |
| 功能与权限 | 是否启用、操作权限、用户与组织归属、服务支持范围                                       |
| 目录       | 分类树/父级关系、直属/后代查询语义、排序、分页、商品分类归属、可售与规格约束           |
| 报价       | 商品/规格/数量、准确金额和币种、报价 ID/版本/有效期、费用/折扣（若有）                 |
| 支付方式   | 服务端方式 ID、类型、钱包 ID/归属/币种、可用状态与原因；仅适配 wallet                  |
| 建单       | 服务端订单 ID、商品及价格快照、应付与作用域、幂等规则、结果恢复查询                    |
| 支付与对账 | 原订单 ID、支付尝试 ID、幂等规则、允许状态、成功/失败/处理中查询、有效期、最终扣款权威 |
| 钱包与账户 | 可用/冻结余额语义、流水分页与订单关联、当前账户和商品权益刷新、最终一致性边界          |

订单请求表达选择的商品、规格/数量、报价标识和支付选项标识，由服务端重新校验、定价并组织订单；前端传入的价格或余额不成为扣款依据。订单保存支付选项/意图，真正扣款是独立动作；服务使用合并事务接口时仍须提供可恢复订单身份、幂等和结果查询，不能省略这些语义。

金额使用服务约定的最小单位整数或精确十进制字符串，带显式币种与精度；不得假设所有币种两位小数，不用 JavaScript 浮点求和作为权威。钱包余额与应付必须在同币种/同资产契约下比较，汇率、费率和折扣均由服务提供；零金额订单是否需要支付由服务明确。

## 文档操作覆盖

购买能力已选中且用户要求完善接口设计时，下游文档应覆盖已确认需求，不因产品 API 尚未实施而省略整个模块。按实际服务允许合并操作，不固定 endpoint、字段名或接口数量；已有服务合同直接采用，缺少合同的建议逐接口标明待服务端确认。

| 模块       | 需要对照的操作与语义                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| 分类与商品 | 分类树/节点、所选分类及后代商品（含父级直属商品）、商品详情与服务允许的规格/数量、权威报价与其可用钱包方式         |
| 订单       | 单商品建单及历史商品/金额/归属快照、按原建单意图恢复查询、订单号/状态筛选分页、原单详情与服务允许动作              |
| 钱包支付   | 原单当前可用方式、对原单发起支付、原支付意图未知时查询、已知支付尝试查询；建单与支付各自防重，不重建原单           |
| 钱包       | 可见钱包、明确个人/组织归属与币种精度、可用/冻结余额与状态、按时间/收支筛选的分页流水、独立流水 ID 与订单/尝试关联 |
| 成功后读取 | 原订单及列表、钱包/流水、当前账号；仅商品确实影响权益/额度/权限且有合同才纳入对应读取，刷新失败保留支付成功        |

请求追踪、业务幂等与会话版本分别核对。恢复关联键的携带方式以服务合同为准，不写入 URL 或日志；建单/支付键的作用域、保留期、同键不同输入拒绝和并发原子性都须明确。一次未找到、窗口过期或副本延迟不能证明未提交/未扣款；“未提交”只有服务确认原意图终止且后续也不会提交时才能作为恢复依据。

订单、单次支付尝试、恢复查询及业务权益使用各自状态。恢复分支中允许 null 的订单/支付字段，不扩散为普通订单列表元素或详情对象可空；跨接口复用 DTO 时按当前响应核对判别字段与可空性。目录展示价不能覆盖历史订单金额，页内记录计数不能冒充费用中心全量统计。

## 状态所有权

| 对象         | 归一化语义示例                             | 操作边界                                             |
| ------------ | ------------------------------------------ | ---------------------------------------------------- |
| 本地购买草稿 | 未选、已选、报价中、可确认、失效           | 可更改；没有服务端订单前不称为待支付订单             |
| 服务端订单   | 待支付、支付处理中、已支付、已关闭、已过期 | 仅服务端允许的待支付订单可续付；未知状态默认不可支付 |
| 单次支付尝试 | 未发起、处理中、成功、失败、结果未知       | 失败是否可重试由服务判断；未知先对账                 |
| 业务权益     | 待生效、已生效、已到期等（如适用）         | 与支付状态分离；已支付不推断权益立即生效             |

状态名称只是映射示例，不要求修改服务。服务端返回的可支付能力、归属和订单状态共同决定操作；客户端倒计时仅展示，不能宣告服务端过期/成功。付款成功后权益仍在同步时保留“已支付”，显示权益待更新。

## 防重复与未知结果

- 建单和支付各自有服务端幂等契约，明确 key 的作用域、有效期、相同 key 不同请求的拒绝及查询入口。前端防双击只改善交互，不能替代跨标签页和跨设备的服务端防重复扣款。
- 同一意图重试使用原 key；用户明确改变商品或发起服务允许的新支付尝试才产生新的 key。key 与订单恢复标识不能放 URL 或日志；确需刷新恢复时只经数据层保存最小、按用户/组织隔离的非凭据关联标识，恢复后仍查询服务，不持久化余额/权限/订单权威状态。
- 建单返回超时且未知是否成功：以幂等关联查询结果，找回原订单；查询仍未知时阻断重新建单。支付请求超时：查询原订单/尝试，不自动生成新支付尝试，不自动重放写操作。
- 只有服务确认原尝试已终止且原单仍可付时，用户才可再次支付。查询成功已支付立即关闭支付入口。轮询有界、支持取消/退避；离开页面停止轮询，后续由订单查询恢复，不在后台无限请求。
- 钱包余额不足、冻结、报价过期、订单不可付和权限错误用本地化业务反馈。业务 403 不自动注销；401 按认证合同退出。网络容错保留会话不授权离线支付或依据旧余额放行。

## 会话、组织与账户刷新

- 复用现有 SaaS 认证协调者；钱包属于用户还是组织必须有真实契约，不因 UI 当前显示组织就推断。所有目录权限、报价、订单、支付与钱包 Query key 绑定影响结果的 target、用户/组织 scope 和语言，不含 Token。
- 提交前冻结当前身份、组织、会话 revision、订单/报价和支付方式，响应写回前复核。退出、切组织、权限变化使旧 UI 和读取失效；取消 Fetch 不代表服务端已取消扣款。
- 服务端确认支付成功后失效并重新读取：原订单详情与列表、钱包余额/流水、当前账户资料及该商品影响的权益/额度；需要时按服务权限契约刷新权限。不得清空全部 QueryClient 影响无关功能，也不得直接乐观修改余额或凭空增加额度。
- 在原作用域内等待/收集各刷新结果。部分失败单独标记待更新，保留支付成功；只重试这些读取。作用域已改变时不将原账户结果写入新 scope，保留原订单的可恢复查询路径。

## 模块与实施验收

`routes → features/{catalog,checkout,orders,wallet} → data/api/<domain> → client` 体现责任方向，可消费所需稳定下层。分类/商品查询归 catalog，购买协调归 checkout，原单恢复归 orders，余额/流水展示归 wallet；模块间通过有名称的契约和 Query options 协作，不直接读写对方私有 atom。只有真实共享时才抽取金额格式/订单状态映射，主题与认证保持既有唯一所有者。

至少覆盖默认关闭与无权限、分类错误/迟到报价、无可用服务端方式、幂等并发、超时后实际成功、刷新恢复原单、已支付后重复提交、钱包不足与币种不符、付款中切组织、支付成功但账户/权益刷新失败。真实请求测试验证未发送前本地错误不被当成“网络未完成可重付”；Mock 与真实服务分别报告。真实付费测试须在获批环境和范围内，不因通用 Skill 自动触发。
