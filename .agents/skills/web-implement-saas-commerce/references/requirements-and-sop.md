# 可选购买能力：需求与用户 SOP

仅适用于明确选中的 SaaS 客户端。下游 PRD 记录启用事实、用户/组织作用域、服务契约和具体设计，本文件是可复用基线。未选中不注册菜单/路由、不加载业务数据；三项入口分别受服务端权限控制，隐藏按钮不能替代服务端鉴权。

需求核对使用 [基础 API 的客户端能力映射](../../../../docs/API.md#客户端契约缺口)：现有参考可关联认证与账号资料读取，尚无商品、分类、订单、支付、钱包或权益接口。采用时在 PRD 记录各操作的真实契约及缺口，不把本 SOP 的能力名称直接当成 endpoint。

## 选择与创建交接

新建 SaaS 客户端必须明确询问购买模块是否需要，模块包含商品选择、订单管理和钱包管理。推荐关闭只作为建议；实际回答或明确接受默认值后记录选择、来源与日期到 README 创建交接，首次 PRD 沿用，不重复询问。旧项目缺少创建记录时在首次相关需求补问；已有 PRD 的当前决定优先，不补造历史。选择不生成业务，也不授权资金写操作。

## 页面与最小范围

| 菜单     | 用户目标                     | 最小内容                                                                                        |
| -------- | ---------------------------- | ----------------------------------------------------------------------------------------------- |
| 商品购买 | 按分类查找并购买商品         | 树形分类、商品选择、规格/数量（仅服务允许时）、服务端报价、可用钱包支付选项、订单确认与支付结果 |
| 订单管理 | 查询已有订单与恢复未完成支付 | 订单号/状态筛选、分页、商品快照、金额/币种、创建时间、支付状态、详情及条件性“继续支付”          |
| 钱包管理 | 查看可用资金及收支记录       | 服务端钱包归属、币种、可用/冻结余额（仅服务提供时）、钱包状态、流水筛选与刷新                   |

默认单次选择一个商品及其服务支持的规格，数量默认 1；不扩张为购物车、多商品合单、自动续订、优惠码或商品管理后台。钱包管理默认只读，不因示例出现充值按钮就增加充值、提现、转账或退款。已有获批充值能力才可作为余额不足的下一步入口；没有时说明不足并允许稍后从原订单继续。

## 分类与商品

- 分类具有稳定 ID、名称、父子关系与顺序。根节点无父级，服务数据必须无环、无重复 ID、无悬空父节点；不合法分支不可用于下单，给出可重试读取错误。
- 商品至少关联一个有效分类，可售状态与分类可见范围由服务端决定。分类可以同时拥有商品和子分类，不把全部父分类强制视为不可选。具体是否允许多分类、分页/懒加载及最大深度按契约确定。
- 中性默认：选择分类时查询该分类及其子分类商品；向服务明确表达范围，不能自行拼接各页后声称完整列表。若服务仅支持直属商品，在 PRD 与 UI 中明确这一语义。
- 展开分类与选择分类是不同动作；保留祖先路径和选中态。切换分类使不再有效的商品、规格、报价与支付方式失效；迟到响应不能覆盖当前选择。
- 下架、不可售、无权限、空分类、分类被删除、报价过期分别反馈。搜索、筛选、分页只管理浏览状态，不把已提交订单变成可编辑草稿。

## 首次购买 SOP

1. 用户登录后进入“商品购买”。确认当前账户/组织，加载分类与商品；加载失败保留可恢复入口，权限失败不展示购买按钮。
2. 用户展开并选择分类，再选择商品；查看名称、说明、服务支持的规格/数量、价格与币种。当前未选择商品时，订单摘要引导选择，不显示可提交按钮。
3. 服务端返回当前商品组合的报价与可用支付方式。仅渲染可识别的钱包方式，展示所属钱包、币种、可用余额和不可用原因。服务未返回钱包、钱包冻结或无兼容币种时不可支付。
4. 用户选择钱包，核对商品、数量/规格、计价、应付金额、支付方式与购买作用域。费用、折扣、条款只有服务/产品真实要求时出现；不能照搬示例费率、品牌渠道或强制条款。
5. 点击“确认购买”，防止重复提交；创建订单成功后展示订单号，并进入该订单的支付流程。服务端重新计价或支付方式失效时，展示变化并重新确认，不能悄悄接受更高扣款。
6. 支付请求处理中保持订单可识别，不把关闭弹窗当成取消。失败且明确未扣款时，保留订单并提供服务允许的恢复动作；超时或断网进入“结果确认中”，查询原订单/支付尝试，不能立即重复扣款。
7. 服务端确认成功后显示“支付成功”，刷新订单、钱包、当前账户资料及受影响的权益/额度；只有确受商品影响才刷新权限。刷新失败单独显示“已支付，账户数据待更新”，提供刷新，不再提供支付按钮。

## 订单管理与未完成订单再次支付 SOP

1. 在“订单管理”找到未完成订单，进入详情；重新查询服务端状态，校验当前用户/组织归属、可支付标志、有效期、剩余应付与允许方式。
2. 仅服务端确认待支付且允许续付时显示“继续支付”。支付中/结果未知只提供状态查询；已支付、关闭、过期或无权限不给再次支付入口。
3. 复用原订单 ID 与商品/金额快照，重新选择当前可用钱包；不能用当前商品价格覆盖历史订单，也不能默认重建订单。价格或条款必须变更时由服务明确决定重新报价/新单，用户再确认。
4. 发起新的合法支付尝试，沿用同一支付 SOP；刷新页面、前进后退或多标签页都不能绕过服务端幂等与状态校验。

## 钱包查询 SOP

进入“钱包管理”→确认归属及币种→查看余额/状态→按时间或收支类型查询流水→查看交易与订单关联。旧余额只标记为待刷新数据，不作为扣款成功证据；支付完成后主动刷新，流水尚未可见时显示同步中。流水采用服务端分页，不在客户端拼凑账本或允许编辑余额。

## 作用域变化与停用

退出、切组织或服务权限撤销时，失效旧报价、商品选择与支付 UI，取消可取消的读取并屏蔽旧回调。已提交支付不能宣称撤销；回到原作用域后按服务器订单继续对账。按认证合同恢复账户，禁止将旧组织余额、订单和权益写入新组织。

## 可观察验收

- 默认关闭时三项菜单/直达路由不可用，且没有对应请求；选中但无权限仍不可购买。
- 至少两层分类可展开和选择，父级直属商品不丢失；切分类后迟到报价不能恢复旧商品。
- 服务未提供钱包时不可下单支付；报价失效、余额不足、钱包冻结/币种不符都有明确恢复说明。
- 双击确认、刷新与跨标签页不重复建单/扣款；创建或支付超时后实际成功能通过原请求/订单查询恢复。
- 原订单可续付；已支付/支付中/关闭/过期订单不能再次扣款；关闭弹窗不改变服务端结果。
- 支付期间退出/切组织不污染新作用域；确认成功后刷新当前账户、钱包与订单；账户刷新失败不将支付改判失败。
- 窄屏、键盘、中文/英文、状态播报、失败后输入保留均按 UI 规范验证；Mock 通过不等于真实扣款通过。
