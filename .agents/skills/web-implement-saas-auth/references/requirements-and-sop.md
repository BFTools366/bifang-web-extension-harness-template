# SaaS 认证需求与用户标准操作

本文件是可复用的需求基线，不是已实现的产品或服务契约。下游采用时将本次模式和差异纳入 Product Spec；未提供的 endpoint、密码策略、验证码有效期/限流和账号开通规则由真实服务确认，不填猜测值。

已有基础参考的操作/字段映射与差异见 [API 认证关联](../../../../docs/API.md#认证操作映射)，权限码、可用组织和切换接口见 [客户端契约缺口](../../../../docs/API.md#客户端契约缺口)。采用时复用已确认的用户名/密码规则、验证码场景与秒级倒计时；来源的验证码可关闭、找回会暴露未注册目标及退出吊销全部令牌等差异必须明确处理，不能把参考覆盖说成完整 SaaS 认证已就绪。

## 1. 模式与页面

| 能力                                            | SaaS 客户端 `saas-client`    | SaaS 大后台 `saas-admin`       |
| ----------------------------------------------- | ---------------------------- | ------------------------------ |
| 登录、退出登录、找回密码                        | 必须                         | 必须                           |
| 登录后主 UI、当前用户/头像菜单                  | 必须                         | 必须                           |
| LocalStorage 会话凭据、API header、路由凭据校验 | 必须                         | 必须                           |
| 服务端权限码驱动功能与路由                      | 必须，含当前组织作用域       | 必须，使用服务端后台权限作用域 |
| 邮箱验证码注册                                  | 必须                         | 不提供，账号由既有服务流程开通 |
| 多组织切换                                      | 当前用户有多个可用组织时提供 | 不提供                         |

页面包括登录、找回密码、客户端注册、受保护主 UI，以及加载/网络待恢复/无权限状态。退出登录是头像菜单动作，不是删除账号；如有回调路由只负责完成该动作。具体 URL 沿用下游 Router，不把本文示例操作名当作固定路径。

所有表单提供可见标签、字段错误、提交中状态、防重复提交和可访问反馈；密码允许密码管理器及粘贴，采用正确的 autocomplete。密码、验证码不进入 URL、日志或持久存储。所有产品文案使用既有 i18next。弹窗具有标题、焦点管理、键盘操作和关闭后的焦点恢复。

## 2. 登录 SOP

1. 打开登录页面。无凭据时显示表单；已有凭据先按会话合同校验并获取用户/权限，成功后去可访问的主 UI，防止登录页与主 UI 循环跳转。
2. 填写用户名和密码，点击登录。是否另支持邮箱登录由真实服务决定；前端不自行转换用户名或裁剪密码。前端校验必填及已确认格式，服务端仍负责最终验证。
3. 提交期间禁用重复提交，保留输入并显示进度。认证失败留在登录页，使用可理解且不泄露账号是否存在的提示；验证码、限流、禁用账号按真实错误映射，网络失败不冒充登录成功。
4. 成功响应须通过运行时校验。保存有效会话凭据到 LocalStorage，并装配受管 client；取得当前用户、权限码，以及客户端的当前组织和可用组织清单。凭据写入失败不能声明登录成功，清理临时会话并提示恢复存储后重试。
5. 只有用户与权限上下文就绪才进入主 UI。显示当前用户名称与头像；头像缺失时使用名称缩写等非敏感占位。客户端同时显示当前组织，权限按该组织解释；后台使用服务端返回的后台权限，不从“后台用户”身份推断全权限。
6. 登录后优先返回经过同源内部路径与权限校验的原目标；目标无效或无权限时进入首个可访问首页。完全无功能权限时进入安全的无权限状态，保留退出入口，不在登录和首页间循环。

客户端没有组织时展示“暂无可用组织”与退出入口，不伪造默认组织或自动创建组织。多个组织却没有服务端当前组织时，先完成受控组织选择及上下文获取，再进组织业务；单一组织也需要服务端确认其作用域。

登录已取得凭据但用户/权限获取遇到纯网络问题时，保留凭据并停留在“正在恢复登录/重试”状态；没有已知权限时不显示受保护主 UI。收到会话明确失效响应时执行统一退出流程。

## 3. 退出登录 SOP（两模式）

1. 当前用户打开头像菜单，选择“退出登录”。不使用“注销账号”表示这个动作；删除账号不在此范围。
2. 禁止新的受保护操作，使旧异步结果失效，取消旧用户/组织请求与订阅。若服务提供退出接口，使用当前凭据做一次有界吊销尝试；本地清理不等待服务器永久返回，不自动重复写操作。
3. 无论远端退出成功、已失效或网络失败，移除本应用的会话 Storage 项、内存 Token/continuation、当前用户/组织/权限及私有 Query 缓存，关闭组织弹窗。保留语言/主题等无关偏好，不调用 `localStorage.clear()`。
4. 跳转登录页面，浏览器“后退”也必须经过守卫，不重新显示私有数据。同步其他标签页退出。
5. 网络失败只说明“本地已退出，服务器会话吊销未确认”，不能宣称全部设备已退出。Storage 删除失败按会话合同阻断本地恢复并提示清理，不能谎报持久清理成功。

路由校验失败、当前会话 401、已确认账号禁用/吊销均复用同一个幂等退出流程；只有用户主动退出可以省略会话过期提示。退出接口自己的 401 不递归触发另一次退出。

## 4. 注册 SOP（仅客户端）

1. 从登录页面点击“注册”，进入注册页。填写 **用户名、邮箱地址、密码、邮箱验证码**；邮箱地址是发送和校验验证码所必需的补充字段。
2. 输入有效邮箱，点击“发送验证码”。发送成功后展示重发倒计时和反馈；倒计时、验证码期限及尝试上限来自真实服务契约，前端倒计时不能替代服务端限流。更换邮箱后旧验证码状态失效。
3. 输入与该邮箱、注册用途绑定的验证码，提交注册。用户名/邮箱唯一性、密码策略、验证码正确性/有效期/一次性消费由服务端保证；前端显示对应字段错误。密码确认框可按已选原型提供，不额外强制增加产品字段。
4. 注册失败保留可安全保留的输入，允许修正；验证码过期时引导重发。超时或网络中断不自动重放注册请求，也不宣称注册成功。
5. 注册成功后清除密码/验证码等临时输入，显示成功提示并跳回登录页；可带入用户名，**不自动登录、不持久化注册响应里的会话凭据**。

注册是否自动开通组织、邀请关系或需要审核不在通用基线中推断。没有真实接口前只记录待确认项；大后台既不展示注册链接，也不保留可直达的注册路由或调用分支。

## 5. 密码找回 SOP（两模式）

1. 从登录页点击“忘记密码”，填写账号绑定邮箱并申请找回验证码。发送反馈避免暴露邮箱是否已注册；服务若只支持重置链接，则明确记录其等价流程和差异，不编造验证码 endpoint。
2. 输入找回用途的邮箱验证码、新密码及确认密码，提交重置；两次密码一致且符合真实服务策略。注册验证码不能用于找回，验证码与邮箱绑定、一次性使用及有效期由服务端校验。
3. 错误或过期时留在流程内修正/重发；提交超时不自动重放，不误报成功。
4. 重置成功清除临时密码/验证码，清理当前应用该会话的本地认证上下文，返回登录页，提示使用新密码登录；不自动登录。服务端旧 Token 的吊销范围须由真实契约确认，不能声称已注销所有设备。

大后台没有注册和组织切换，但保留密码找回；如后台服务不支持自助找回，实施前明确缺口和已批准恢复方式，不能留下只会成功提示的假表单。

## 6. 切换组织 SOP（仅客户端）

1. 登录后使用服务端返回的可用成员组织判断入口。**去重后的可用组织数大于 1** 时在头像下拉菜单显示“切换组织”；只有一个或没有可用组织时不展示。
2. 点击后打开选择弹窗，显示可用的其他组织，排除当前组织、已禁用或不再有成员资格的组织。按需刷新组织清单；加载、失败、空结果均有反馈。没有候选时解释原因并允许关闭。
3. 选择目标并确认，显示切换中，禁用重复提交，阻止旧组织的新业务请求；尚未提交前取消弹窗保持当前组织。
4. 请求服务端切换组织。服务器重新检查成员资格，返回新的组织上下文及适用凭据；前端不能仅改本地 organizationId 或从列表猜权限。
5. 切换成功后使旧 scope 失效，取消旧请求/订阅，移除旧组织私有缓存；保存服务端新凭据（若轮换），**重新获取当前用户、当前组织、组织清单和权限码**。全部就绪后才启用新组织业务、关闭弹窗和显示成功反馈。
6. 重新检查原路由权限：新组织仍可访问则重载该页，否则去首个可访问入口或无权限状态。重置组织相关选择、表单草稿和分页，不能将旧组织数据短暂呈现给新组织。
7. 切换被明确拒绝且服务器确认原会话未变时保留原组织并显示错误；若服务器可能已切换（提交超时、响应丢失）或切换后取用户失败，停在受保护的“组织上下文恢复中”，重取权威上下文，**不直接回滚旧组织继续请求**。认证失效则统一退出。

组织切换是会话作用域变化，纯网络容错只保留凭据，不允许跳过新组织用户/权限初始化。跨标签页同时登录/切换的处理见会话合同。

## 7. 路由校验与权限操作

- 每次实际路由导航先校验当前凭据，再判定目标权限，最后运行受保护 loader/API 和呈现页面；刷新、直接输入 URL、前进/后退和 search/params 导航同样覆盖。预取及页内纯锚点不当成实际导航；公共登录/注册/找回页使用公开流程，避免守卫自循环。
- 校验成功后使用该会话/组织的用户与权限；接口若返回更新过的上下文或权限版本，原子应用并重判当前目标。校验接口返回错误则走统一退出；纯网络问题默认保留当前凭据，仅复用同一 scope 已加载权限，显示网络状态。取消和被新导航取代的请求不注销新会话。
- 首次恢复只有 LocalStorage Token，没有已加载用户/权限时，即使纯网络失败也停在重试状态，不把未知权限视为允许。
- 服务端权限码驱动菜单、按钮、操作入口和路由。被禁用的可见控件说明原因；隐藏/禁用选择沿用产品规范。用户手输 URL、深链接和直接调用操作也必须检查权限，服务端继续鉴权。
- 缺失、空或未知权限默认无授权；`all`/`any`、通配符和后台超级管理员语义须显式声明，不能自行猜测。客户端权限还需匹配当前组织；业务 403 显示无权限并按需重取权限，不把它当成通用退出信号。

## 8. 可观察验收标准

| 场景                                      | 预期结果                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------- |
| 两模式正常登录                            | 凭据持久写入、API 正确带 header，用户/权限就绪后进入主 UI并显示当前用户 |
| 刷新、直达、历史与 search 导航            | 先完成当前导航校验及权限判断，私有 loader 无抢跑                        |
| 校验返回错误 / 纯网络失败 / 导航取消      | 分别统一退出 / 保留凭据和同 scope 已知权限 / 安静忽略旧工作             |
| 冷启动离线、未知或空权限                  | 无越权闪屏；提供重试或无权限状态                                        |
| 退出及退出接口断网                        | 本地会话和私有缓存清理，后退不恢复；不误报远端吊销                      |
| 注册与密码找回                            | 验证码绑定用途/邮箱；成功返回登录，不自动登录；失败不假成功或自动重放   |
| 多组织与组织切换                          | 入口条件正确、弹窗排除当前组织；新用户/权限重取、旧缓存与迟到结果隔离   |
| 切换结果不确定                            | 阻断组织业务并恢复权威上下文，不沿用旧权限                              |
| 功能/路由权限与普通 403                   | 控件和深链接一致受控；服务端拒绝仍显示权限反馈、保留会话                |
| 大后台负向路径                            | 注册和组织切换的入口、直达路由、请求均不存在                            |
| Storage 损坏/拒绝、凭据轮换、多标签页竞态 | 不假保存、不复活旧会话、不串用户或组织；详见会话合同                    |

此表用于下游开发回归和需求对照，实际覆盖按任务报告；本 Skill 文件和 Mock 检查不证明服务端、真实浏览器或最终候选通过。
