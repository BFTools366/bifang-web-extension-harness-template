# SaaS 会话、路由与权限实施合同

适用 `projectType=web` 且已明确采用 `saas-client` 或 `saas-admin` 的认证功能。默认 HTTP client 仍持有内存 Token/continuation；本文件只规定 SaaS feature 如何协调 LocalStorage 与该 client，不提供现成产品代码或真实 endpoint。

采用已收录服务时，先核对 [API 操作与字段](../../../../docs/API.md#认证操作映射) 和 [协议与会话适配](../../../../docs/API.md#协议与会话适配)，再确认真实契约。profile 可作为经确认的导航校验候选，但不返回权限码，默认组织也不证明当前组织/成员资格；GraphQL `health` 或仅 HTTP 200 不能用作凭据校验。接口存在 refresh 不改变本文件“校验返回错误即退出、不自动 refresh/replay”的边界。

## 1. 状态与所有权

认证 feature 是唯一会话协调者，负责恢复、登录、持久化、凭据轮换、当前用户/权限、退出、导航校验和组织切换。数据层负责 Storage 与类型化 API；Router 负责导航，Query 负责当前用户等远端状态。不要把同一份用户/权限复制进 Jotai 或 LocalStorage。

采用可观察状态而不是多个互相矛盾的布尔值：匿名、恢复中、已认证、网络暂不可校验、组织切换/恢复中、退出中。网络暂不可校验仅表示按用户要求保留凭据，不是服务器已证明有效；它必须区分是否已有同 scope 用户与权限。

- 会话 scope 至少区分用户、模式、服务环境/target，客户端再包含组织；Query key 仅使用这些非敏感标识，不含 Token。
- 会话 generation/revision 与当前导航 ID 共同保护每次副作用。登录、退出、切组织或外部标签页改变会话使旧工作失效；await 后再次核对，不让迟到响应/401/handler 覆盖新会话。
- 认证状态只在所有必需步骤完成后呈现；登录尚未完成、组织不明、权限未知时不挂载私有业务内容。

## 2. LocalStorage 限定例外

两种 SaaS 模式的服务端会话凭据必须跨刷新持久保存，使用 `src/data/storage/` 与已有 `getWebStorage("local")`，不新增第三方存储依赖。普通 Web、Extension 和基础生成 client 不自动持久化。

- Key 使用项目 ID、模式、环境/受控 target 和 schema 版本隔离，例如 `<project-id>:auth:<mode>:<target>:v1`；具体命名在下游确定后保持兼容。相同 origin 上不能让客户端与后台互读同一个默认 key。
- 单项版本化记录仅含必要的有效凭据、真实协议规定的 token type/expiry 和校验所需的最小 scope 标识。默认只需访问凭据；服务要求刷新凭据时再明确其持久化范围与生命周期，不从返回字段自动启用 refresh/replay。
- 不保存密码、验证码、整个登录响应、用户档案、权限码快照或 continuation；不凭 JWT 解码结果/本地 expiry 授予权限。服务提供的过期信息可提前阻止过期使用，服务器校验仍为权威；未知格式的 opaque Token 不按 JWT 解析。
- 所有读入按未知数据检查版本、字段、范围、有界字符串和 header 可编码性；损坏记录按无可用会话处理并尝试删除。不信任 DevTools 或脚本写入的数据，也不输出原值。
- 登录/轮换先校验响应，完成可核实的持久写入和受管 client 更新后才能公布新会话。写入失败阻断登录或新作用域，撤销临时内存会话并显示可恢复错误；不静默降级成“已持久登录”。
- 退出移除精确 key 并验证结果，设置当前上下文的禁止恢复状态。若删除失败，清空内存和私有 UI、阻止本标签页重新读取旧记录，提示用户清理站点存储并提供重试；尽力吊销服务器会话，但不得声称刷新后也能保证清理。删除成功或新登录经过完整流程后才能解除该恢复阻断。

LocalStorage 可被同源 JavaScript 读取，XSS 可窃取凭据；客户端加密且密钥也在前端不能消除此风险。采用此方案是当前用户明确选择的范围例外，不能描述为安全存储。实际下游须避免不可信 HTML/脚本、使用合适 CSP/HTTPS、对认证响应采用服务端 no-store，并控制第三方脚本。风险参考 [OWASP HTML5 Security](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage)；访问拒绝及持久语义参考 [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。不因本 Skill 自动访问生产或改变部署策略。

## 3. HTTP 与凭据同步

- 每次发送请求时从当前受管会话取 Token；基础请求头为 `X-AUTH-TOKEN`。若真实服务要求 `Authorization: Bearer` 或其他格式，实施明确的服务适配层，保证不会同时发送冲突请求头。仅设置 BaseURL 或 凭据提取器 不会改变默认请求头。
- 只有批准的 API target 可以接收凭据；公开登录/注册/验证码/找回操作不带残留旧会话凭据，公开操作自身的认证失败不触发受保护会话的 401 退出 handler。使用可显式隔离认证注入与失效副作用的受控公开请求边界；现有 client 不具备所需能力时在实施中补齐并测试，不能仅传空请求头 假设会覆盖动态注入。不对任意第三方 URL、跳转地址发送 Token。
- 登录/恢复调用已校验的 `applicationHttp.setAuthToken`；退出调用 `clearSession`。自动提取器保持只读，不写 Storage 或导航。真实服务会轮换 Token 时，先为**已被 client 接受的当前 revision**增加受控同步适配，由唯一协调者持久化；不能将任意 2xx 响应头 或迟到提取结果写入 LocalStorage。当前基础不承诺已有持久化订阅接口。
- 轮换存储失败必须阻断继续使用未经持久确认的新上下文并进入退出/恢复处理；不保留一个 UI 声称有效、刷新却恢复旧 Token 的半会话。
- 普通受保护请求的当前 401 经既有 single-flight 触发统一退出；普通 403 保留会话并处理权限。认证域确认的账号禁用/吊销可映射为退出原因，不把所有业务 403 当成失效。
- 凭据刷新、401 自动重放及组织切换重试不在默认范围。只有真实契约与授权明确需要时加入一个有界的协调者；写操作不自动重放，超时不代表服务器没有执行。

## 4. 导航凭据校验

在受保护导航的 `beforeLoad` 完成校验与授权后才放行 loader/页面，不能先呈现再用 effect 检查。

1. 启动读取当前模式/target 的 Storage 记录，校验形状，建立 client 内存上下文；没有凭据则进入匿名流程并保存安全的内部 return target。
2. 每次实际导航调用真实凭据校验操作，不使用 Query 的长 staleTime 把旧成功当成“本次已校验”。同一次导航内的嵌套路由可共享 in-flight Promise；不同导航、不同 Token revision、不同组织不得复用旧结果。预取不替代真正导航的校验。
3. 成功后按契约获取或更新当前用户、组织与权限；只检查 Token 的接口不等于已取得权限，必须补齐上下文。每次凭据轮换遵循上一节。
4. 对目标执行当前 scope 权限规则。再核对会话和导航仍有效，才加载业务；不允许的目标显示无权限或转到确定可访问入口。

| 校验操作的结果                                                  | 必须执行的动作                                                                         |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 合法成功响应                                                    | 使用已校验上下文继续权限判断                                                           |
| 返回 HTTP/业务错误，包括 401/403、429/5xx；或成功报文不符合约定 | 按用户“返回错误时注销”要求统一退出，不回退 Mock 或沿用旧成功；此策略仅针对凭据校验操作 |
| 传输层 network/timeout，未取得 HTTP 响应                        | 默认保留当前凭据，显示暂不可校验；仅有同一用户/组织已加载权限时放行其原有授权范围      |
| 纯网络失败且冷启动/新登录/新组织尚无上下文                      | 保留凭据，停在恢复/重试状态，不能创建用户、组织或权限                                  |
| AbortSignal 取消、被后续导航/会话替代                           | 放弃旧工作，不清理新会话、不播报注销                                                   |
| 本地配置、编码、程序或未知异常                                  | 阻断导航并显示可恢复错误，不归类为断网，也不让旧任务清理新会话                         |

浏览器通常不能从无响应的 Fetch 异常精确区分断网和 CORS；实施依据统一 `ApiError.kind` 的 network/timeout 分支做“不确定时保留凭据”，不能声称已经证实纯网络，也不能把 HTTP 错误、协议错误、配置错误全部 catch 为有效。此容错只影响客户端会话连续性，服务端继续逐请求鉴权。

校验 endpoint 不经过依赖它自己的受保护守卫。公共页、登录成功跳转、退出跳转和权限拒绝要防止循环；return target 只允许真实应用内路由，拒绝外站、协议相对 URL 和权限不符目标。

## 5. 权限与组织原子边界

- 真实服务提供权限码集合和作用域；定义 route/action 的 `all` 或 `any` 要求。未声明为公开的功能不能因遗漏配置默认放行；未知码、空集和无权限响应不产生授权。通配符/超级管理员须经明确契约，不靠角色名称猜测。
- 菜单、按钮、路由守卫和操作处理函数复用同一权限判定；URL 直达和代码触发操作也受控。UI 权限只改善体验，后端仍按账号与组织验证每次请求。
- 组织切换后重新取用户、组织、成员组织及权限；Query key、订阅与 UI 草稿同步换 scope。用户/权限加载失败时不能拼接“新组织 ID + 旧权限”。切换结果不确定先恢复权威上下文，再决定继续或退出。
- 新权限撤销当前页时阻断继续操作并转可访问入口；旧组织成功响应、旧权限读取、迟到 401 和 mutation 回调均不能提交进新 scope。
- 未授权错误导致权限重取时使用单一有界流程；没有权限和无法取到权限均不得构造管理员默认集合。

## 6. 多标签页与退出收敛

同一 key 的会话在同源标签页共享。通过受控 `storage` 事件处理其他页的退出、重新登录、轮换和组织变化；事件不在写入页自身触发，写入页也必须同步运行协调逻辑，见 [MDN storage event](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event)。

- 事件处理时重新读取并校验当前记录，不将事件载荷当作可信授权。外部会话变化先失效本页旧请求/缓存与权限，再校验及获取新上下文；不能继续显示旧用户或组织的私有数据。
- 退出移除记录时其他页也退出；切组织或新登录时其他页进入上下文恢复。同一存储 scope 不支持各标签页各自保持不同组织；若产品需要，须明确改变存储/服务契约，而非悄悄增加第二个 owner。
- 内存 revision 只能保护单页，LocalStorage 没有跨标签页 CAS/事务。实施须明确跨页排序/写入协调策略（按真实浏览器能力选择原生机制），并在发布新凭据、发起受保护请求前核对当前存储 scope；迟到轮换不能复活已退出的记录。无法可靠协调时阻断冲突并要求重新认证，不用时间戳比较冒充原子性。
- 每个注销/导航副作用前复核当前 generation；统一退出只执行一次。取消旧私有 Query、移除旧缓存、停止订阅，Storage/内存/HTTP/UI 四方收敛后才恢复操作。

## 7. 实施回归重点

按当前改动覆盖成功和最高风险失败；需要验证时使用既有 Vitest/Testing Library，不引入全局工具。

- 正常登录、刷新恢复、Storage 写入/读取/删除拒绝与损坏记录、模式/target 隔离、轮换后刷新取得新凭据。
- 真实请求边界的 header 编码、公开接口不带旧 Token、受控 target；日志/URL/Query key 无秘密，continuation 未持久化。
- 导航先校验后 loader，历史/深链接/search 导航，取消/并发/迟到 401 不清新会话；校验服务错误退出，network/timeout 容错不新增授权，冷启动离线阻断。
- 普通业务 403 保留会话，未知/空权限拒绝，UI/路由/动作一致；无权限首页无跳转循环。
- 客户端组织入口条件、排除当前组织、服务确认、新用户/权限重取、缓存/订阅/草稿隔离；切换后上下文请求失败与切换结果不确定时均阻断旧权限。
- 退出接口失败仍本地退出、退出自身 401 不递归，删除失败不假报清理；多标签页退出/轮换/切组织与竞争写入不复活会话。
- 客户端验证码注册与两模式找回的成功返回登录、错误/过期/重发及提交超时；大后台无注册或组织切换的可达路由和 API 分支。

只有需求/SOP 记录时对照上述合同，不伪造这些代码测试已通过。真实服务、CORS/Storage 浏览器行为与最终候选按各自事件执行，未执行时如实报告。
