# API 与业务文档导出合同

## 文件布局与聚合

默认 `docs/api/` 为可整体交接的导出根，指定其他目的地时保持内部布局：

```text
README.md
api/
  common.md
  metadata.md
  <business-domain>.md
business/
  <business-domain>.md
```

API 固定 1 份通用结构、1 份元数据、N 份聚合接口；业务按完整用户目标聚合，不要求一一对应。操作用稳定锚点定位。只有独立参与者、权限边界或独立生命周期确有必要时拆域，不按源码目录、函数、版本或子步骤拆分。共同完成一个目标的小域可合并，不设置机械文件数或行数目标。不增加每轮导出报告、代码清单、版本子目录或额外合并文件。

纯本地项目允许 N=0：通用结构说明“无远端共享结构”，元数据说明无远端 API，业务描述真实本地流程。无任何可记录内容不制造空包。

## 根关联说明

`README.md` 提供用途、覆盖范围、阅读顺序，以及关系表：`业务目标 | 业务文档 | API 文档 | 关系说明`。每份域 API 与业务文档必须被索引，通用结构与元数据也有链接；纯本地流程标明“无远端 API”；契约未接入或无调用方的 API 域标明状态，不编造业务文档。

包内文档相对链接允许作为导航；客户端代码路径、源码链接、磁盘绝对路径、函数/类/组件名、导入语句、实现代码及测试路径不得进入任何导出正文。HTTP 相对路径、GraphQL operation 与 wire 字段属于协议事实，允许展示。可信外部服务规范可链接；本地 Schema 路径改成“采用的服务 Schema”等依据类型。

## 一份通用数据结构

`api/common.md` 汇总实际采用的共享成功/空结果/数据集/分页/异常、公共标识与时间；区分不同服务协议，不强加单一封装。JSON 示例与字段表沿用协议格式，已定义但暂无调用的固定模型保留并标明状态；域特有 DTO 留在域文档。

## 一份 API 元数据

`api/metadata.md` 集中收录：

- API 用途、协议类型、相对路径约定与合同依据类型。
- 版本表：`API 版本 | 状态 | 操作范围 | 兼容/弃用说明`。保留合同或实现的实际版本名，v1…vn 只是示例，日期或 SemVer 等版本不改名；没有版本依据写“未声明版本”，操作标识用 `unversioned-`。不将应用构建版本充当 API 版本，不造不存在的版本。
- 操作目录：`操作标识 | 接口名称 | 版本 | 操作类型 | 协议 | 实现状态 | 接口文档 | 关联业务`。每个操作一行，首列为稳定标识；操作类型使用 `列表查询|条件查询|单对象查询|写操作|其他`，协议使用 `GraphQL|REST|其他`，按实际执行或已采用合同登记，不由 HTTP/Mock 状态代替协议。分别标 HTTP、产品 API Mock、契约未接入、设计建议；无消费者写“当前无客户端调用方”，未接入写“尚未形成已实现流程”。
- 通用请求头/认证、错误分类、分页约定等补充；共享 JSON 结构链接到通用结构，不另导出客户端工具文档。
- 本次同步：核对范围、首次导出/新增/变更/移除/无差异、关键语义变化与未确认项。局部同步写明其余范围未核对；仅保留当前结果，不累加历史，不记 Git、时间戳、摘要或源码路径。

每个操作使用唯一稳定 ASCII kebab-case 标识，例如 `v1-items-list`，跨版本标识不同；非 kebab-case 的实际版本只在操作标识中转为稳定前缀，元数据版本列保留原名。域文档在操作前放 `<a id="v1-items-list"></a>`，其后仍为 REST 六项或 GraphQL 格式。元数据关联目标为 `items.md#v1-items-list`，业务步骤关联目标为 `../api/items.md#v1-items-list`（使用普通 Markdown 链接）；目录首列标识必须与接口目标锚点一致，每个操作唯一登记，不收录不存在的标识；“关联业务”反向链接到业务文件。标识不是本地函数名，也不是新增 wire 字段。

列表查询与条件查询（其他带业务查询条件的 GET 类读取）必须 GraphQL；单对象查询（无业务查询条件或路径 ID 详情）、写操作和其他请求必须 REST。按 [列表查询协议强约定](../../../../docs/DATA_ACCESS.md#列表查询协议强约定) 识别。元数据检查实际操作类型与协议，不符合时失败；旧实现如实记录差异，设计建议与实现事实分开，纯本地流程不伪造远端操作。

## 多份业务描述

每份 `business/<domain>.md` 按复杂度采用或合并以下章节，不能留下占位：

1. **业务目标与范围**：用户结果、参与者、入口条件和已实现边界。
2. **调用流程**：触发动作 → 业务校验/分支 → 顺序或并行调用 → 状态变化 → 用户结果；每次实际调用链接到操作锚点，说明条件、依赖和用途。可用 `步骤 | 条件/动作 | 接口 | 结果/下一步` 表格，简单流程用自然语言。
3. **异常与恢复**：源码证明的拒绝、空态、失败、取消、重复操作、结果未知与恢复，不补造不存在分支。不将客户端隐藏入口写成服务端授权保证。
4. **设计思路与边界**：用业务语言说明真实编排的目的与取舍。已有明确设计依据直接说明；仅由行为推导标“从当前行为推导”；理由不足写“设计理由未确认”。缓存写成“成功后重新获取列表以展示最新状态”等效果，不介绍框架、hooks 或缓存键。

纯本地流程明确不调用远端接口；混合流程区分真实本地步骤与远端 Mock。Mock 消费者可以是真实已实现编排，但必须写明远端当前为 Mock，不能宣称服务端已上线。未实施 PRD 流程不输出为已实现业务，只在 API 元数据标设计状态。

## 差异与旧布局迁移

每轮核对接口协议与实现/采用合同，以及已实现编排与旧业务文档两条差异链；机械检查通过不能证明语义同步。

- 首次也找旧文档与人工补充，新增操作标首次登记。
- 旧 `docs/api/<module>.md`、`common.md`、`client.md` 与索引先归类后合并。协议说明迁元数据，业务规则迁业务描述，共同目标的碎片接口合并；有效未接入契约/设计保留。
- 修改/移除操作同步步骤、反向目录与根关系；版本弃用与停止调用分开。更新旧链接；仅确认由此前导出维护且有效内容全部迁移后才移除旧文件。未知归属或冲突保留并报告，迁移未完成不能声明完整导出。
- 局部保留无关文件与人工说明，检查全部受影响引用。共享模型变化同步真实依赖，或报告未完成范围，不能静默留下漂移。
- 最后逐项核对 JSON 与字段表、操作覆盖/版本状态、步骤顺序/条件、错误/恢复、设计理由与多对多关联。内部证据矩阵只留当前上下文或包外临时文件，不进交付包。

## 机械检查边界

`scripts/check-export.ts` 只读检查规范布局、空文件、相对 Markdown 链接/显式锚点、索引与双向操作关联、JSON 语法及明显代码/路径泄漏。使用普通内联 Markdown 链接和显式操作锚点，不使用引用式链接代替关联。

标准反引号与波浪线围栏均检查；围栏、行内代码及 HTML 注释中的示例不登记为真实链接或操作锚点。JSON 与六列字段表中一致的 wire 示例值可以包含业务资源名，不因此误判为源码引用；表格其他说明仍检查。

检查不能证明源码覆盖、字段表完整、REST 六项、版本真实性或设计意图，执行 Agent 必须语义复核。未完成核对、冲突或检查失败不得宣布同步完成。
