# Web Harness：从代码整理 API 文档

把当前代码能证明的 API 行为整理为 `docs/api/<module>.md`，每个模块独立成文，以 `docs/api/README.md` 提供索引。代码是行为事实来源；文档说明当前实现与尚未确认的边界。

## 适用边界

- 仅在存在 `.harness/project.json` 且 `projectType=web|extension` 的下游执行文档生成。源 Harness 只维护本 Skill，不在源中接收或整理具体产品接口。
- 默认整理当前项目全部 API 模块；用户或调用方限定模块时只更新该范围和必要索引。实现/HTTP 流程同步文档时必须传入受影响范围。只写文档，不修改 API、测试、配置、权限或依赖，不启动服务或请求远程接口。
- `docs/API.md` 是可选基础契约参考，不能证明当前接口已实现；保留它，不自动迁移、拆分或覆盖其来源正文。只有当前代码实际采用的部分才进入模块文档。

发现参考契约与实现冲突、需要独立核对时调用 `$web-review-api-contract`，传入当前模块和已有源码证据，复用其差异清单后继续文档生成；常规反向文档整理不强制增加审查。

## 从实现建立模块清单

1. 读取项目入口、工程规则和 Git 状态，保护已有文档修改。先用 `rg --files src/data/api` 查找 API 实现，再追踪公开导出、重导出、请求封装、请求/响应类型、运行时校验与相关测试；API 位于其他路径时按真实调用关系定位，不为了约定移动源码。只按需读取数据访问或运行配置规则，不收集环境文件中的实际凭据和服务地址。
2. 按已有业务域或 API 模块边界归组，同一模块的类型、实现、Mock 和 barrel 属于同一份文档，不按每个源码文件或函数拆文档，也不把重导出算作重复接口。公共 `src/data/api/client/` 有可用导出时独立写 `client.md`，不替业务域虚构 endpoint；没有业务模块时如实说明。
3. 逐个公开操作追踪到实际执行路径，记录导出名、实现文件、类型、相关测试，以及 HTTP、Mock 或其他已存在的传输方式。混合模块按操作标明方式；调用方包装和底层传输分别说明，不能仅凭函数名、注释或参考文档认定方法、路径、鉴权和服务端行为。
4. 模块文件名沿用有效既有名称；新文件使用稳定的模块标识。不同域同名时保留目录层级，例如 `docs/api/admin/users.md` 与 `docs/api/customer/users.md`，避免覆盖。索引只链接真实存在的模块文档。

## 每个模块写什么

模块保留以下事实，公开 REST 与 GraphQL 操作分别遵循下方固定展示格式；无依据的字段明确写“代码中未确认”，不填猜测值或空模板。模块文档可引用公共 client 约定，但应保留理解本模块所需的信息。没有 endpoint 的公共工具与纯 Mock 不套造 HTTP 接口。

- **模块概览与来源**：职责、公开操作清单、传输方式、源码/类型/相关测试的相对链接与符号名。记录整理日期；Git 可用时记录基准提交，并明确有无范围内未提交修改，不能把工作区内容冒充该提交的内容。
- **调用与请求**：函数签名；代码明确的方法和路径、服务 target 或配置键；路径参数/查询参数/请求头/请求体的位置、字段类型、必填与可空区别、默认值、枚举、单位及实际校验。动态路径无法静态确定时保留表达式和未知部分，不猜完整 URL。区分 TypeScript 类型约束、客户端运行时校验与服务端校验。
- **响应与映射**：成功返回类型、字段、嵌套结构、可空/可选语义、已知状态码，以及 wire DTO 到域模型的转换；分页写清外部字段到 `page/pageSize/items/total` 的映射。只有客户端返回类型时不能反推服务端原始报文。
- **认证、错误与副作用**：实际请求头与会话所有者、错误分类/错误码及触发条件、timeout/取消/重试等继承行为；列明实际写入或缓存失效。客户端 401/403 处理不能证明服务端角色策略，未知权限、限流、幂等性和服务端错误码保持未确认。Extension 按实际执行上下文说明接口，不推断跨上下文共享状态或双目标运行通过。
- **调用或报文示例**：采用与类型和代码一致的最小示例，使用虚构且脱敏的数据；区分测试 fixture、Mock 返回和根据类型构造的说明示例。没有执行网络请求就不能标为实测报文，不复制真实 Token、Cookie、密码、个人数据或环境值。
- **待确认与差异**：缺失实现、动态分支、参考契约与代码冲突及未覆盖行为。实现与注释/旧文档不一致时依据实现更新描述并报告差异；仅存在 Mock 时文档写成 Mock API，不编造 HTTP 方法、URL、状态码或服务端保证。

### REST 文档格式

每个接口按以下六项依次展示，栏目名称统一使用中文，不能只列函数签名或请求示例。实际 HTTP 方法值（如 `GET`、`POST`）、请求头名称及报文字段名保留协议和代码中的原名，不翻译技术标识符：

1. **接口名称**：可读名称与对应公开操作/符号，模块内能唯一定位。
2. **接口说明**：用途、调用条件、对象/作用域及已确认的副作用；说明当前为真实 HTTP 还是 Mock。权限与服务端保证只写有依据的事实。
3. **请求路径**：相对路径及服务 target/配置键；动态段保留实际表达式。存在路径/查询参数时单独用字段表说明位置、类型、必填、默认值与约束，不把它们写成 JSON 请求体，不展开真实环境地址。
4. **请求方法**：实际 HTTP 方法，使用 `GET`、`POST` 等标准写法；无法确认时明确标注，不根据操作名推断。
5. **请求头**：表格列为 `名称 | 必填 | 值或格式 | 说明`。覆盖当前接口实际发出的 Content-Type、认证、语言、追踪等请求头；已确认的响应头在本项下另列“响应头”表，明确方向。继承公共 client 时注明来源与动态提供者。敏感值只展示格式和脱敏占位，不填真实凭据，也不把未出现的请求头当作必填。
6. **请求与响应数据**：默认按 JSON 契约，用字段表分别展示**请求数据、成功响应数据、错误响应数据**；保留已知 HTTP 状态、响应封装与传输数据结构到域模型的映射。表格是主要说明，JSON 示例只能补充，不能代替字段表。

请求与响应数据的字段表统一使用 `字段路径 | JSON 类型 | 必填/必有 | 可空 | 说明与约束 | 示例值`：

- 请求的“必填”和响应的“必有”分别判断；字段缺省与值为 `null` 分开，不能将 TypeScript 可省略字段当作可空字段。默认值、枚举、长度/范围、单位、精度和校验依据写入“说明与约束”。
- 嵌套字段使用 `data.account.id`、`items[].id` 等清晰路径，并列明对象/数组父节点；顶层数组或原始 JSON 值使用 `$`，数组元素用 `$[]`。字符串、数字、布尔、对象、数组及 null 按实际 JSON 表达，示例值本身使用合法 JSON 表示。
- 判别联合按实际判别字段 分表或明确标出各分支，避免把互斥字段混成一组可选字段。已知错误结构同样用表格展示，另列错误码与触发条件；只确认客户端错误时，不反推服务端原始错误 JSON。
- 无请求体写“无请求数据”，无响应体写“无响应数据”；不能补造 `{}` 或 `null`。真实实现使用纯文本、multipart、二进制或事件流时，在“请求与响应数据”项如实注明实际格式及 JSON 不适用，不为了文档统一修改接口或伪造 JSON。只有域返回类型时，表格明确标为客户端结果，服务端原始报文保持未确认。

### GraphQL 文档格式

每个公开操作同样先展示**接口名称**和**接口说明**；名称关联实际 operation/根字段，说明用途、调用条件、作用域与实现方式。契约主体使用 `graphql` 代码块中的 **Schema SDL**，不能只用 TypeScript 类型、字段表或 query 示例代替 Schema。

- 从当前项目可信的 Schema、生成输入或已采用且可追溯的服务契约取得 SDL。按真实操作展示对应 `Query`、`Mutation` 或 `Subscription` 根字段、参数和返回类型；不因文档格式新增未实现的操作类型。
- 展示理解该操作所需的 object、input、enum、scalar、interface、union 与依赖类型；递归类型避免重复展开。截取模块契约时明确标为 Schema 子集，其他依赖链接到真实存在的 Schema/模块文档，不能声称是完整服务 Schema。
- 准确保留 `!`、列表与元素可空性、默认值、已知 description/directive 和弃用信息；区分 `[T]`、`[T!]`、`[T]!`、`[T!]!`。输入参数/字段只有非空且无默认值时才必须提供；自定义 scalar 的单位、格式与序列化语义依真实契约说明，未知处保持未确认。
- 只有客户端 query/fragment、TypedDocumentNode 或 TypeScript 结果类型时，明确“服务端 Schema 未确认”，另列已有 operation 文档与源码依据；不能从选择集反推服务端完整类型、nullability 或参数默认值，也不能把 operation 文档标成 Schema。
- Schema 之外仍说明实际接口地址、请求方法/请求头、operationName、variables、返回映射，以及 HTTP/GraphQL 错误与 partial data 策略。JSON variables/响应需要字段说明时复用上述请求与响应数据字段表规则；query/fragment 示例只作调用补充。未确认 Mutation、Subscription 或推送协议时不宣称支持。

## 增量更新与核对

- `docs/api/README.md` 列出模块、职责、文档链接和实现方式；限定模块更新时保留其他有效索引项及人工补充。文件开头区分代码派生事实与有来源的外部说明，不把未确认说明升级成代码事实。
- 已移除或改名的操作同步更正文档与索引。对不再有实现的模块文档明确标记历史/待确认并从当前模块清单移出；不批量删除用户文档或覆盖无法安全合并的编辑，存在冲突时先保留并报告。
- 对照模块清单逐项核查公开操作覆盖、参数、返回、错误、Mock 标识、来源符号与相对链接；REST 核查“接口名称、接口说明、请求路径、请求方法、请求头、请求与响应数据”的中文栏目及顺序，以及请求/成功/错误 JSON 字段表；GraphQL 核查名称/说明、Schema 来源、依赖类型与可空语义。确认没有将同一操作的重导出重复登记。没有可记录的模块时说明扫描范围和结果，不创建空的模块模板。
- 纯文档整理只做链接、差异和与源码逐项对照所需的最小检查；不自动构建、全量测试、浏览器验证或联网。未运行相关测试时，只能说“读取测试作为依据”，不能声称测试通过或接口可用。

## 完成输出

报告索引和模块文档路径、覆盖模块与操作、发现的差异和待确认项、实际检查及未执行项。生成文档不等于接口联调或最终产物验收，不自动创建 PRD、ADR、Status、Work Plan 或 Verification。
