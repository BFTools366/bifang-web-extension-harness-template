# Web Harness：从代码整理 API 文档

把当前代码能证明的 API 行为整理为 `docs/api/<module>.md`，每个模块独立成文，以 `docs/api/README.md` 提供索引。代码是行为事实来源；文档说明当前实现与尚未确认的边界。

## 适用边界

- 仅在存在 `.harness/project.json` 且 `projectType=web|extension` 的下游执行文档生成。源 Harness 只维护本 Skill，不在源中接收或整理具体产品接口。
- 默认整理当前项目全部 API 模块；用户限定模块时只更新该范围和必要索引。只写文档，不修改 API、测试、配置、权限或依赖，不启动服务或请求远程接口。
- `docs/API.md` 是可选基础契约参考，不能证明当前接口已实现；保留它，不自动迁移、拆分或覆盖其来源正文。只有当前代码实际采用的部分才进入模块文档。

## 从实现建立模块清单

1. 读取项目入口、工程规则和 Git 状态，保护已有文档修改。先用 `rg --files src/data/api` 查找 API 实现，再追踪公开导出、重导出、请求封装、请求/响应类型、运行时校验与相关测试；API 位于其他路径时按真实调用关系定位，不为了约定移动源码。只按需读取数据访问或运行配置规则，不收集环境文件中的实际凭据和服务地址。
2. 按已有业务域或 API 模块边界归组，同一模块的类型、实现、Mock 和 barrel 属于同一份文档，不按每个源码文件或函数拆文档，也不把重导出算作重复接口。公共 `src/data/api/client/` 有可用导出时独立写 `client.md`，不替业务域虚构 endpoint；没有业务模块时如实说明。
3. 逐个公开操作追踪到实际执行路径，记录导出名、实现文件、类型、相关测试，以及 HTTP、Mock 或其他已存在的传输方式。混合模块按操作标明方式；调用方包装和底层传输分别说明，不能仅凭函数名、注释或参考文档认定方法、路径、鉴权和服务端行为。
4. 模块文件名沿用有效既有名称；新文件使用稳定的模块标识。不同域同名时保留目录层级，例如 `docs/api/admin/users.md` 与 `docs/api/customer/users.md`，避免覆盖。索引只链接真实存在的模块文档。

## 每个模块写什么

按实际接口选择以下内容；无依据的字段明确写“代码中未确认”，不填猜测值或空模板。模块文档可引用公共 client 约定，但应保留理解本模块所需的信息。

- **模块概览与来源**：职责、公开操作清单、传输方式、源码/类型/相关测试的相对链接与符号名。记录整理日期；Git 可用时记录基准提交，并明确有无范围内未提交修改，不能把工作区内容冒充该提交的内容。
- **调用与请求**：函数签名；代码明确的方法和路径、服务 target 或配置键；path/query/header/body 的位置、字段类型、必填与可空区别、默认值、枚举、单位及实际校验。动态路径无法静态确定时保留表达式和未知部分，不猜完整 URL。区分 TypeScript 类型约束、客户端运行时校验与服务端校验。
- **响应与映射**：成功返回类型、字段、嵌套结构、可空/可选语义、已知状态码，以及 wire DTO 到域模型的转换；分页写清外部字段到 `page/pageSize/items/total` 的映射。只有客户端返回类型时不能反推服务端原始报文。
- **认证、错误与副作用**：实际请求 header 与会话所有者、错误分类/错误码及触发条件、timeout/取消/重试等继承行为；列明实际写入或缓存失效。客户端 401/403 处理不能证明服务端角色策略，未知权限、限流、幂等性和服务端错误码保持未确认。Extension 按实际执行上下文说明接口，不推断跨上下文共享状态或双目标运行通过。
- **调用或报文示例**：采用与类型和代码一致的最小示例，使用虚构且脱敏的数据；区分测试 fixture、Mock 返回和根据类型构造的说明示例。没有执行网络请求就不能标为实测报文，不复制真实 Token、Cookie、密码、个人数据或环境值。
- **待确认与差异**：缺失实现、动态分支、参考契约与代码冲突及未覆盖行为。实现与注释/旧文档不一致时依据实现更新描述并报告差异；仅存在 Mock 时文档写成 Mock API，不编造 HTTP method、URL、状态码或服务端保证。

## 增量更新与核对

- `docs/api/README.md` 列出模块、职责、文档链接和实现方式；限定模块更新时保留其他有效索引项及人工补充。文件开头区分代码派生事实与有来源的外部说明，不把未确认说明升级成代码事实。
- 已移除或改名的操作同步更正文档与索引。对不再有实现的模块文档明确标记历史/待确认并从当前模块清单移出；不批量删除用户文档或覆盖无法安全合并的编辑，存在冲突时先保留并报告。
- 对照模块清单逐项核查公开操作覆盖、参数、返回、错误、Mock 标识、来源符号与相对链接；确认没有将同一操作的重导出重复登记。没有可记录的模块时说明扫描范围和结果，不创建空的模块模板。
- 纯文档整理只做链接、差异和与源码逐项对照所需的最小检查；不自动构建、全量测试、浏览器验证或联网。未运行相关测试时，只能说“读取测试作为依据”，不能声称测试通过或接口可用。

## 完成输出

报告索引和模块文档路径、覆盖模块与操作、发现的差异和待确认项、实际检查及未执行项。生成文档不等于接口联调或最终产物验收，不自动创建 PRD、ADR、Status、Work Plan 或 Verification。
