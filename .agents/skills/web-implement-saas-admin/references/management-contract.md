# 管理领域与服务合同

本文件约束状态所有权与协作关系，不声明真实 endpoint、字段拼写、权限码或已经存在的服务能力。具体下游先取得契约，再映射 UI 与域 API；本地规则真实实现，仅缺少地址的远端操作使用类型化 Mock。

基础参考的领域覆盖与缺口集中在 [大后台 API 关联](../../../../docs/API.md#大后台契约缺口)，通用响应、错误与 Bearer 适配见 [协议与会话适配](../../../../docs/API.md#协议与会话适配)。profile 的默认组织不是管理目标；Account 的 1/0 状态不能套用到其他领域，秒级 `updated_time`、JWT `ver` 与 `request_id` 分别不能冒充实体版本、管理版本与幂等/审计凭证。

## 领域与不变量

| 领域       | 服务必需事实                                                               | 不变量                                                       |
| ---------- | -------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 分类       | 稳定 ID、父级、排序、状态、版本、商品/子级引用及可见性规则                 | 树无环且引用有效；移动与影响校验原子化；父级直属商品不能丢失 |
| 商品与报价 | 分类归属、可售/发布状态、规格、价格/币种/精度、版本、报价失效策略          | 商品属于有效分类；准确金额；历史订单快照独立于当前商品       |
| 组织       | 组织状态、负责人、成员关系、影响范围、可执行动作及版本                     | 管理目标不变成登录身份；停用不隐含交易回滚或数据删除         |
| 账户与成员 | 全局账户状态、每个组织的成员/邀请/角色、可授予范围、唯一负责人保护         | 成员移除不改变其他组织；负责人交接由服务原子执行             |
| 订单       | 原购买者/组织、商品/金额快照、支付与权益状态、允许动作、版本/幂等/恢复查询 | 状态与取消由服务决定；未知先对账；不编辑历史金额或强制成功   |
| 钱包/支付  | 钱包真实归属、资产/币种、余额与流水、尝试关联、结果查询及一致性期限        | 只读核查；不从余额差额自行断言订单支付成功                   |
| 平台访问   | 当前操作员身份、平台权限、可授予角色、客户成员权限的独立范围               | 默认拒绝；不得超出可授予范围；防止最后管理员失效             |
| 审计       | 可信操作员、对象/组织、动作、时间、原因、结果与关联请求、字段脱敏          | 服务端拥有记录；与业务写入一致；不能客户端删除/伪造          |

商品、分类、组织与订单状态名称按服务映射。只有服务提供可执行动作时才呈现按钮，不把页面可见权限等同于编辑、发布、取消、角色分配或跨组织读取权限。平台范围与组织范围使用真实权限集合的 all/any 语义，未知/空权限不放行；不定义臆造的公共权限码或超级管理员通配规则。

## 写入、并发与恢复

- 提交前冻结当前操作员、认证 revision、目标对象/组织、输入快照、预期版本及当前权限。使用服务的版本/条件写入机制防止覆盖并发修改；冲突时保留表单并重取，不静默转成无条件覆盖。
- 创建、移动、发布、停用、成员/角色变更和订单取消使用真实允许状态与防重复契约。前端防双击不能替代服务端幂等；同一未知请求保持原关联，先查询是否成功，不能自动 replay mutation 或自动生成新请求身份。
- 纯读取可取消、有限重试；有响应的业务错误、配置/协议错误与无响应网络失败分开表达。普通业务 403 保留会话；凭据校验操作仍遵循认证 Skill 的错误退出规则。401 及迟到错误由唯一会话 owner 处理。
- 级联影响、唯一负责人、最后有效管理员、分类引用与取消/支付竞争必须服务端原子校验；前端检查只作提前反馈。自我降权成功时重取当前权限并退出不可访问页面，不能为了留在页面沿用旧权限。
- 成功后精确失效当前实体详情、受影响列表与关联查询：分类变更影响树/目录；商品变更影响其报价与目录；成员/角色影响对应上下文；订单影响原订单/支付与相关钱包查询。不要直接改余额或清空整个 QueryClient。
- 结果未知、保存成功但刷新失败和实际保存失败分开：前两者不自动重复写入，提供原请求状态查询或读取刷新；表单关闭不代表服务已取消操作。

## 历史保护与资金边界

价格使用服务约定的最小单位整数或精确十进制字符串，包含币种/精度；浮点展示计算不成为定价依据。类别/名称/规格/价格变化不能覆盖已有订单快照，商品下架与分类停用不能擅自撤销历史权益。

组织或账户停用对现存待支付订单、会话、钱包状态和成员访问的影响必须明确映射服务能力；无法确定时阻断对应高影响动作并解释缺少的契约，不把“启停”实现成物理删除。历史订单、流水和审计默认保留，不新增默认硬删除或级联删除。

钱包/支付管理默认是查询与核查。取消未支付订单不等于退款；状态刷新不发起扣款；重新查询不触发补发权益。不将手工余额输入、支付状态下拉框或浏览器模拟账本用于管理写入。新增任何资金动作、自动续费、账单/发票、退款或补偿任务须先形成真实下游范围、授权和服务合同，不因“等”字自动添加。

服务端管理写入需绑定可信操作员并保证所需审计与业务结果的一致性；前端不能保存成功后再单独写一条可能失败的浏览器审计来冒充保证。异步审计/流水索引延迟按服务一致性规则显示待同步，保留原业务结果。读取脱敏信息，不显示 Token、密码、验证码或支付秘密；默认不批量导出客户资料。

## 作用域、缓存与模块

管理员是会话主体，组织筛选/详情是查询目标；切换筛选不会调用客户端组织切换接口、写入客户凭据或冒充客户。Query key 含影响结果的 target、操作员/权限上下文、目标组织/对象、语言与分页，不能包含秘密。退出、目标变化或权限撤销使旧响应、草稿和回调失效；不能把上一组织详情展示为新组织。

按实际功能组织 `features/catalog-admin/`（分类与商品）、`organization-admin/`（组织与成员）、`order-admin/`、`wallet-inspection/`、`access-control/`、`audit/`；用户账户独立变化时再从组织成员模块拆分。路由只装配页面，域 API 位于 `src/data/api/<domain>/`，复用既有 client/认证/Query。模块通过稳定具名契约协作，例如组织详情用订单查询的公共 scope，不互相导入私有组件或 atom；下层不导入 feature，不建立全局兜底 utils 或共享 core。

## 开发验证

至少覆盖权限与目标隔离、树循环/引用、商品归类与并发改价、历史快照不变、负责人/管理员保护、账户与成员状态分离、取消/支付竞争、提交超时实际成功、刷新失败保留写入结果、审计来源与脱敏。表格验证实际筛选/分页恢复与错误操作；缺少真实服务时只声明 Mock/规范已验证，不声明数据库约束、真实资金或服务端审计已经实现。
