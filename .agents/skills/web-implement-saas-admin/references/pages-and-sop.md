# 大后台页面与操作 SOP

各页面与已收录基础契约的对应关系见 [大后台 API 缺口](../../../../docs/API.md#大后台契约缺口)。认证/当前操作员资料可按真实服务采用；后台的目标对象查询、管理写入、平台权限和审计须另外提供契约，不能把自服务 register/profile 当成客户开通或客户管理接口。

本基线衔接 SaaS 登录、组织账户与可选购买能力。下游只按已选模块和真实服务能力应用；管理员登录身份与被管理客户分离，不开放公开注册，不提供客户端组织切换或隐式代登录。

## 页面与动作矩阵

| 页面           | 必要内容                                                                   | 条件性操作与边界                                                                 |
| -------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 商品分类       | 可展开/可选择的分类树、名称、父级、顺序、可用状态、关联商品                | 新建/编辑、移动、排序、启停或归档；服务校验后才允许，引用和子级影响明确          |
| 商品管理       | 按分类/名称/状态查询，商品标识、名称、分类、规格/价格/币种、可售状态与详情 | 新建草稿、编辑、发布/上架、下架、归档；状态语义依服务，历史订单不受覆盖          |
| 组织管理       | 标识/名称/状态筛选，详情、负责人、成员、关联订单/钱包                      | 创建/编辑组织、服务支持的启停、成员维护与负责人交接；查询范围不改变登录身份      |
| 用户与成员     | 用户账户状态与组织成员关系分开；查找账户、查看所属组织及成员角色           | 仅授权时管理账户状态或组织成员；不能用移除成员代替全局禁用账户                   |
| 订单管理       | 订单号、购买者/组织、商品快照、金额/币种、支付/权益状态、创建时间、详情    | 查询支付状态、刷新；服务明确允许时取消未支付订单并填写原因；不代付或手改支付结果 |
| 钱包与支付记录 | 按用户/组织/币种查询钱包余额/状态、流水与支付尝试，关联订单                | 默认只读，异常状态显示恢复查询；不能直接编辑余额、流水或支付成功标记             |
| 平台访问控制   | 平台操作员、可授予角色及权限范围；与客户成员角色区分                       | 服务支持时分配/撤销可授予角色、启停操作员；不得越权授予或绕过最后管理员保护      |
| 操作审计       | 时间、操作员、对象/组织、动作、结果、原因与关联请求                        | 只读筛选和详情，敏感字段脱敏；不提供修改/清空入口或默认导出所有客户数据          |

核心管理范围为分类、商品、组织与订单。用户/成员、访问控制、钱包支付查询与审计补齐管理所需上下文；无服务能力的写动作不显示为可执行，不能以本地假成功代替保存。订单权益详情仅商品实际交付权益/额度时出现。

## 分类维护 SOP

1. 打开分类管理，读取分类树及版本；展开与选中分离，显示路径和关联商品。父分类可同时有商品与子分类，与客户端查询语义一致。
2. 新建/编辑时填写名称、父级、顺序及服务必需字段。移动节点时排除自身和全部后代，核对将迁移的子树与商品关联范围，不擅自重新挂载后代或批量改商品分类；服务端仍校验无环、重复标识、悬空父级和并发变化。
3. 提交成功后重取树、受影响商品归属和列表；版本冲突保留输入，读取新版本并让用户核对，不覆盖别人修改。
4. 停用/归档前读取影响：子分类、直属/后代商品、客户端可见性。存在引用时按服务约定阻止或迁移；不默认级联删除，不把隐藏分类等同于已取消订单。

## 商品维护 SOP

1. 按分类查询并打开新建/编辑，填写稳定标识（按服务）、名称/说明、有效分类、可选规格、准确价格/币种与可售规则。商品必须挂在有效分类下；多分类规则沿用服务契约。
2. 默认先保存草稿；服务无草稿状态时使用其真实生命周期并明确保存后的可见影响。发布前核对分类、规格、计价、钱包兼容币种及服务端校验结果。
3. 价格/规格或分类变化时展示影响，按真实版本保存；既有报价按服务契约失效或保留，后续报价获取当前版本。已创建订单保留其商品/规格/金额快照；新价格只按服务规则作用于后续报价/新单。
4. 下架/停用只改变可售性。既有待支付订单是否仍可付、失效或需要用户重新确认，由服务端订单/报价能力判断；已支付订单和权益不自动撤销。
5. 归档或删除前核对引用与历史保留规则；已被订单引用的商品不可通过客户端级联删除历史。写入超时后按原请求找回结果，不重新创建第二个商品。

## 组织、用户与成员 SOP

1. 进入组织列表，选中组织打开详情，始终显示目标组织标识。成员、订单与钱包查询使用该对象范围，不改管理员会话 Token 或平台权限。
2. 创建/编辑只使用服务必需资料和版本；管理组织负责人、添加已有用户或服务支持的邀请时区分账户、邀请和成员关系，邀请不等同于已经加入。
3. 成员变更前核对目标用户、组织、当前角色与可授予范围。移除成员/停用成员不全局禁用账户；同一用户其他组织的成员关系保留。
4. 负责人交接要求新负责人有效、操作员有权、服务原子执行；不能先移除唯一负责人再补建。对最后有效平台管理员、自己角色与自己会话的变更遵循服务保护并同步权限。
5. 停用组织/账户前展示真实影响并收集服务要求的原因；明确是否禁止登录、创建订单或继续支付，不自行假定停用同时退款、取消订单、冻结钱包或删除数据。恢复后的能力也由服务确认。

## 订单与支付核查 SOP

按订单号/组织/用户/状态/时间查找 → 查看商品及金额快照 → 分别读取订单、支付尝试与权益状态 → 结果未知时查询原尝试 → 核对关联钱包流水 → 按服务状态显示已支付、处理中、失败或未知。

- 支付成功与权益生效分开；权益同步失败不将订单改成待支付。查询和刷新不产生新扣款或新支付尝试。
- 取消只对服务当前允许的未支付订单开放，展示影响、填写原因并提交版本/幂等关联；与支付并发时以服务最终结果为准。超时未知只查询，不宣称已取消或立即重复执行。
- 已支付、关闭/取消、过期订单不提供强制改状态、修改历史金额或删除交易记录。退款、调账、重新发放权益和外部支付接入不在默认管理范围。

## 访问控制与审计 SOP

从服务读取当前操作员权限与可授予角色 → 查目标平台操作员/客户成员的独立角色范围 → 展示差异与影响 → 提交服务允许的变化 → 重取权限/详情并检查当前页面是否仍可访问。角色名、URL 参数和隐藏菜单不产生权限。

服务端为管理写入保留操作员、目标、作用域、动作、时间、原因、结果与关联标识。审计页面显示服务端记录，不由浏览器补造权威事件；没有读取审计权限时隐藏入口，不影响已授权业务的服务器审计职责。审计读取失败保留已确认业务结果，只重试审计读取，不重复业务写入。凭据、密码、验证码和支付敏感材料不进入详情/审计。

## 验收场景

- 分类移动到自身/后代被拒，非法树不可维护；有引用分类不能静默删除或丢掉直属商品。
- 无分类商品无法发布；两个操作员并发改价出现可恢复冲突；改价/下架后历史订单快照保持不变，待支付资格重取。
- 选组织不改变管理员身份，跨对象越权读取/写入被拒；账户状态、成员关系与平台操作员权限不混用；唯一负责人/管理员保护有效。
- URL 直达、按钮与实际动作都按权限控制；权限撤销、退出、目标切换后迟到响应不能写入当前 UI。
- 取消与支付并发、提交超时后实际成功先恢复原结果，不重复写入；已支付不出现代付或手改余额入口。
- 服务端审计与管理结果一致，失败/未知可解释；客户端日志不是审计证据。列表恢复、键盘和错误反馈按现行规范验证。
