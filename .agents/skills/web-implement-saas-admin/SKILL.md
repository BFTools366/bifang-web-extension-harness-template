# Web Harness：设计与实施 SaaS 大后台管理

为 SaaS 客户端的账户、组织与购买流程提供相应管理能力，保留历史交易和平台权限边界。源 Harness 只维护并分发通用规范，不实现具体产品；SaaS 创建成功后按 [创建与开发 SOP](../web-design-prototype/references/prd-outline.md#创建与开发-sop) 在下游采用本合同。

## 适用边界

- **仅已初始化 Web 且明确采用 saas-admin 模式时应用**。在唯一 Product Spec 中记录页面范围、服务能力和权限；分发 Skill 不开启管理功能，也不启用客户端的可选购买能力。不新增项目身份 Schema、环境键或第二套认证。
- **组织管理不切换管理员登录组织或冒充客户**。组织是被管理对象或查询范围；平台管理员权限来自当前服务端会话，不因选中某组织而取得客户身份。沿用大后台认证，无公开注册或头像切换组织入口。
- 核心页面为分类、商品、组织与订单；配套页面为用户与成员、钱包与支付记录查询、平台访问控制、操作审计。各页面与动作按真实服务能力和权限裁剪，不从“管理员”名称推断全部权限。
- **钱包与支付记录默认只读查询**。不自动增加充值、提现、退款、调账、强制标记已支付、代客户支付、批量删除或生产写入；需要这些能力时按新的真实契约和授权单独扩展。

业务类型与范围事实统一遵循 [Web 类型与可选能力](../web-design-prototype/references/prd-outline.md#web-类型与可选能力)，不建立第二份模式记录。

## 按请求渐进执行

通用流程读取本 Skill 时，仅补充当前阶段的领域合同与检查项，随后返回调用方，不反向重复启动定义、原型、实施或接入流程。发现真实范围变化时，将差异交回当前编排入口处理。

缺项按工程规则“渐进式交互引导”逐项补问，每轮优先一个影响下一步的问题并给可靠建议与理由。例如“钱包记录是否先保持只读查询？建议沿用默认只读，资金写操作另行明确范围”。接口核对委托 `$web-review-api-contract`，限定本次操作及最小依赖链，不要求用户一次提供全部管理接口；权限、目标组织和交易状态不从默认值推断。

1. 识别源/下游、模式、本次页面及授权范围。需求/SOP 读取 [pages-and-sop.md](references/pages-and-sop.md)；首次采用或管理页面/动作范围变化时，由 `$web-define-product` 更新下游唯一 PRD，日常修复复用已有确认事实。
2. 设计读取 [neutral-ui-design.md](references/neutral-ui-design.md) 与当前 UI 规范，按通用触发条件使用 `$web-design-prototype`；已有有效原型登记且范围未变时复用，由调用方检查有效性。本 Skill 的通用页面规格不替代下游登记的单一桌面原型。
3. 实施前完整读取 [management-contract.md](references/management-contract.md)、`docs/DATA_ACCESS.md` 的数据层/状态所有权与当前操作命中的 HTTP/认证章节，以及 [SaaS 会话合同](../web-implement-saas-auth/references/session-contract.md)；核对 [基础 API 的大后台关联与缺口](../../../docs/API.md#大后台契约缺口)。来源只覆盖当前账号自服务，不提供管理目标组织/账户、商品订单、平台权限或审计接口。商品/订单规则与 [客户端购买合同](../web-implement-saas-commerce/references/order-and-wallet-contract.md) 一致；不从通用字段或 BaseURL 猜 endpoint。
4. **改价与下架不改写历史订单快照**。分类移动与删除/归档必须校验树及引用；组织成员、账户禁用与平台角色分别建模。写入使用真实版本冲突、允许状态和幂等/恢复契约，超时未知先查询，不自动重放。
5. **菜单、路由与操作复用服务端权限判断**。区分平台作用域、目标组织、对象与动作；业务 403 不自动注销，凭据校验错误按认证合同统一处理。成功响应、迟到错误和缓存写回均复核当前会话与目标。
6. **管理写操作由服务端校验并留存审计**。前端收集必要原因、展示影响与结果；不能用客户端日志替代审计，也不直接编辑交易状态、钱包余额或历史记录。源 Harness 维护不执行业务写入；读取本 Skill 不自动授予下游真实账户或资金写入授权。
7. 实施复用 `$web-implement-change`、列表 Skill 与既有 Router/Query/Mantine/i18next；真实 HTTP 按 `$web-connect-http-service`。按分类商品、组织成员、订单、钱包查询、访问控制、审计功能内聚拆分，API 留在 `src/data/api/`，依赖单向无环，不建立共享 core。
8. 按参考中的场景完成相关非空回归或文档情境检查；不自动构建、发布或做正式候选验收。报告未支持能力、Mock 与真实契约，不能把管理规范分发称为后台已上线。

权限入口实现委托 `$web-implement-access-control`；重复提交、未知结果与并发恢复委托 `$web-implement-write-recovery`，具体订单允许状态、钱包资金及服务审计仍归本领域合同。仅在实施阶段命中对应变化时调用，需求或原型阶段不因此修改代码。

## 完成输出

说明适用模式、页面与动作矩阵、与客户端流程的约束、权限/作用域、历史数据保护、冲突和未知结果恢复、服务端审计要求及实际验证。明确未接入的服务能力与未执行的真实副作用。
