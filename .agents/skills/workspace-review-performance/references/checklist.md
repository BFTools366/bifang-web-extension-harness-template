# 并发与性能检查清单

只读取当前范围命中的章节。每条都是审查问题，不是默认要做的改动；命中后按 SKILL 的三类结论给出证据。

## Go 服务

### 防死锁

- **SQLite 单写者**：生产与测试使用同一连接池配置；SQLite 设置 `busy_timeout` 与 WAL，写入连接数为 1 或独立读池。只在测试里固定 `SetMaxOpenConns(1)` 会掩盖生产的 `database is locked`。
- **事务内只用 tx**：`Transaction(func(tx){…})` 内不得调用外层 `db` 或会自行开事务的仓储；池大小为 1 时这会自等待。
- **固定加锁顺序**：同一聚合只用一个有文档的加锁顺序（如先锁组织行 `FOR UPDATE`，再成员，再角色）。不要依赖 SQLite 全库锁提供串行化，换到 Postgres/MySQL 时会变成按行锁并交错。对死锁与序列化失败只做有界重试，且只重试幂等或已确认可重放的写入。
- **事务内无网络 I/O**：SMTP、短信、外部 HTTP 在事务外执行；配额或频率检查与名额预留必须原子化（条件插入或行锁），不得先查后做。
- **锁内不阻塞**：持有 `sync.Mutex` 时不做 I/O、回调、channel 发送或 O(n) 扫描；在锁内拍快照，锁外处理，或分片。

### 无界等待与泄漏

- 每个外部等待都有截止时间：`PingContext`、迁移 `WithContext`、外部 HTTP 的可复用 `http.Client` 总超时、HTTP server 读写与空闲超时、优雅关闭 ctx。
- 每个 goroutine、ticker 都有拥有者和停止路径（ctx 或 stop 函数）；中间件构造函数不得每次调用泄漏一个后台循环。
- 按键增长的内存结构（限流访客表、缓存）有上限或 LRU；`ClientIP` 依赖的可信代理必须显式配置，否则伪造头会无限扩表。
- 请求与响应缓冲有上限：读取前缀用于日志时要把剩余 Body 接回（`io.MultiReader`），响应捕获只在需要时开启且封顶；流式与大文件不得整体缓存。GraphQL 设复杂度、别名与 Body 上限。
- 启动失败路径关闭已打开的资源（DB、监听器）。

### 性能热点

- **N+1**：循环内逐行查询改为按关系 `IN (?)` 批量加载后在内存关联；分页列表每行 1–3 次查询即为热点。
- **逐行写**：多行写入用 `CreateInBatches` 或 `INSERT … SELECT … ON CONFLICT`；启动同步任务不得在一个写事务里做 O(租户×权限) 次往返。
- 共享写状态与事务竞态需要 `go test -race` 证据；性能修改需要真实瓶颈、基准或 profile。

## TypeScript / React 前端

- **只在真实变化时发布**：权限、会话等 runtime 刷新期间保留上一份有效快照，只有主体或数据变化才通知订阅者；失败关闭语义变化需先修订访问控制合同。
- **计时器粒度**：倒计时 1 秒一次并下沉到叶子组件，或只排定下一个截止点的 `setTimeout`；不要让整张表单每秒多次重渲染。
- **对称清理**：订阅返回取消函数，effect 清理计时器与监听，`AbortSignal` 监听在 `finally` 中移除；长期对象只复制需要的字段，不捕获大闭包。
- **不复制不读的 Body**：只读 Header 的提取器不要 `response.clone()`；需要克隆时消费或取消副本。
- **截止时间覆盖 Body 消费**：超时与取消应持续到响应体读取完成，而不是 `fetch` 返回 Response 就清除。
- Query 缓存、重试与失效的唯一拥有者见 `docs/DATA_ACCESS.md` §2.6–2.7，不另建第二套缓存。

## Node 工具与测试

- **有界并发**：文件遍历与读取的 fan-out 设上限（约 16），避免 `EMFILE` 与一次性占满内存；同一次运行每个文件只读一次，结果在校验器之间共享。
- **异步子进程**：循环与测试中不用 `execFileSync`/`spawnSync`，它们阻塞事件循环，使 Vitest 超时无法触发；每个子进程都有 timeout，同时消费 stdout 与 stderr 以免管道写满互等。
- **批处理代替逐文件进程**：对整目录运行一次格式化或使用长期 worker，不要每个文件启动一次 Node/gofmt。
- **Git 隔离**：可能触发交互的 Git 调用设置 `GIT_TERMINAL_PROMPT=0`、`GIT_EDITOR=true`；测试夹具隔离用户全局配置（如 `GIT_CONFIG_GLOBAL`、`-c commit.gpgsign=false`），避免 pinentry 或编辑器挂起。
- **超时预算**：单个测试内子进程超时之和必须小于测试超时；昂贵夹具（Go 二进制、生成项目）每次运行只构建一次；服务自行绑定端口 0 并回报地址，不先探测再复用端口。
- 独立的校验步骤用 `Promise.all` 并行，最慢的子进程最先启动；有顺序依赖或共享写入的步骤保持串行。
