# Web Harness 下游初始化表单

服务来源支持 existing、create、none；只有明确不需要服务端才采用 none，不创建 Go 成员，三环境不配置服务地址。服务来源改变后旧地址和接口文档失效，同次主动给出的新值仍须校验。所有问答阶段均允许主动 JSON 修订已知基础或策略字段，保留其余答案并重新校验受影响项。

创建 Workspace、唯一所选 Web 或 Extension 前端及按服务来源决定的 Go 服务端成员使用固定表单逐项引导基础输入并生成项目标识；Extension 另需非空简短说明。复用当前请求或命令已提供的合法值，只问缺失或非法项；Web 说明和确认来源不作为用户必填字段，已有服务须提供开发 BaseURL；没有则创建并连接 Go 服务。

## 固定问题清单

固定题面及禁止新增问题只适用于清单中的工程输入和策略字段，不限制 `$web-define-product` 为明确首版需求逐项提出必要问题。Agent 的完整创建确认按实例化 Skill 执行，CLI confirmation 只确认工程事务。

[`initialization-questions.json`](initialization-questions.json) 是 Agent 与 CLI 共用的题目文案唯一事实来源。创建前读取该文件，按 `basic` 的键顺序处理基础字段，再按 `policy` 的键顺序处理适用的自定义策略，CLI 使用 `confirmation` 确认工程事务，Agent 使用 `agentConfirmation` 确认工程输入、首版范围与开发验证，两者不连续询问；下一字段与汇总由[共享只读表单工具](form-adapter.md)返回；字段是否需要询问仍由下文的条件与校验决定。

- `title` 是固定问题名称，`question` 是固定题面；逐字使用，不自行缩写、改写、合并或新增问题。首次询问、非法回答重问、默认值变化与中断恢复都保持同一名称和题面。
- 每个选项固定显示为 `label（description）`，使用中文全角括号，说明紧跟选项名称。说明必须表达选择的实际意义，不能只展示 `web`、`enabled` 等技术值；保留清单的选项顺序，不因推荐值变化重排。
- `hint` 提供终端输入格式与适用说明；聊天优先使用题库的 `agentHint`，没有时复用 `hint`，不显示内部字段名或终端输入符。首次缺失不显示错误，实际非法回答才说明修正原因；建议/默认值、错误原因和已答进度另行展示，不能拼入或替换题名、题面及选项说明。选择题只展示当前题目的选项，自由文本题不虚构选项。
- Agent 每轮只发一题并等待实际回答；不得把整份表、多个问题或五项策略合成一轮问卷。Agent 复用用户主动提供的多个合法值，只继续询问下一项缺失或非法值。CLI 基础问答的 JSON 接受全部已知基础与可选输入字段，允许主动修订已答项，修订后重新校验并重算派生值；自定义策略经命令行参数或逐项回答提供，JSON 中的不支持字段会明确报错。
- 使用问答工具时，完整保留问题名称、题面和各选项的括号说明；工具的短标题、推荐标记或预选值不能替代这些内容。聊天中的建议值需明确回答接受；仅 CLI 在题面之外明确提示“回车采用”的配置项允许实际空回答接受。

## 交互状态机

- 字段状态只取 `待首轮询问`、`待条件询问`、`待校验`、`已解析` 或 `不适用`。
- 每轮只问一个尚缺失或非法的字段，收到实际回答并校验后才进入下一项：只展示共享工具返回的下一项，JSON 的键顺序是唯一题序。CLI 直接接收普通文本，仍兼容用户主动附带多个字段的 JSON 对象；不要求一次填表。需求采集作为第一项，已有需求直接复用；项目类型只显示 1.Web / 2.Extension。Agent 根据充分需求优先自动选择唯一适配的宿主、能力和本地方案，真实争议或多个方案同样适用才推荐并询问；自动结果通过 selection 独立记录理由。CLI 不分析语义，需求后再显式选择无默认值的宿主。没有现成服务则默认创建所选前端和一个 Go 服务端，明确纯本地才采用 none，不再询问成员组合。Agent 设置默认采用预设，不询问策略模式；主动提供单项策略则沿用为自定义，仅补齐缺项。项目标识由项目名称的英文翻译自动生成小写 ASCII kebab-case；Agent 负责翻译并传入 `englishName` / `--english-name`，英文名称可直接生成，不要求用户填写 id，不转拼音、不从父目录名推导。纯终端无翻译能力时只补问英文译名。已有显式合法 id 优先复用。
- 父目录允许相对或绝对路径。聊天以源 Harness 根为基准，CLI 以调用 cwd 为基准；保留原始输入，只读解析最近真实祖先、核对访问权限与目标约束，在最终汇总展示解析基准和最终绝对保存位置，询问是否保存到此位置，用户同意后继续，无需重输绝对路径。非交互相对参数未获路径确认时零写入，提示使用同一命令在交互终端确认或提交已确认的 `--form`。交互省略位置参数时才补问 `targetRoot`，最终目录为“父目录/id”，不猜默认父路径。
- Web 说明默认使用显示名称；Extension 缺失说明时单独补问，空白值必须修正；已有服务必填开发 BaseURL，自建服务由创建器写本地 Go 地址，none 不配置地址；不猜测 endpoint，测试和正式地址不在首轮询问；正式发布前按运行配置合同补齐地址：自建服务首次空地址从生产配置推导本机地址并提示确认，其他远端使用 HTTPS。
- 用户主动提供的可选字段全部复用并校验，包括主动提供的 JSON 中附带的地址。非法已填值进入后续修正轮；已经合法的字段不重问。
- 确认来源自动记录为“当前用户”，已有明确合法来源时复用；不单独询问姓名或确认来源。时间记录最终收齐日期。
- 选择“自定义”后每轮只询问一个缺失或非法的策略字段，展示同名预设值作为建议默认值；题面明确“回车采用”，接受后记录来源。已主动提供的合法策略值全部复用。未提供策略时默认直接展开预设，不询问；最终汇总仍展示。
- 完成解析后展示唯一完整汇总，包含源/目标原始路径与规范路径、身份、已配或未配的地址、品牌、完整 policy 和输入来源；工程 CLI 使用 `confirmation`；Agent 同时展示真实首页、页面、操作依赖及原因、固定设计、数据模式和验收场景，使用 `agentConfirmation` 确认连续下游实施与开发走查，阶段交接不重复确认。已有覆盖当前汇总的明确完整创建授权直接复用并记录真实来源；修改工程输入、Logo、原文或首版范围后重新生成修订，旧确认失效，保留其余合法答案。
- 完整汇总确认前只允许读取规则、解析输入和规范路径，以及在源/目标之外的临时目录提取完整需求文本、按品牌 Skill 生成或导入 Logo 候选，不创建目标/staging、复制、安装、初始化 Git 或修改源文件；拒绝确认不写入源/目标/staging。非交互命令通过完整必需参数表达创建意图。
- 需求文档可选，首版需求必须明确；创建需求按 [输入与交接合同](requirements-intake.md) 委托需求定义进行只读分析并交接；不在模板源写产品记录或业务代码。endpoint、凭据、完整范围确认在下游 PRD 中复用；真实付费、生产、发布需求与最终 E2E 选择按各自门禁处理。
- 项目内 `design-taste-frontend` 默认安装，已有有效版本原样保留，不作为表单或策略选择，不全局安装。

## 基础输入与自动字段

下表只解释字段；题序与条件由共享工具及 JSON 决定。

| JSON 字段 / 命令行参数         | 字段                  | 规则                                                                     |
| ------------------------------ | --------------------- | ------------------------------------------------------------------------ |
| `projectType` / `--type`       | 项目类型              | 仅 Web 或 Extension；需求唯一适配时 Agent 自动选择，CLI 无默认值。       |
| `name` / `--name`              | 项目显示名称          | 非空文本。                                                               |
| `id` / `--id`                  | 项目标识              | 由英文译名生成，匹配 `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`；显式值优先复用。 |
| `targetRoot` / 位置参数        | 源 Harness 外的父目录 | 模板之外；最终目录为此路径/`id`，该子目录须不存在或为空。                |
| `policyMode` / `--policy-mode` | Agent 策略模式        | 默认预设且不询问；主动自定义时接受 `custom`，显式预设不接受单项覆盖。    |

服务来源字段 `serverMode` / `--server`：需求确定完全本地时自动 none；需要服务时只补现成服务事实，明确没有后直接 create；多个同样适用或有争议时才推荐。已有明确选择优先复用，自动结果及依据单独保存 selection。支持 `existing`（有）、`create`（没有）和明确纯本地的 `none`（不需要）；选择没有时默认创建所选前端和一个 Go 服务端，不另问服务端类型。已有服务必填 developmentBaseUrl，可用 apiContract / --api-contract 提供可信接口文档，内容快照进入根 docs/api/source-contract.txt 并绑定创建确认。BaseURL 不授予猜测接口的权限。无需独立 Go 技术或功能问卷。

## 可选输入与后续配置

- 需求输入可选，支持 Markdown（.md）、TXT（.txt）、Word（.doc/.docx）或直接文字，也可暂不提供；用途是理解用户、页面、流程与范围，减少重复沟通。`requirementsFile` / `--requirements-file` 接受相对或绝对 `.md` / `.txt` 路径；`requirementsText` / `--requirements-text` 接受直接文字或 Agent 从 Word 完整提取的正文。二者互斥，非空 UTF-8 文本最多 1 MiB；CLI 当前题输入 `text:正文` 或 `文字：正文` 即直接输入，回车跳过，聊天明确说暂不提供才跳过。Word 读取、完整性与失败处理按[输入合同](requirements-intake.md)，CLI 不原生读取 Word。文本快照随 staging 保存到下游 `docs/requirements/source.txt`，不因跳过输入阻止后续逐项澄清。

- `englishName` / `--english-name`：项目名称的英文翻译，用于自动生成标识；英文显示名称可省略，不写入下游身份配置或自动扩充本地化。中文名称由 Agent 翻译，纯终端缺失时补问；非交互缺失且未给显式 id 时在写入前拒绝。
- `developmentBaseUrl` / `--development-base-url`：已有服务必填开发 API 地址；自建服务固定初始本地地址。
- `testBaseUrl` / `--test-base-url`：测试 API 地址，初始化无需提供，可后续配置。
- `releaseBaseUrl` / `--release-base-url`：正式 API 地址，初始化无需提供，正式发布前按运行配置合同补齐地址。
- 已填地址必须是无凭据、查询参数、片段 的绝对 HTTP(S) URL；正式远端地址只接受 HTTPS，本机回环允许 HTTP。三份环境文件仍生成；普通文件校验允许空地址，活动 Release 校验要求正式地址非空。
- `description` / `--description`：Extension 必填，非空且最多 132 字符，已提供则复用；Web 缺省或空白时使用显示名称。扩展所有语言的名称最多 75 字符。
- `identityI18n` / `--identity-i18n`：可选 JSON 字符串，包含 `defaultLocale: en|zh_CN` 与 `translations` 对象；每份翻译必须同时包含非空 `name` 和 `description`。默认语言使用根字段，不重复记录在 translations。缺失翻译回退默认身份，未知语言/字段或不完整翻译在写入前拒绝。
- `confirmedBy` / `--confirmed-by`：仅复用已明确来源，缺省或空白时自动记为“当前用户”，不主动询问。
- `brandColor` / `--brand-color`：合法十六进制颜色，缺省 `#4C6EF5`。
- `--logo`：可选本地图像，由 Logo 预检验证；纯 CLI 直接省略时保持单图确定性生成。Agent 路径按 `$web-prepare-brand-identity` 沿用正式源图或自动选择需求唯一适配的方向；多个方向同样适用或有审美分歧时才展示候选并推荐，离线候选也按同一原则；只导入已选路径。选图由品牌 Skill 单独管理，不增加基础表单字段，也不代替最终创建确认。候选临时目录位于源和目标之外；汇总列出已选源图、母版及当前宿主派生文件。

## 条件策略字段

“自定义”模式按 JSON 的 `policy` 键顺序逐项询问，结果物化为 `enabled` 或 `disabled`；交互回答另接受“启用/关闭”“是/否”；仅 CLI 实际回车可采用已展示的建议，聊天仍须明确回答。

题序不在本文另建列表；只复用本次创建请求的明确答案，不复用源策略默认值。

`user_owned_tasks` 推荐/default 都为 `disabled`。`e2e_hint` 仅建议本次发布首次 E2E 选择，同一发布复用已明确的选择。“预设”确定性物化为：

```yaml
user_owned_tasks: disabled
superpowers: disabled
parallel_worktree_subagents: disabled
acceptance_smoke: enabled
e2e_hint: disabled
```

## 路径与来源汇总

最终汇总逐字展示源 Harness 根的脚本输入与 `realpath` 规范值、用户提供的原始父路径、相对路径的解析基准、拼接项目标识后的完整项目路径与解析既存祖先后的规范值。来源标记固定入口、命令行位置参数、交互问答、主动 JSON 表单、交互接受默认值、英文名称自动生成、显示名称默认值、未配置地址、自动确认来源、品牌默认值或确定性预设。没有实际配置的地址明确显示“未配置”，正式地址提示发布前必须补齐。

路径汇总只是写入前确认事实，initializer 仍独立执行空目录、符号链接、源外位置、目录名和 source freeze 门禁。目标不存在时只读解析最近已存在祖先，不为规范路径提前创建目录。

## 原子写入边界

- 最终确认后、首个目标或 staging 写入前，冻结纳入复制的源文件路径、完整字节与权限模式，以及 `Version.md`（存在时）和可用 Git HEAD/完整 porcelain 状态。
- staging 初始化完成、原子发布前复核同一事实；纳入文件的新增、删除、字节或模式变化，Version、Git HEAD 或状态变化都失败关闭。
- 首次父目录写入前使用规范目标路径；创建唯一 `.<id>.harness-init.lock` 租约，冻结父目录、staging、holding 与既存空目标的设备/inode/模式。身份漂移停止发布；holding 回收失败只报告已发布但有残留，不改写成功结果或沿替代树清理。
- Node 标准库不提供跨平台目录 `rename-if-absent`，同机进程故意绕过租约的竞态不属于内核级保证；检测到目标竞争仍须失败关闭。

本表维护工程输入、原文交接与完整创建确认的边界；工程事务结束后，创建入口在下游继续首版，业务操作与依赖由唯一 PRD 记录。

完整创建与工程事务的停止条件以 [实例化 Skill](../SKILL.md#在下游完成首版) 为准；固定问题清单不替代实际需求澄清，CLI 成功不能作为首版交付证据。
