# Web Harness：核对 API 契约

交付当前操作的契约证据与差异清单，供实现、接入或文档流程复用。只读核对不证明服务可达。

## 触发与边界

- 仅在已初始化且 `projectType=web|extension` 的下游核对产品接口；源 Harness 只维护本 Skill，不接收产品地址、endpoint 或凭据。
- 用户要求契约审查，或调用方确实需要核对受影响操作时应用；纯 UI、已完成且未变化的核对不重复启动。
- 不修改代码、配置、测试或文档，不启动服务、不请求远端接口；不从 BaseURL、函数名、Mock 或客户端类型猜服务端契约。
- 接收调用方已确认的范围、来源和证据，只补充本次操作及最小依赖链。完成后返回调用方，不反向启动产品定义、原型、实施、接入或文档生成。

## 按需读取

先读取项目身份、工程规则及受影响操作。`docs/API.md` 如存在，仅读取本次已采用的来源章节与关联表；参考收录不等于实现。按需读取 `docs/DATA_ACCESS.md` 的数据层与状态所有权，再选择 HTTP/认证、GraphQL、分页或推送章节。运行配置仅在 target/环境映射影响本次判断时读取，不采集实际秘密。

## 核对流程

1. 用 `rg --files` 和公开符号定位 API、输入/结果类型、校验、传输封装、调用方与相关测试，追踪到实际执行路径；重导出不算新操作。
2. 为每个受影响操作建立“接口用途 → 契约来源及版本/章节 → API 符号与实现 → 消费者 → 测试依据”的对应关系。区分可信外部契约、代码事实、Mock 和说明示例，冲突分别列出。
3. 核对请求路径、请求方法、请求头、参数位置与 JSON 结构、响应映射、错误、分页、认证/权限/组织作用域、取消/重试及写入语义。只核对适用项；缺失写“未确认”，没有执行测试只写“读取测试作为依据”。
   请求语言、逐请求追踪及访问鉴权按服务放 Header，核对实际发出的 X-Lang/X-Request-Id/Authorization、公开请求隔离及 CORS。响应 Header、REST 合同已定义的 JSON request_id、登录 TokenPair 与刷新请求的 refresh_token 分别核对；不得把 continuation 改名为 RequestID，或把访问凭据放进 query/body。通用成功、异常和分页模型核对原始字段及内部映射，不因当前没有列表接口而漏掉固定模型。
4. GraphQL 核对可信 Schema 与实际 operation、参数/列表可空性、映射及错误策略；只有 query/fragment 或客户端类型不能反推完整 Schema。推送只按已确认协议核对。
   远端列表查询必须使用 GraphQL，按 `docs/DATA_ACCESS.md` 的“列表查询协议强约定”识别集合、条件查询与分页用途。已有 REST 列表/契约列为阻断符合性的差异，不改写事实；缺少可信 GraphQL 契约时不能将 REST 接入或文档改名当作迁移。
5. 将差异分为阻断当前操作、可继续的非阻断待定、实现与文档漂移。按工程规则渐进补问阻断项，每轮优先一个关键问题；有效既有资料直接复用，不要求全套接口一次提供。

## 返回结果

返回核对范围、逐操作对应关系、已确认来源、差异/缺口及其影响和未验证项。无需落盘报告；调用方已有唯一需求或模块文档时由其增量记录，不建立第二份契约正文。不自动运行全仓检查、构建、浏览器或最终候选验收。
