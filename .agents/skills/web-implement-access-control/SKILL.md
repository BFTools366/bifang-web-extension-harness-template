# Web Harness：实施访问控制

把已确认的权限契约应用到真实入口，保持菜单、直达路由与动作的一致判断。

## 范围与事实

- 仅已初始化下游且本次涉及访问控制时应用；源 Harness 只维护本 Skill，不生成产品权限模型。Extension 的服务端业务权限与浏览器 permissions/host permissions 分开，不能相互替代。
- 复用调用方确认的模式、功能选择、当前身份/作用域及权限码。身份认证、组织切换、权限获取与会话失效继续由既有认证拥有者负责，不新建第二套会话。
- 功能选择不授予权限；不发明公共权限码、不从角色名称或网络失败推断授权。仅有本地 UI 可见性需求时保持该含义，不能声称存在服务端鉴权。
- 读取工程规则、当前宿主 UI/Router 规范与受影响权限契约；凭据和错误语义只按需读 `docs/DATA_ACCESS.md` 的认证章节。领域合同由调用方传入，不为执行本 Skill 重走需求定义。

## 实施流程

1. 为受影响菜单、路由、按钮及请求列出所需权限、对象/组织范围和 `all/any` 语义；复用现有统一判断函数。Web 的页面路径与精确激活遵循 `docs/MANTINE_UI_GUIDELINES.md` 的“导航路由与当前项”，菜单与守卫消费同一页面声明。没有权限要求的公开入口显式声明，不误伤登录与错误恢复页。
2. 对受限能力在权限未加载、不可解析或缺失时默认拒绝；权限加载有可辨识反馈，失败允许按既有流程重试，不短暂放行。依真实契约处理空权限与只读能力。
3. 菜单可见性、Router 进入/重定向及动作执行消费同一判断，不仅隐藏按钮。直达 URL、返回前进、参数变化与异步执行前均核对当前权限和作用域。
4. 已识别但无权限的目标不能当作未知路由或静默回落首页。Web 转到独立无权限恢复路由，URL 与页面提示一致；该页不依赖被拒绝的业务权限，不运行受限 loader，保留退出及经当前权限确认的返回入口；完全无可访问页时只提供真实恢复动作，不形成跳转循环。Extension 在实际 surface 的路由内提供等价拒绝状态，不新增 Web 入口。
5. 撤权或身份/组织变化时立即阻断已挂载的受限正文与新操作，再停止相关请求与订阅、清理或隔离受限缓存并进入上述拒绝恢复流程；迟到响应和错误不得覆盖新上下文。刷新后权限来自服务端；Mock 阶段由域 API 重建当前测试上下文，不持久化权限副本来恢复授权。
6. 业务 403 按既有反馈与刷新契约处理，不自动注销；只有认证拥有者定义的会话失效才进入统一退出流程。服务端仍须校验每次请求，前端无法提供服务端授权保证。
7. 按功能保持判定、路由与呈现边界，不为小范围权限增加全局框架。相关非空测试覆盖允许/拒绝、加载失败、直达路由、登录返回目标、拒绝页无循环、撤权与旧作用域迟到结果中本次受影响的最高风险路径；菜单隐藏与受限正文未挂载分别断言。

## 返回结果

返回权限与入口矩阵、实际改动及测试、待确认权限/服务能力和未验证项。完成后返回调用方，不反向启动认证、产品定义、实施编排或候选验收；不因本 Skill 自动运行全仓检查、构建或浏览器。
