# Web Harness：实施持续事件流

为真实持续事件建立可取消、有边界的连接与投影，保持事件、Query 数据和客户端状态的职责分开。

## 触发与边界

- 仅已初始化下游的真实订阅、持续来源或复杂时序需求触发；普通 callback、有限 HTTP、单次浏览器消息不需要本 Skill 或 RxJS。源 Harness 只维护通用规则。
- 先复用已确认的 endpoint/Schema、认证与事件/恢复契约；没有 Subscription 或推送协议时不能从查询接口推断支持。缺项按工程规则逐项补问，不要求全套协议一次提交。
- 连接 adapter 负责传输、校验与幂等 teardown，feature hook/service 拥有启停、恢复和投影；不创建全局可写 Subject 或另一套请求/认证状态机。
- 返回调用方，不反向启动接入、产品定义或候选验收。接入授权不扩大真实服务、凭据、生产或浏览器权限范围。

## 按协议渐进读取

先读 `docs/DATA_ACCESS.md` 的数据层与状态所有权、现有消费者和受影响契约；随后只读命中分支：

| 本次能力             | 所需章节与证据                                                      |
| -------------------- | ------------------------------------------------------------------- |
| SSE                  | “Server-Sent Events”：方法/headers、认证、恢复游标与 client 选择    |
| GraphQL Subscription | “Subscription 推送”：可信 Schema、实际握手协议与 payload/error 语义 |
| 多来源/复杂时序      | “可选 RxJS 事件流编排”：真实引入条件、共享与 teardown               |
| Extension 跨上下文   | 当前宿主兼容规则、消息边界及 Chrome MV3 / Firefox MV2 生命周期      |

没有命中某分支不读取、不安装其依赖；选用新库时按项目依赖规则核对官方证据与锁文件。

## 实施流程

1. 固定唯一连接/重试拥有者、target、身份/组织 scope 和认证 revision。浏览器 WebSocket 不能任意设置 HTTP headers，Ky 拦截器不自动作用于握手；凭据不进入 URL 或日志。
2. 外部 payload 按 `unknown` 校验后转换为领域事件；按真实 eventId、sequence/实体版本拒绝重复、乱序与旧作用域事件。本地时间戳不能单独作为权威版本。
3. 连接不放进永不结束的 Query queryFn。卸载、target/scope 改变、退出、撤权与认证轮换时关闭旧连接、移除监听；取消和 teardown 幂等，最后一个消费者退出后无残留连接。
4. 断线按服务端游标/重放语义恢复；快照与订阅窗口用缓冲对账或重取快照解决，不能承诺无契约的恰好一次。退避、jitter 与重连上限只由一个所有者控制，确定性协议/认证错误停止无限重连。
5. 完整且可判定更新的事件才写入对应 Query，否则精确失效再读取；Jotai 仅保存纯客户端状态。多来源分别隔离错误；共享/replay 仅在真实需要时采用，明确有界缓冲、refCount/reset 与清理，不复制实体权威。
6. Extension 不承诺 MV3 service worker 常驻或进程内流跨上下文；消息、Port 及重建按当前宿主合同实现。受影响的权限与兼容审查交回调用方处理。
7. 相关非空测试覆盖有效/畸形事件、重复/乱序、旧 scope、取消/重复挂载、断线恢复及本次最高风险共享/失败隔离路径。Mock 订阅不证明服务可达或真实双浏览器运行通过。

## 返回结果

返回协议与来源、连接/重试/投影拥有者、恢复与丢失边界、实际测试及未验证项。不自动增加全仓检查、构建或浏览器；真实宿主后台/权限硬要求返回既有正式候选流程。
