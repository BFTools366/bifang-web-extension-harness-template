# Web Harness：实施写操作恢复

为当前写操作区分确定成功、确定失败和结果未知，让恢复不会重复产生副作用。

## 触发与边界

- 仅已初始化下游的真实写流程、重复提交或恢复缺陷触发；源 Harness 只维护本 Skill。纯读取、普通表单显示不自动应用。
- 复用当前领域操作、授权范围和契约；订单允许状态、价格快照、钱包资金及服务端审计仍归领域合同。本 Skill 不建立万能 mutation 框架。
- 缺少服务端幂等、结果查询、版本或冲突契约时明确缺口，不编造 endpoint 或把禁用按钮当作幂等保证；实现授权不扩大为真实付费、生产或不可逆操作授权。
- 按需读取数据访问中的 mutation、请求上下文与错误章节、日志脱敏规则及本次领域合同。由调用方传入已核对的事实与证据，完成后返回调用方，不反向启动编排。

## 实施流程

1. 冻结一次逻辑操作的输入、身份/组织/目标与服务端规定的幂等键或版本。相同操作的恢复复用该身份，新操作才按契约建立新身份；不在每次网络重试时生成新幂等键。
2. UI 防重复提交，并核对 HTTP、Query mutation 与自定义 adapter 的重试拥有者，写操作不自动重放。网络取消或超时不证明服务端回滚；并发标签页仍依赖服务端原子处理。
3. 明确区分确定失败与结果未知。未知时先通过已确认的操作标识/订单/幂等查询恢复；查询失败保持未知，不盲目创建新对象或再次扣款。只有服务端已确认可安全重试或仍允许执行时才提供相应动作。
4. 版本冲突重新读取当前对象并展示差异；保留仍适用的用户输入，让用户按领域契约重新提交，不覆盖他人修改、不自动合并资金/权限动作。
5. 服务端确认成功后保持成功事实，再刷新精确关联的 Query、账户或列表。刷新失败只重试读取，不重新发起已成功写入；领域要求的到账/生效等后续状态单独展示。
6. 身份/组织/目标切换后，旧操作结果只对原作用域记账与查询，不写回当前缓存或误导当前 UI。日志仅记录允许的标识和状态，不输出凭据、支付载荷或敏感输入。
7. 相关非空测试覆盖本次最高风险路径：重复点击、已受理后超时、查询恢复、并发冲突、成功但刷新失败或旧作用域迟到响应。真实扣款/生产写入只能按已有明确授权执行，Mock 不能证明服务端幂等。

## 返回结果

返回操作状态与恢复路径、幂等/冲突/作用域拥有者、精确刷新范围、实际测试和服务端未确认项。不自动增加构建、浏览器、全仓检查或最终候选验收。
